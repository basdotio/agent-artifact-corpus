# 语料库是怎么建起来的

[`classification.zh-CN.md`](classification.zh-CN.md) 说的是**测什么**。本文说的是每个类别的材料**从哪来**，以及各自附带哪些陷阱。

请务必读陷阱那部分。这里列出的每一个外部语料库都至少有一个陷阱，其中两个被布置得足以让一行正则拿到满分。

---

## 问题的形状

八个测量类别（classification.zh-CN.md）按"谁能提供样本"干净地一分为三：

| 类别 | 来源 | 为什么不能反过来 |
|---|---|---|
| 1 假阳性、2 召回 | **外部** | 我们写不出能让自己意外的样本。我们自己的对抗性 fixture 是由写规则的同一批人写的，所以里面只有我们已经想到过的形状。这是结构性问题，不是粗心——再小心也消除不掉。 |
| 3 披露、4 规避、5 不变量、6 闸门、7 健壮性 | **我们自己** | 它们需要*注入的故障*。没有任何公开数据集会包含一个带 `chmod 0111` 子目录的 skill，因为没有别的扫描器有"必须承认自己没读到什么"这条不变量。 |
| 8 性能 | **真实机器** | 一棵字节数正确的合成目录树，文件数分布是错的，而遍历的开销取决于文件数。 |

类别 1 和 2 必须来自外部，这件事的证明不是论证。把扫描器指向 DataDog 的语料库，**第一个样本**就暴露了一个在我们全部 30 个对抗性场景里都不存在的形状：一个教科书式的反弹 shell 拿到 88/100，顺利通过 `--fail-on high`。本该抓住它的规则 `BD-003` 只匹配三个字符串字面量，漏掉了所有语言原生的写法。

## 第 1 层——vendored（随仓库分发）、离线、我们自己的

`corpus/<class>/<surface>/<id>.yaml`（标签）与 `corpus/<class>/<surface>/<id>/`（样本树）并列存放。标签绝不放进样本树内部——这一条的代价见 [`label-schema.zh-CN.md`](label-schema.zh-CN.md)。

**类别**：`benign`、`malicious`、`hard-negative`。
**作用面**：`skills`、`hooks`、`permission`、`mcp`、`connector`、`instruction`。

作用面指的是**加载路径**：agent 从哪里读到这个 artifact，而这决定了它能做什么。只列举六个却不定义它们，正是 `connector` 长期空着的原因——没人能说清什么样的 artifact 该归到那里，于是什么都没归进去。

| 作用面 | artifact 是什么 | 凭什么算这个作用面 |
|---|---|---|
| `skills` | 一个 skill 目录（`SKILL.md` 以及它附带的东西） | agent 把它当作可以遵循的指令来读 |
| `hooks` | 带有非空 `hooks` 块的设置文件 | 它会在 agent 的某个事件上执行命令，且当时无需征求同意 |
| `permission` | 带有非空 `permissions` 块的设置文件 | 它决定 agent 可以不问就做哪些事 |
| `mcp` | 一个服务器的工具声明（名称、描述、输入 schema） | agent 读它来了解某个工具是干什么的 |
| `connector` | 把 agent 之外的东西接进来的配置：指向远端端点（带 http/sse 传输的 `url`）、OAuth 授权范围、`.mcpb`/`.dxt` 清单 | 它授予的是访问权，而不是描述一个工具 |
| `instruction` | 被要求当作指引来对待的自由文本 | 它自己没有加载路径；它是以内容的形式到达的 |

`surface` 是一个**列表**，因为一个文件经常同时是两个加载路径。真实的 `.claude/settings.json` 通常同时带着 `hooks` 块和 `permissions` 块——抽查的头五个真实文件里有三个如此。把这种文件归到其中一个作用面下，会让 `permission` 变成"恰好没有 hook 的设置文件"，这是一个由 schema 臆造出来、而非在真实世界里找到的子总体。artifact 只 vendoring 一次，由它的第一个作用面拥有目录，因此各作用面的计数之和不等于样本总数。`corpus stats` 在打印它们的地方会写明这一点。
**技术**：来自 [`taxonomy/techniques.yaml`](../taxonomy/techniques.yaml)，它们是标签中**不属于任何人**的那部分。一个标签的 `truth` 块用这套技术写成，单凭它自己就足以给任何扫描器打分；`expect.<tool>` 在其之上追加某一个具名扫描器的规则 ID，是可选的。这正是第 1 层能被"给一个不是我们写的工具跑基准"的人使用的原因，也是验证器必须在没有 check out 任何扫描器的情况下也能运行的原因。

`hard-negative` 是一个独立类别，而不是 benign 的一种口味，因为它背负一项额外义务：**每一个硬负样本都与一个必须仍然触发的恶意样本配对。** 一次抑制和"规则仍然有效"的证明要么一起落地，要么都不落地。没有这个配对，"降低假阳性"就退化成"删掉规则"，而且没有任何东西能抓住这种退化。

### 第 1 层必须包含什么

**每一个已确认的假阳性，都要钉住。** 今天已确认四个：文件偏移 0 处的 UTF-8 BOM、传给子进程的 `os.environ.copy()`、**教 agent 拒绝注入的防御性散文**，以及一个被两条规则同时报出的 `atob(`。每一个都获得一条 `hard-negative` 条目，规则 ID 写进 `quiet:`，并且每一个都配上它的恶意孪生样本。靠改一条正则来修假阳性，会被下一次正则改动悄无声息地撤销。把它变成一个样本，才使"这条不许触发"成为一个可回归测试的性质。

**类别 3–7 的每一个注入故障用例。** 这些是只有我们能写的。

**任何许可证比本仓库更严格的东西都不要。** 见 [`licensing.zh-CN.md`](licensing.zh-CN.md)。第 1 层是 MIT 加上宽松许可的 vendored 材料；任何无许可证、NC、SA 或 copyleft 的东西，要么属于第 2 层，要么哪儿也不属于。

### 无法成为文件的那部分

Git 不携带目录权限位，而 BSD `tar` 无法复现 `0111`（实测）。所以这一整族**只能在测试 setup 代码里构造**，不能作为签入的 fixture：

- 只可穿越的目录（`chmod 0111`）——agent 按路径执行，`WalkDir` 读不到
- 用 FIFO 冒充 `SKILL.md`、`settings.json`、`.mcp.json`
- 符号链接逃逸与环
- 在被读取的过程中还在变大的文件

`fixtures/` 是这些东西的 Go 构造器应该放的地方。**它今天是空的**——目录在，里面什么都没写过，这是第 1 层里最大的一个已声明缺口。**磁盘上的 fixture 换来的是规模和非 Go 贡献者；Go harness 保住的是文件系统层面的规避手法。** 两者互不替代，而迄今审计中发现的三个最严重缺陷全都在第二组里。

## 第 2 层——引用、按需拉取、绝不 vendored

`manifest/*.yaml` 记录一个钉住的引用以及关于它的已知信息：`url + commit + sha256`、`license` 和 `role`、来源自称的数量，以及决定它能怎么被计数的 `hazards`、`overlaps` 和 `prep`。**永远不记样本内容。**

记录一个 URL 和一个哈希不构成分发。这正是这一层存在的全部理由：它可以引用无许可证、CC-BY-NC-SA 和 AGPL 的语料库，在本地对它们做测量，并发布聚合数字，而这一切都在它们的分发条款管辖范围之外。

## 会悄悄造出满分的陷阱

**`MalSkillBench` 的标签泄漏。** 4,000 个良性样本中有 3,878 个带 `_meta.json`；3,944 个恶意样本中一个都没有。**只看这一个文件在不在，不读任何 skill 内容，就能把整个语料库分类到 98.5% 的准确率**——恶意样本全中，良性样本中 97%。 使用前把那个文件删掉。（配套的那个传言——说恶意目录是空的——是假的：全部 3,944 个都有 `SKILL.md`。）

**`skillfortifybench` 的捷径特征。** 恶意样本使用 RFC-2606 保留域名；良性样本从不使用。一条正则就能拿满分，而且泛化为零。

它的后继项目提供了一个值得抄的机制：`metrics/leakage.py` 是一个**机械化的发布闸门**——任何支持度 ≥8 且能以 ≥95% 纯度预测标签的结构性特征，都会让构建失败。这里的 `make validate` 实现的是同一个想法。一个不读内容就能解开的语料库，不是语料库。

**循环的良性标签。** Smithery 的 `verified`、Glama 的 `qualityScore`（一项付费推荐位）、各种声誉分——全都是流行度或厂商策展，没有一个是安全审查。

### 良性可信度排序

由强到弱：

1. 密码学背书（只有 NVIDIA 有）
2. 企业在自己的 namespace 下以宽松许可发布
3. 被官方市场收录
4. 市场的"未见可疑"标记加上下载量
5. **"没有扫描器发现问题"——对我们来说是循环的。任何权重下都不可用。**

## 污染地图——这些数字加不起来

```
MaliciousSkillBench ⊃ SkillTrustBench + MalSkillBench + ATR + SkillFortifyBench + …
SkillTrustBench     ⊃ overtly-malicious-skills (4)
DataDog ai-skills   ⊃ overtly-malicious-skills (tjade273-* is simple-formatter)
snyk-labs           ∩ pyxeroai  = both from NET_NiNjA
```

每一条 manifest 条目都要声明 `overlaps:`。`make stats` 拒绝打印跨越互相重叠条目的合计总数，因为那个和会朝着"看起来安全"的方向撒谎。

## 按来源切分是强制的

Cisco 测得：当切分方式从随机切换成按来源切分时，召回从 **31.43% 掉到 7.75%**。随机切分是在同一个作者的模板上做训练和测试，它测的是模板记忆。

这一点在良性那一侧同样咬过我们。一个 12.9% 的全机器假阳性数字，拆开来是 7 个来源，其中两个高达 87%，逐来源的分布跨度是 0.0%–30.8%——比那个数字本身还宽。**这条 12.9% 的数字描述的是两个作者的写作习惯。**

**因此**：每一个比率都按来源分别报告，附上 `n`、来源数量，以及样本加权值和来源不加权值两者。两者不一致时，这个不一致本身就是结论。

## 构建顺序

第 1 层的 schema 和验证器先做——便宜，而且它们的输出就是后续一切工作的采样清单。先收集材料，等于保证了后面要把所有东西重新打一遍标签。

那份输出现在是两份清单，因为一个标签有两半。`make stats` 会打印**词表里的每一项技术，包括那些一个样本都没有的**，这是工具中立的空洞，也是另一个团队能据以行动的那种。8 个维度现在都有样本了；空着的是 32 个「维度 × 层级」格子里的 7 个，`make stats` 会逐个点名。以及按工具分别列出，**它的哪些评分规则一个样本都没有**——这个数字必须从该工具生成的规则参考里读出来，绝不能手写。本段的某个早先版本把这个数字手写成了 61，而生成的头部写的是 62——这正是那条规则要防止的漂移，却提交在了陈述这条规则的文档里。现在这里刻意不写任何数字。

| 阶段 | 内容 | 之后我们才能说 |
|---|---|---|
| **0** | Schema、验证器、泄漏闸门；把某个扫描器已有的对抗性用例提升进来 | 在一个小集合上拿到真实数字，**以及哪些技术、哪些评分规则未被测试** |
| **1** | 假阳性分母：`SkillMD-138K` + awesome 树 + clawhub，按来源分列 | 假阳性率开始有意义 |
| **2** | 召回：去重后的 DataDog、skillsgoat、ToB 试金石 | 召回可以发表了，按维度分列 |
| **3** | 我们自己的作用面：skillcraft-audit 和 cisco 提供恶意样本；**采集**真实的 hook、权限、MCP 配置作为良性样本 | 差异化的作用面被覆盖了 |
| **4** | 类别 3–7 的注入故障；`fixtures/` 的 Go 构造器 | 那些性质类别有证据了 |
| **5** | 第 1 层上 CI 闸门，第 2 层发布报告 | 可被外部引用 |

阶段 1 永远排在阶段 3 之前。先建我们自己的，等于保证朝错误的方向建——反弹 shell 那个缺口就是常设的证明。

## 报告必须发布什么

除了各项比率之外：**没有样本的技术、以及没有样本的规则，两者都要点名。** 与该工具自己的 `COV-000` 是同一种纪律——一个被声明出来的空洞是操作者可以据以行动的东西，一个被藏起来的空洞是谎言。分母取自该工具生成的 `docs/rules.md` 头部块中的 `score` 计数，绝不用手写的数字。

还有一条常设禁令：**"外部语料库里没有这个，所以这条规则没问题"不是论证。** 一个公开语料库覆盖的是它作者选定的主题，不是威胁作用面。第 1 层存在的意义是填补那个缺口，而不是把它开脱掉。
