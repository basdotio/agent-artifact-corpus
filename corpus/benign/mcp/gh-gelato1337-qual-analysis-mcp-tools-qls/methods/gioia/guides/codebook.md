# The codebook

The codebook is the set of rules everyone codes by. It is how a session working on interview 15
knows what was decided while coding interview 2. Agents propose; the researcher approves.

## An entry (after MacQueen et al. 1998)

| Field | What it says |
|---|---|
| label | the concept's label |
| definition | one or two sentences: what the concept covers |
| use when | inclusion: what a passage must show to get this code |
| do not use when | exclusion: near misses, and which code to use instead |
| example | one or two quote ids that show it well |

"Do not use when" is the most useful field. It grows from hard cases: every time you hesitate between
two codes, the reason you chose one is a rule for the next session.

## When to propose

- A new entry, when a concept recurs across informants, or when it is likely to (in calibration, from
  the few interviews you have).
- A change, when an approved entry nearly fits a passage and the difference matters: write a
  `meaning` memo on the entry with the passage, and propose the change (narrower, broader, split, an
  added exclusion).
- Not for every concept. One-informant concepts stay concepts until they recur.

## Using approved entries

- Use the approved label for the same idea; add evidence to the concept that carries it.
- Do not bend an entry to fit, and do not bend the passage to fit the entry. Both lose meaning.
- If the codebook seems to be steering you away from what the informant said, that is a `residual`
  or `reflexive` memo, and possibly a checkpoint question.
