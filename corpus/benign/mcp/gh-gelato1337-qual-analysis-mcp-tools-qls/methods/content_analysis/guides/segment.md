# Coding a segment

A segment is a passage that says something relevant to the research question, coded into one or
more categories.

## Before coding

Read the whole interview first. Informants return to the same episode several times and correct
themselves; code the episode where it is told most fully, and add the other passages as further
quotes of the same segment.

## One segment = one thing said

- One factor, event, decision or explanation. When the informant names two factors in one breath,
  code two segments.
- `label`: what the informant says, in a short English phrase, close to their terms: "export orders
  collapsed when the main customer moved production", not "external decelerating factor".
- quotes: the shortest span that carries it, copied exactly, each with a reason.
- `categories`: every category it belongs to, each with a one-line reason. A passage about a key
  customer leaving can be both external and decelerating.

## Time and direction

- `period`: whenever the informant places it in time, record it as they do: "1999", "2001-2003",
  "after the merger" (then say in the description what that was). Leave it empty rather than
  guessing.
- `direction`: accelerating, decelerating, turning point, or neutral, as the informant sees it, not
  as you would judge it.

## What not to code

Small talk, the interviewer's own explanations, and agreement with the interviewer's suggestion
("Joo", "Kyllä") without content of the informant's own. Note doubtful cases in a memo.
