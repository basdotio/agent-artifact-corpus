# Project Analyst 分析指南

> 本文档是 Project Analyst Skill 的扩展参考指南，用于指导 Agent 对软件项目进行系统化、证据驱动的分析。
>
> 核心目标：在有限上下文、有限工具调用和有限输出预算下，尽可能准确地建立项目整体认知模型。

---

# 1. 分析目标

Project Analyst 的目标不是读取尽可能多的代码，也不是生成尽可能长的项目报告，而是以尽可能少但足够可靠的证据回答以下核心问题：

1. 这个项目是什么？
2. 它解决什么问题？
3. 使用了什么技术？
4. 项目由哪些主要部分组成？
5. 程序从哪里开始运行？
6. 核心模块分别负责什么？
7. 模块之间如何通信和协作？
8. 数据和状态如何流动？
9. 项目如何安装、构建、运行和测试？
10. 项目如何打包、发布或部署？
11. 当前有哪些值得关注的技术风险？
12. 哪些重要信息目前仍然无法确认？

分析结果应帮助一个此前不了解该项目的开发者快速建立可靠的整体认知。
