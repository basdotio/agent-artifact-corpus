# Framework mapping: where the single theme source lives

Read when the project uses a CSS framework, component library, CSS-in-JS, or a CMS/commerce theme. The rule is the same everywhere: **the theme source is the place the framework already reads theme values from.** Put the contract's semantic roles there. Never add a parallel palette file the framework does not read. Two sources drift apart, and a theme switch then updates half the site.

Check `Detected:` and `Theme sources:` in `scripts/frontend_index.py` output first. Versions were checked in September 2026. If the project pins another major version, follow its own docs.

| Stack | Theme source | Dark / theme switch | Components consume | Avoid |
| --- | --- | --- | --- | --- |
| Plain CSS, CSS Modules, Sass | One global CSS file with custom properties (start from `assets/templates/theme-tokens.css`), imported once at the app root | `[data-theme]` on `<html>` plus `prefers-color-scheme`, as in the template | `var(--role)` in every module | Sass variables for colours that must switch at runtime: Sass compiles once, so the theme cannot change later. Keep Sass variables for build-time values (breakpoints, mixins) or alias them: `$brand: var(--color-brand)` |
| Tailwind CSS v4 (4.x) | Global CSS: `@import "tailwindcss";` then `@theme { … }`. For runtime-switchable roles, define values in `:root` / `.dark` and expose them with `@theme inline { --color-canvas: var(--canvas); }` | `@custom-variant dark (&:where(.dark, .dark *));` or a `[data-theme=dark]` selector | Utilities generated from theme names (`bg-canvas`, `text-subtle`) | Arbitrary values such as `p-[13px]` or `text-[#333]` that bypass the scale. The inventory counts them: add a role instead. Do not add a `tailwind.config.js` palette to a v4 CSS-first project unless it already uses `@config` |
| Tailwind CSS v3 | `tailwind.config.{js,ts}` → `theme.extend`, with values pointing at CSS variables, e.g. `brand: 'rgb(var(--color-brand) / <alpha-value>)'` | `darkMode: 'class'` or `['selector', '[data-theme="dark"]']` | Utilities | Hex values in the config for colours that must switch themes |
| shadcn/ui on Tailwind | The global CSS file: `:root` and `.dark` tokens (`--background`, `--foreground`, `--primary`, `--primary-foreground`, `--muted`, `--border`, `--ring`, `--radius`), mapped through `@theme inline` | `.dark` class | Utilities such as `bg-background`, `text-muted-foreground` | Raw colours inside copied component files. Keep the convention: every surface token has a `-foreground` partner, and new roles (`--success`, `--warning`) follow it. Check muted text on muted surfaces, because it can land near 4.5:1 |
| Bootstrap 5.3 | Sass overrides (`$theme-colors`, `$primary`, …) before importing Bootstrap, plus runtime `--bs-*` variables | `data-bs-theme="light|dark"` on `<html>` or on a component | Bootstrap classes, and component variables such as `--bs-btn-bg` | A separate stylesheet that re-colours `.btn-primary` with hex values. Change the Sass map or the `--bs-*` variables instead. (Bootstrap 6 was still alpha in September 2026) |
| MUI (Material UI v9) | `createTheme({ cssVariables: …, colorSchemes: { light, dark }, palette, typography, spacing, shape })` | `colorSchemes` plus `cssVariables.colorSchemeSelector` (`'class'` / `'data'`), `useColorScheme()`, `InitColorSchemeScript` against SSR flicker | `sx` / `styled` reading `theme.vars.*` → CSS variables `--mui-*` | Hex in `sx` props and extra CSS files with colours. Put the contract roles in the palette and extend it for custom roles |
| Chakra UI v3 | `createSystem(defaultConfig, defineConfig({ theme: { tokens, semanticTokens } }))` | Semantic tokens with `_dark` values | Style props using token names | Raw colours in style props |
| styled-components / Emotion | `ThemeProvider` theme object whose values reference CSS variables (`text: 'var(--color-text)'`) | Switch `data-theme` on `<html>`; the theme object can stay the same | `${({theme}) => theme.color.text}` | Interpolating hex literals inside components |
| Angular Material 19+ | Sass `mat.theme(…)` in the global styles, which generates `--mat-sys-*` system tokens | `color-scheme` / a theme class | Components read system tokens; custom components use `var(--mat-sys-…)` | Per-component palettes that ignore the system tokens |
| Vue/Nuxt, Svelte/SvelteKit, Astro, Solid | One global CSS file imported at the root (`nuxt.config` `css: []`, root `+layout.svelte`, base layout, `index.tsx`) | Same as plain CSS | `var(--role)` in scoped styles | Scoped `<style>` blocks that hide their own palette |
| Shopify themes (Online Store 2.0) | Merchant settings in `config/settings_schema.json`, colour schemes printed as CSS custom properties in `layout/theme.liquid` | Colour-scheme classes on sections | Sections and snippets use `var(--…)` and the scheme class | Hex values in section CSS: they break merchant colour schemes. A new merchant setting is a product decision, so ask the owner first |
| WordPress block themes | `theme.json`: `settings.color.palette`, `typography.fontSizes`, `spacing.spacingSizes`, `custom`. These generate `--wp--preset--color--{slug}`, `--wp--preset--font-size--{slug}`, `--wp--preset--spacing--{slug}` and `--wp--custom--…` | Style variations in `styles/*.json` | Blocks and templates use presets | Editing a parent theme or plugin files (updates overwrite them). Use a child theme, and override WooCommerce templates under the theme's `woocommerce/` folder |
| WordPress classic themes | The theme's main stylesheet with custom properties, enqueued once; child theme for changes | As plain CSS | `var(--role)` | Inline styles printed from PHP templates |

## Applying the contract to a framework

1. Name the contract roles once (canvas, surface, text, subtle, brand, on-brand, border, focus, status, chart, spacing, type, radius, layers, motion).
2. Map each role to the framework's native slot: Tailwind theme names, MUI palette keys, Bootstrap theme colours, `theme.json` presets. Keep a two-column table in the design contract: role → framework name.
3. Components use only the framework's role-bound utilities or props. A missing value becomes a new role, never a literal.
4. Check contrast on the real theme source:
   - For CSS-based themes, run `scripts/contrast_check.py --css <file>`.
   - For themes defined in JavaScript, check the values with `--pair`, or check the CSS variables the running page exports.
5. When the framework's defaults (for example a default palette or spacing scale) already serve the brand, reuse them and record that choice. Consistency does not need custom values.
