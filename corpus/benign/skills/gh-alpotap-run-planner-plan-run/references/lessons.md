# Lessons from earlier runs

Each row is something that went wrong, why, and the rule it produced. The rules are already built into the skill and the runner; this table is the reason for them. Add a row when a run teaches something new.

| What happened                                                                                                    | Cause                                                                                                                         | Rule now                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| A one-line favicon task took 20 minutes                                                                          | specified as a branding project; read a 254 KB ledger; ran the isolation suite and a rebuild                                  | scope = what was asked; sizes; one ledger per run; targeted tests                                                                |
| Tasks sat waiting, needing a keypress                                                                            | a build sent to the background; a live session waiting for `/exit`                                                            | background off; waiting inside one command; everything headless                                                                  |
| Long M tasks, sessions hitting usage limits                                                                      | full suites and mutation checks in every task; whole-file reads; huge notes                                                   | full suites once in the gate; no mutation checks; ranged reads; capped notes                                                     |
| A task rewrote docs that a later task changed again                                                              | docs updated per task                                                                                                         | documentation only in the closing phase, and only if D1 = Y                                                                      |
| The run stopped at phase boundaries and questions                                                                | phases triggered by hand; "stop and ask" in tasks                                                                             | one sequence per run; decisions settled in planning                                                                              |
| A screen was built that sent free text where the backend expected a key                                          | the screen was planned without reading the reference app                                                                      | read the reference implementation before planning a screen that mirrors it                                                       |
| A one-function fix (append `/v1`, update one test table) took 23 turns and re-read 1.1M context tokens           | 4 turns to find its own section in the plan; 6 to re-locate code the plan had found; 5 on the ledger and two commits; 26 tool definitions (35K context) on every turn; marked M | the runner sends the task text; lean tool set (11K); the runner writes the ledger; coordinates and new text in the task; size honestly; Haiku for recipes |
