# 模型适配（Models）

> **说明**：本文是经验性归纳，用于决定「提示词该长什么样」。模型的参数上限、字段名、能力边界请以官方文档为准。用户点名的模型优先按本文档调形态，不确定时如实说明并建议以官方文档核对。

---

## 一、通用适配原则

1. **提示词形态跟着模型走**：
   - 自然语言派（Gemini / GPT Image / Veo / Seedance）→ 写完整句子，讲清关系
   - 标签派（Midjourney / SD / FLUX）→ 短词组 + 逗号分隔 + 权重语法
2. **负面词的位置不一样**：
   - 有独立 negative prompt 字段的（SD / FLUX / 部分国产模型）→ 分开写
   - 只吃单一 prompt 的（Midjourney / GPT Image / Gemini）→ 用「包含排除结果的场景描述」写进正文
3. **参数写法不一样**：Midjourney 用 `--ar 16:9 --style raw`；其他模型参数在 UI 或 API 里设，不进提示词。
4. **语言**：中文友好的（Seedream / 可灵 / Seedance / MiniMax）可直接中文；其余优先英文。

## 二、生图模型

| 模型 | 提示词形态 | 偏好 | 避坑 |
|---|---|---|---|
| **Nano Banana Pro**（Gemini 3 Pro Image） | 自然语言长句，中文可用 | 强指令跟随、强文字渲染、强图像编辑；1K/2K/4K 可选 | 描述过碎会稀释；编辑任务要显式写「只改 X，其余不变」 |
| **Nano Banana 2** | 同上一代系 | 自然语言、对话式改图 | 同上 |
| **Seedream / 即梦** | 中文自然语言，可结构化 | 中文语境强、海报与文字排版强、国风题材强 | 过长的英文技术词收益低 |
| **GPT Image**（1.5 / 2） | 自然语言，指令式 | 指令跟随极强、文字与排版准、编辑能力强、精确控制物体数量 | 别用 MJ 式参数语法；数量与位置要精确写 |
| **Midjourney** | 短词组 + 参数 | 美学与风格强、`--ar` `--sref` `--cref` 等参数体系 | 不吃长句、`--no` 效果有限、英文优先 |
| **FLUX / Stable Diffusion** | 标签式逗号分隔 + 权重 `(word:1.2)` | 独立 negative prompt 字段、LoRA/ControlNet 生态、可复现性强 | 需要正确的权重与负面语法；长句不如标签有效 |
| **Ideogram** | 自然语言 + 文字内容显式给出 | 文字/Logo/海报渲染最强 | 用引号明确要渲染的文字 |
| **Imagen** | 自然语言 | 写实摄影感好 | — |

**生图通用建议**：`比例` 与 `分辨率` 一律外置成「推荐参数」行，不写进正文（Midjourney 的 `--ar` 是例外，那是它的语法）。

## 三、视频模型

| 模型 | 提示词形态 | 偏好 | 避坑 |
|---|---|---|---|
| **Seedance 2.0** | 导演式 + 显式参考 + 时间节拍；可用 `Setting:/Action:/Camera:/Style:/Audio:/Shot 1:` 等标签分段 | 多模态参考（图/视频/音频，官方上限约 9 图 + 3 视频 + 3 音频）、多镜头、最长约 15s、双声道音频、路径控制 | 短片段别堆太多同时发生的动作；参考资产要逐个声明角色 |
| **Seedance 2.5** | 同上，增加编辑与续写 | 文生/图生/参考生/编辑/续写、多节拍时间轴、首尾帧 | 长镜头要说明期望的**结束状态**；建议用能容纳动作的**最短时长** |
| **可灵 Kling** | 中文友好，动作描述直白 | 运动控制、首尾帧、物理可信度较好 | 动作描述避免抽象；明确镜头是否固定 |
| **Veo 3 / 3.1** | **五段式**：`[电影摄影]+[主体]+[动作]+[上下文]+[风格与氛围]` | 原生音频（台词/SFX/环境声）、首尾帧转场、镜头语言丰富 | 负面要写成「包含排除结果的场景描述」；不写模型名/时长/比例 |
| **Sora** | 自然语言，可长 | 长镜头、复杂物理、叙事连续 | 别用关键词堆砌；写清镜头逻辑 |
| **Hailuo / MiniMax H3** | **保留官方字段名与行序**（T2VA / I2VA / FL2VA / L2VA / 全参考模式） | 对齐指令、镜头时间戳、表演迁移 | 字段名、空行分隔是 schema 要求，**不能擅自简化** |
| **LTX-2 / 2.3 / 2.5** | 2.5 可用 screenplay 多行格式 | 2.5 支持原生多镜头、剧本式对白、Dub-It 语音替换、视频编辑 IC-LoRA | 时长与设置写成**外部参数**，不进正文；单镜头/图生视频默认一段 prose |
| **Wan 2.2 / Wan Animate 2** | 自然语言 + 运动描述 | 动画与角色驱动 | 动作要具体到关节级描述更稳 |
| **Ovi** | 自然语言，结构化可 | 音视频一体 | — |

## 四、按模型切换检查清单

切换模型时，逐项确认：

- [ ] 提示词形态改了吗（自然语言 ↔ 标签）
- [ ] 负面词位置改了吗（独立字段 ↔ 写进正文）
- [ ] 参数写法改了吗（外置 ↔ 模型语法）
- [ ] 语言改了吗（中文 ↔ 英文）
- [ ] 有没有把不该进正文的东西写进去（模型名、时长、比例、分辨率）
- [ ] 目标模型是否要求官方 schema（MiniMax / LTX / Seedance 多镜头）→ 保留其字段与行序

## 五、跨模型迁移

需要把一个模型的提示词迁到另一个模型时：

1. **拆解**：按十二维/视频结构把原提示词还原成维度清单，别逐字翻译。
2. **重排**：按目标模型的形态与结构重新组织。
3. **补约束**：补上目标模型特有的约束（媒介边界、参考资产映射、官方字段）。
4. **去噪音**：删掉源模型的专属语法与参数。

**不要做的事**：把 Midjourney 的 `--ar 16:9 --style raw` 原样贴给 Gemini；把 Gemini 的 600 字长句原样贴给 SD。
