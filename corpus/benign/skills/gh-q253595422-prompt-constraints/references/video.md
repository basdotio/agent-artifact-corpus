# 视频提示词（Video）

## 一、视频与生图的根本差异

| 维度 | 生图 | 视频 |
|---|---|---|
| 时间 | 单帧，静态 | **时序**，动作必须按时间展开 |
| 重心 | 构图 / 光影 / 材质 | **运动 / 镜头 / 表演 / 声音** |
| 一致性 | 一张图内部自洽 | **跨帧、跨镜**必须自洽 |
| 参数 | 比例 | 比例 + **时长** + 镜头数 |
| 冗余信息 | 描述画面里的一切 | 描述**变化**，静态部分越少越好 |

**核心约束：视频提示词描述「运动和变化」，不是描述画面长什么样。** 首帧已经说清楚的东西，不要重复描述。

---

## 二、全局视频约束

- **T1 参数不进正文。** 模型名、版本、时长、比例、分辨率、设置项**不写进提示词**，单独列「推荐参数」行。**例外**：目标模型官方 schema 要求（MiniMax H3 对齐指令与镜头时间戳、Seedance 多镜头时间轴、LTX screenplay 格式）。
- **T2 时长只用于内部规划。** 时长决定这段提示词能承载**几个动作节拍**，不写进正文。
- **T3 图生视频时，图是视觉锚点。** 除非用户要求图片分析或某个细节必须变，否则**不深描述图片内容**，专注写：运动、镜头、情绪/表演、声音。
- **T4 动作连续性。** 明确「连续 / 一镜到底 / 无剪辑」，并排除跳切、瞬移。
- **T5 物理可信。** 加速度、惯性、遮挡、接触、因果必须成立。写清「谁导致什么」。
- **T6 单镜头动作密度受限。** 短片段塞太多节拍 = 全都做不好。宁可少而清晰。

---

## 三、输入模式判定

先确认输入形态，它决定提示词该写什么：

| 模式 | 提示词重心 |
|---|---|
| 文生视频 t2v | 一切都要写：主体、动作、环境、镜头、声音 |
| 图生视频 i2v | 只写变化：运动、镜头、表演、声音 |
| 首尾帧控制 | 写清楚「从哪到哪」的转场/运镜/关键节拍 |
| 参考驱动（多图/视频/音频） | **逐资产声明角色**，见 §四 |
| 编辑 / 续写 | 写清什么保留、什么改变、从哪续 |

---

## 四、参考资产映射（多资产场景）

有参考资产时，**逐个声明它负责什么**，不要让模型猜：

```
@图1 分镜/构图参考  ｜ @图2 角色参考  ｜ @图3 场景参考  ｜ @图4 道具服装参考
@视频1 运动节奏与运镜参考  ｜ @音频1 氛围与节奏参考
```

中文场景也可写：

```
参考图 1 的构图与分镜推进，使用图 2 的角色、图 3 的场景、图 4 的道具，
运动节奏对齐视频 1，氛围与节奏线索参考音频 1。
```

**数量约束**：多资产常受上限限制（例：Seedance 2.0 官方上限 9 图 / 3 视频 / 3 音频）。超限时按重要性取舍，并在交付时说明。

## 五、视频提示词结构

默认按此顺序组织：

1. **输入用法**：首帧 / 编号路线参考 / 角色参考 / 路径控制图
2. **规格**：比例、时长、一镜到底还是多镜头
3. **视角与运动**：谁的 POV，如何移动
4. **路线/节拍顺序**：编号停靠（近景互动）或地理分段（路径控制）
5. **紧凑时间轴**：一节拍一个目标 / 一段一段推进
6. **环境动态与声音设计**（有用才写）
7. **一致性声明 + 回避清单**

**五段式速记公式**（Veo 系官方口径，通用性好）：

```
[电影摄影] + [主体] + [动作] + [上下文/环境] + [风格与氛围]
```
- 电影摄影 = 运镜 + 景别/构图
- 动作 = 主体做什么（要清晰的节拍）
- 风格与氛围 = 美学 + 情绪 + 光影

## 六、时间轴写法

**节拍数由时长决定**，超出容量就该建议缩短时长或拆镜头：

| 时长 | 建议节拍 | 目标/人物数 | 处理 |
|---|---|---|---|
| 5—8s | 1—2 | 1—3 | 一个清晰动作，一次变化 |
| 8—12s | 2—3 | 3—4 | 短互动 + 一次揭示 |
| 12—15s | 3—4 | 4—5 | 顺序停靠的理想区间 |
| 15—25s | 4—6 | 5—8 | 节拍变短，分组过渡 |
| 25s+ | 拆镜头 | 8+ | 分组 / 分区 / 多镜头 |

**时间轴模板：**

```
时间轴：
0.00—X.Xs：[建立起点与环境动态]
X.X—X.Xs：移动到 [目标1]，[动作/台词/反应]
X.X—X.Xs：移动到 [目标2]，[动作/台词/反应]
...
X.X—ENDs：[到达终点或回望全景，形成空间层次]
```

**无时间戳时**：用「先…接着…随后…最后…」的叙事顺序，或 `Shot 1 / Shot 2 / Final shot` 分段。

## 七、POV 与物理约束

**FPV 不等于人眼高度。** 用户指定就遵从；没指定则选一个让场景更成立、更有趣的视角。

| 场景意图 | 可选 POV | 运动线索 |
|---|---|---|
| 宅邸 / 公寓 / 派对 | 受邀客人、管家、快递员、宠物猫 | 步行摇晃、转向、手/爪入画 |
| 客厅 / 咖啡馆 / 居家 | 宠物猫、扫地机器人、访客 | 低机位滑行、家具腿、爪尾/电机声 |
| 户外 / 城市 / 战场 | 无人机、鸟、风筝、灵体 | 空中弧线、高度变化、风声、无脚步 |
| 博物馆 / 展厅 | 访客、导览机器人、监控 | 缓步、展品停顿、精准转向 |
| 恐怖 / 悬疑 | 孩童、持手电者、监控、幽灵 | 低高度、迟疑移动、视野受限 |
| 车 / 船 / 飞行器 | 乘客、驾驶员、固定机位 | 受限路径、窗外移动、引擎/路面/水声 |

**必须强制物理限制：**
- 人：眼高、步行起伏、呼吸、手/衣袖可入画
- 猫狗：低高度、好奇转头、爪/尾可入画、**无人类手势**
- 无人机：平滑连续飞行、高度变化、倾斜转弯、**无步行起伏**
- 扫地机器人：极低高度、贴地滑行、家具腿显大、**不能上沙发/跳/爬楼梯**
- 鸟/虫/灵体：漂浮弧线或滑翔、非常规高度，但仍需连续且动机合理

> 猫不能飘过桌子；无人机不能穿墙；扫地机器人不能跳上沙发；人不能穿过家具。

## 八、镜头语言

**用标准电影动词，不要自造词：**

- 运动：`dolly shot` / `tracking shot` / `crane shot` / `aerial view` / `slow pan` / `slow push-in` / `orbit` / `POV shot`
- 景别构图：`wide shot` / `close-up` / `extreme close-up` / `medium shot` / `two-shot` / `low angle` / `profile shot`
- 镜头焦点：`shallow depth of field` / `wide-angle lens` / `soft focus` / `macro lens` / `deep focus`
- 中文对应：推轨 / 跟拍 / 摇臂 / 航拍 / 缓摇 / 缓慢推进 / 环绕 / 第一人称
- 连续运动描述：持续前推、自然倾斜、近距离掠过、高度变化、前景视差、渐进加速、地平线稳定

---

## 九、音频导演（支持音频的模型）

- **台词**：用引号包住准确内容。`一位女性说："我们必须现在离开。"`
- **音效**：显式点名。`音效：远处雷声炸裂。` / `SFX: thunder cracks in the distance.`
- **环境声**：定义声场。`环境声：星舰舰桥低沉的嗡鸣。`
- 不要台词就**直接说明**，只指定音效/环境声。
- 声音要对齐画面节拍，不要写与画面对不上的音轨。

## 十、路径控制 vs 编号停靠

两种路线约束方式，**选错会毁掉整条视频**：

### 编号停靠（默认优先）
适用：近景角色互动、室内、人多场景、需要精确目标数量的场景。

首帧图规则：
- **不画**红色路线/连接线/箭头
- 每个目标附近或地面放**小号编号标记**
- 标记顺序按**空间可达深度**排列，不是随机撒
- 标记 1 通常最靠近镜头，后续往纵深推进
- 每个下一站必须**物理可达**（不穿墙、水、家具、栏杆、人群）
- **先设计可行走/可滑行/可飞行的路线，再摆角色**

### 红线路径控制
适用：航拍地图、世界地图穿行、城市到地标飞越、赛道线、峡谷/无人机路线、开放世界预告。

路线图 prompt 规则：
- 16:9 高分辨率航拍地形图/世界地图/战术地图
- **一条**清晰连续的红线，可带细箭头，从起点到终点
- 路线必须物理可行（道路、山谷、河流、城门、桥、峡谷、屋顶、空域、隧道、海岸线、山脊）
- 建 **4—6 个视觉可区分路段**形成推进感：平静起点 → 过渡区 → 地标/城市 → 危险区 → 终点
- 红线干净可辨，不做多路径竞争（除非用户要分支）

视频 prompt 规则：
- 明确声明上传图是**路线规划图，不是最终画面**
- 明确声明红线/箭头/标注**只是镜头路径控制，必须完全消失**
- 镜头严格沿路线几何从起点到终点
- POV 用隐形第一人称（无人机/鸟/灵体/车载），除非路线真的可步行
- 时间轴按**地理分段**，不按角色停靠
- 回避：地图视角、可见红线、标注、瞬移、倒放、跳切、可见无人机、引导角色、平坦地形、地标变形、结构闪烁

> **判定**：GPT Image 常画不出一条物理连贯的连续红线（穿家具/穿人/穿墙）。近景互动场景一律优先**编号停靠**。

## 十一、常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 视频像一张会动的图 | 只描述了静态画面 | 改写成运动/镜头/表演/声音 |
| 动作做不出来 / 中途变形 | 节拍超出时长容量 | 减少节拍或延长时长 |
| 画面里出现数字/箭头/UI | 未声明「标记只是参考，不得入画」 | 补显式排除 |
| 角色第二镜换脸 | 缺一致性声明 | 补 L4 不变量 + 角色参考图 |
| 路径穿过障碍物 | 路线未按可达性设计 | 先画可行路线，再放目标 |
| 猫飘起来 / 无人机走路 | POV 物理约束缺失 | 按 §七 补运动约束 |
| 提示词里混了工具参数 | 参数未外置 | 按 T1 剥离到「推荐参数」行 |
| 音画不同步 | 声音未对齐节拍 | 把音频线索绑到时间轴节点 |
