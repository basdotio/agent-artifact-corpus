# 組合語言專屬規則

疊在 SKILL.md 之上；本檔只講組合語言才有的細節。
第一次寫下時的例子是 macOS ARM64（Apple 晶片）的 clang 內建組譯器，其他架構照同樣的精神套用。

## 哪些成員算非 private

- 用 `.global`（或 `.globl`）匯出的符號才算非 private，例如 `_main`，要寫完整契約。
- 沒匯出的標籤（檔內的小常式）算 private，不套五段模板。
  但組合語言沒有型別與參數名稱，所以每個內部常式上方仍要一到兩行寫清楚：
  輸入放在哪個暫存器、回傳放在哪、會弄髒哪些暫存器。這屬於實作註解，不是契約。
- 自訂的呼叫慣例（例如幾個常式共用某個暫存器當游標、彼此不存不還原）一定要寫在那組常式的上方，
  並在 AI-NOTES 記下「改的時候哪裡會壞」。

## 外殼

組合語言沒有 IDE hover 的標準 doc comment，就用該組譯器的行註解（clang/GNU ARM64 是 `//`，x86 NASM 是 `;`），
直接放在標籤正上方，分段標籤照 SKILL.md。
【行為】裡把暫存器的意義寫成白話，例如「w0 = 左右位移」，不要寫成 `@param`。

## AI-NOTES 標記

沒有折疊標記，照通用退路：`// ==== AI-NOTES ====` 到 `// ==== END AI-NOTES ====`（NASM 用 `;`），放檔案最後。
特別值得記的：從系統標頭查出來的常數與結構偏移量（要寫是在哪台機器、哪個系統版本查的），
以及這個平台呼叫慣例跟別的平台不一樣的地方。

## 驗證

- 組譯與連結：macOS 用 `clang 檔名.s -o 程式名`。
- 需要終端機的互動程式，標準輸入不能是管線；用 `python3` 的 `pty` 模組開起來、送按鍵、讀輸出。
- 想固定亂數之類的系統函式來做測試時，可以另外編一個測試版，連一個自己寫的同名 C 函式進去蓋掉它，
  正式版不受影響。

## 從組合語言呼叫 Objective-C（macOS 視窗程式）

- 常式如果會被 Cocoa 當成方法呼叫（用 `class_addMethod` 掛上去的），進來時 x0 是物件自己、x1 是選擇子，
  真正的參數從 x2（或 d0）開始；在它上方的一兩行註解要把這件事寫出來。
- 會弄亂參數暫存器的輔助巨集（例如查選擇子的巨集），要在巨集上方寫清楚「先呼叫它、再放參數」，
  並在 AI-NOTES 記一條，這是最容易寫錯的地方。
