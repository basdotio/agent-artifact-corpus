# 术语卡模板

每张卡 500–1200 字；读完应该能跟别人讲清楚它是什么、为什么存在、在候选人项目里起什么作用。

```markdown
# <术语>（<全称 / 中文名>）

**一句话**：<它是什么，大白话，不用其他没解释过的术语>

**类比**：<编程/工程类比，或生活类比>

**为什么会有它**：<它解决了之前方法的什么问题>

**原理（通俗版）**：
<3–6 句。先讲直觉，再讲关键机制。出现的新术语当场用括号解释。>

**出处 / 现状**：<论文或项目名、机构、年份、一句话贡献> — [来源](url)
<查不到就写：⚠️ 未核实：简历里的写法是「...」，可能是候选人内部命名，面试时让他解释>

**在 <候选人> 的简历里**：<原话语境 + 在他系统中的角色；他声称的效果>

**面试追问**
- 验真：<只有真做过的人才答得上的问题> → 好回答会提到：<要点>
- 请教：<让他讲你还没搞懂的部分> → 想学到：<要点>

**相关**：<库里已有或同批出现的相邻术语>

**候选人怎么讲的**：<面试后入库时补充；初次出卡留空或省略>
```

## 写得好 vs 写得差

差（只是换个说法重复名字）：
> Flow Matching：一种生成模型训练方法，用于动作生成。

好：
> **一句话**：让模型学一个"速度场"，把随机噪声沿一条尽量直的路线推成真实数据（这里是机器人动作）。
> **类比**：Diffusion 像蒙着眼一步步去噪、要走很多小步；Flow Matching 直接学"每个位置该往哪个方向走多快"，路线更直，所以采样步数少、推理快。
> **为什么在 VLA 里流行**：机器人要 20Hz 以上出动作，Diffusion 几十步去噪太慢；π0 系列用 flow matching 动作头把步数压到约 10 步。
