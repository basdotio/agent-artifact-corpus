# resume-learn · 从简历偷师

用户经常面试算法/机器人方向的候选人，想借每份简历补自己的知识盲区。目标是**简历里出现的东西全都要懂**，不按"和我相关"过滤——唯一的过滤器是「术语库里已经有了」。

三样产物：

| 产物 | 位置 | 用途 |
|---|---|---|
| 术语卡 | `~/Desktop/面试/术语库/cards/*.md` + `index.json` | 长期知识库，跨简历去重、记录谁的简历里见过 |
| 学习包 | `~/Desktop/面试/<姓名>-简历学习包.md` | 面试前读：这份简历涉及的全部知识，按学习顺序排 |
| 追问题库 | `~/Desktop/面试/<姓名>-追问题库.md` | interview-copilot 的 `--bank`；**start.sh 没传 --bank 时会自动找这个文件** |

脚本：`KB=~/.claude/skills/resume-learn/scripts/kb.py`（纯标准库，`python3 $KB -h` 看全部子命令）。

## 流程

### 0. 确定要处理哪些简历

- 用户给了路径 → 直接用。
- 用户说「新简历」「还没看的」→ `python3 $KB pending` 列出没处理过的 PDF（按内容哈希记，改名也认得）。
- 用户说「明天/这周要面的人」「飞书日历里的」→ 读 `references/feishu-calendar.md`，用 Chrome 打开飞书日历列出面试日程；桌面已有同名简历就用本地的，没有的**先问用户再下载**（下载文件需要用户明确同意）。
- 第一次使用（`index.json` 不存在）先跑 `python3 $KB seed-analyse`，把 `~/Desktop/Analyse/` 里已经 grok 过的讲义登记进库，免得重复学。

多份简历时逐份处理；每份都是独立的 1–4 步。份数多（≥3）可以派 subagent 并行，每个 subagent 只处理一份，prompt 里写明「你不要调用 Agent / Task 工具启动新的 subagent，自己直接完成这个任务」，并让它们只写自己那份学习包和一个 terms JSON，入库（`kb.py add`）由主 agent 串行做，避免并发写 index.json。

### 1. 读全简历

`python3 $KB pdf <简历.pdf>` 打印全部页。**读完所有页再开始提取**——长简历后几页常藏着最硬的东西（之前只读第一页就漏掉过 BA 多相机标定这种关键项）。文字很少说明是图片简历，改用 Read 工具直接看 PDF。

### 2. 提取「全部」可学的点

逐段扫，列出所有技术性条目，分三类：

- **概念/名词**：模型、论文、方法、框架、库、数据集、硬件、协议、指标（如 Flow Matching、RECAP、LeRobot v3、Wan VAE、pylibfranka、action chunk、state dropout）。
- **做法与经验数字**：简历里"遇到什么问题→怎么解决→效果多少"的工程套路（如「推理 115ms 下用异步推理+action chunk 平滑保持 20Hz」）。这是书上学不到的，最值钱。
- **基础项**：Python、PyTorch、Linux、ROS、Git 这类大概率会的——不跳过，但只进"基础速查"一行解释，不出完整卡。

组合词要拆开：「Qwen3-VL-4B + flow-matching 动作头」= Qwen3-VL、VLM 当主干、flow matching、动作头 四个点。缩写写全称并把缩写放 aliases。

然后一次性查库：`python3 $KB lookup "术语1" "术语2" ...`
- `HAVE` → 学习包里只列一行 + 卡片/讲义链接，不重写（状态是 known 的连这行都可以省）。
- `NEW ... RELATED: xxx` → 可能是库里讲义的同义项；打开对应讲义看一眼，确实是同一个东西就当 HAVE 处理，入库时用 `same_as` 挂到库里那条上（见下方 JSON），否则当 NEW。
- `NEW ... MENTIONED_IN: xxx` → 库里某篇讲义/卡片正文多次提到它。去那篇里看讲到什么程度：讲透了就当 HAVE（`same_as` 挂过去，学习包里链接到讲义）；只是顺带一提就出卡，卡片「相关」里链上那篇讲义。
- `NEW` → 出卡。

### 3. 给每个 NEW 写卡片

用户想要的是真懂，不是看到一个名字。按 `references/card-template.md` 的结构写，要点：

- **大白话优先**：每个术语第一次出现就用一句人话解释，别假设用户懂细分领域的行话；类比优先用编程/工程类比（用户是开发者）。
- **核实，不靠记忆**：论文/模型/框架名、2025 年以后的新东西、你不能百分百说清出处的，都先 `WebSearch` 查（出处、作者/机构、一句话贡献），卡片里附来源链接。查不到就老实标 `⚠️ 未核实`，并在追问里让候选人讲清楚——候选人自己起的名字或内部项目名很常见。
- **简历里怎么用的**：引候选人的原话语境（不带手机号、邮箱这类个人信息），说明这个东西在他项目里解决了什么。候选人写的效果数字是"他声称"，不是事实。
- **长度**：500–1200 字，够讲清原理即可；简单的硬件/库可以短。
- **两类追问**：「验真」问题（真做过的人才答得上）+「请教」问题（让他把你没懂的部分讲给你听），各附"好的回答应该提到什么"。
- 值得系统学（核心原理深、以后工作会反复用到）的标 `deep_dive_worthy: true`，最后挑 2–4 个推荐给用户用 grok 深挖，**不要自动跑 grok**（一次十几分钟，堆多了用户看不过来）。

每张卡写成 scratchpad 里的一个 md 文件（避免在 JSON 里转义整篇 markdown），JSON 里用 `card_file` 指过去，然后入库：

```json
[{"term": "Flow Matching", "aliases": ["流匹配", "flow-matching"], "category": "生成模型",
  "card_file": "<scratchpad>/cards/flow-matching.md", "deep_dive_worthy": true,
  "seen": {"candidate": "秦川", "context": "Qwen3-VL-4B + flow-matching 动作头"}},
 {"term": "Eye-to-Hand 手眼标定", "same_as": "手眼标定-Eye-in-hand与Eye-to-hand",
  "seen": {"candidate": "刘哲豪", "context": "外置相机抓取误差 <3mm"}}]
```

`python3 $KB add terms.json`。HAVE 的术语也要放进这个 JSON（不带 card_md，只带 seen），这样「谁的简历里见过」才完整，trend 才准。简历里的叫法和库里名字不同（包括 RELATED 确认为同一个东西的）时，`term` 填简历叫法、`same_as` 填库里的名字，脚本会把新叫法并入别名。

别名只放**真正的同义叫法**（缩写、中英文名、连字符变体），别放 ResNet、一致性、四元数这种泛词——`add` 按任一别名命中就合并。脚本合并时会打印 ⚠️，看到了核对一下。

基础项**不入库**：只在学习包「基础速查」里列出，用户确认「本来就会」后再 `mark known`（会直接登记），否则会把「待学」数量虚高。

分类尽量复用库里已有的（`python3 $KB stats` 后看 README.md 的分类标题），常用：VLA/机器人学习、生成模型、视觉感知、3D/几何标定、机器人控制与硬件、数据与训练工程、部署与推理、强化学习、仿真、做法与经验数字、基础。

### 4. 写学习包和追问题库

**学习包** `~/Desktop/面试/<姓名>-简历学习包.md`：

```markdown

## 一张图看懂他在做什么
（3–6 句大白话把整份简历的技术主线串起来：他的系统从数据到部署是怎么流动的，每个环节用了哪些新术语）

## 学习顺序
（按依赖排：先学被别的概念依赖的。例：VAE → latent 空间 → Wan VAE → 世界动作模型 WAM → FastWAM）

## 新知识卡片
（入库后用 `python3 $KB cards 术语A 术语B ...` 按学习顺序打印，标题已降成 `###`，直接拼进来，不要手抄）

## 做法与经验数字

## 已在库（复习一眼）

## 基础速查
```

**追问题库** `~/Desktop/面试/<姓名>-追问题库.md`：interview-copilot 读题库只取前 9000 字，所以控制在 **8000 字符以内**（`python3 -c "print(len(open(路径).read()))"` 量），只放问题，不放讲解：

```markdown
# <姓名> 追问题库（resume-learn 生成）
## 考点 1：<项目或技术点>
- 验真：<问题>
  - 听什么：<好回答的关键词/数字>；红旗：<答不上或说空话的表现>
- 请教：<问题>
  - 听什么：<面试官想学到的点>
```

按简历里最核心、最可疑的项目排在前面；每个新知识至少一问。

写完跑 `python3 $KB processed <简历.pdf> --candidate <姓名> --pack <学习包路径>`。

### 5. 汇报

对话里给：两个文件的链接、新知识数量、最值得先看的 3 个点（每个一句话）、建议 grok 深挖的列表、基础项请用户确认哪些本来就会。提醒一句：面试时直接 `start.sh --name <姓名>` 会自动带上追问题库。

## 其他用法

- **面试后入库**：interview-copilot 的《面试总结.md》第 8 节是「新知识」。用户说「把面试学到的入库」→ 读最近 session（`~/Desktop/面试/sessions/.current`）的总结，第 8 节每条走第 2–3 步（seen.context 写「面试现场：...」），已有卡片的术语把候选人的讲解补进卡片的「候选人怎么讲的」一节（用 `add --overwrite-cards` 前先读原卡片合并，不要丢内容）。
- **批量出讲义**：用户要把术语库里的知识点都整理成详细 md 时，走 grok skill。量大时分层：`deep_dive_worthy` 的走完整双师 grok，其余按 7 个一批由 Claude 单师+联网核实写（同样的讲义模板，外加「面试关联」一节）。先报规模和 token 估算让用户选。子任务只写 `~/Desktop/Analyse/` 和各自的 done 记录，主 agent 最后用 `python3 $KB link links.json`（`{术语: 讲义路径}`）挂回术语库。子任务可能因网络中断集体卡死，中间文件放 scratchpad 且每篇写完立刻记 done，重跑时就能续作。
- **标记掌握**：「XX 我懂了 / 本来就会」→ `python3 $KB mark mastered XX` 或 `mark known XX`。
- **复习**：「复习术语」→ `python3 $KB review --n 10`，读卡片后用卡片里的追问考用户，一次问一个，答完再讲解；用户答得好就 mark mastered。
- **趋势**：「最近简历都在做什么」→ `python3 $KB trend --last 20`，结合分类讲讲行业在往哪走、哪些还没学。
- 总览：`~/Desktop/面试/术语库/README.md`（每次 add/mark 自动重写）。
