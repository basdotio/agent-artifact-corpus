# 台账模板

放在项目文档目录下的 `brain/` 里：多仓项目放文档/契约仓，单仓项目放 `docs/brain/`。项目已经有同类文件就迁进这个结构，旧文件删掉，git 里有历史。

```
brain/
  ledger.md        当前状态快照（增删改）
  decisions.md     仍然有效的决定（增删改）
  handoff.md       下周开工第一屏（每周整篇覆盖）
  log/2026-W39.md  周流水（只追加本周）
  inbox/           讨论会话交回的文档（主脑处理完就删）
```

## ledger.md

```markdown
# 在飞台账（主脑维护，反映"现在"）

## 0. 规则
当前主脑会话：<会话名>（<YYYY>-W<ww> 起；每次换主脑时更新）
交回目录：<讨论会话交回文档的目录，比如 docs/gap-reports/ 或 brain/inbox/>

以上两行的开头文字固定不变，讨论会话靠 grep 这两个前缀找到台账和交回目录。

1. 派活权、验收权只在主脑。讨论会话只把结论落成文档（<gap-report 目录> 或 `inbox/`），直接提交到 main 后通知主脑。
2. WIP：<仓> 同时在飞代码分支 ≤ <N> 条。
3. 串行合入；每合一条，其余在飞分支 rebase 并重跑测试。
4. 联合验收：在合并后的 main 上跑全量。
5. 契约先行：<契约/ADR 所在仓> 先合。
6. 合入权限：<ff 合入并直接 push main | 每次合入先问用户>。
7. 测试口径：<全仓命令>；<集成命令>；真依赖地址 <...>。

## 1. 在飞（合入后删除这一行）
状态只用这几个值：`已派` / `实施中` / `待验收` / `验收中` / `打回` / `待用户` / `可合入`。
| 编号 | 分支（各仓） | 会话（名称 / task_id） | tip | 状态 | 验收要点 |
|---|---|---|---|---|---|

## 2. 待用户拍板（拍板后删除，有长期效力的移到 decisions）
| 编号 | 问题 | 选项 | 建议 | 阻塞什么 |
|---|---|---|---|---|

## 3. 队列（按优先级，随时重排；派出后移到 §1）
- P1 F-xxx <一句话> —— 来源 <文档/会话>

## 4. 环境与待清理
- 待归档会话：<会话名>（<原因>；等它空闲后归档）
```
