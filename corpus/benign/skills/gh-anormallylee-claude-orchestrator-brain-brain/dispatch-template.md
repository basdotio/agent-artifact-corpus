# 派活提示模板

每个槽位都必填，内容写不出来就说明任务还没想清楚，先别派。提示要能**自包含**：分支会话看不到主脑的对话。

```
你是<项目>主脑派出的<实施|调研|讨论>会话（中文交流）。
仓库根：<绝对路径>（<多仓时列出各仓及技术栈>）。

## 规则
- 在 worktree 里开发，分支 `<type>/<名字>` 基于最新 main；不合 main、不 push main。
- **每完成一条就 commit + push 分支。**
- <契约先行：改 <契约目录> 先落 <文档仓> 同名分支>
- 测试用真依赖（<本机依赖地址>），禁止 mock DB；每条修复附变异验证（回退修复，测试必须变红）。
- 禁止弹窗提问（不用 AskUserQuestion），需要决策时用文本列出选项和建议。
- 禁止按模式杀进程（`pkill -f`、`killall`、`kill $(pgrep -f …)`）：`-f` 匹配整条命令行，`pkill -f cat` 会命中 `/Applications` 下所有应用。只杀自己启动的进程，用启动时记下的 PID（`$!`），或先 `pgrep -fl` 确认再 `kill <PID>`。
- 越界即停：需要用户的凭据、登录、真实资金操作，或者改动超出本任务范围 → 停下来回报主脑，不要自己绕。
- 台账 <路径> 只读，由主脑更新。
<讨论会话改为：只产出文档到 <gap-report 目录>，不派修复、不做技术验证、不 rebase 别人的分支。>

## 不要碰

## 完工回报（用 SendMessage 发给主脑，按下面的格式；没有 SendMessage 时，把回报原文给用户，第一行写"请转发给主脑"）
```

## 回报格式（分支会话填写）

```
<任务名> 最终回报：<一句话结论>

【1. tip】每个仓：分支 = commit（基于 main 的哪个 commit），已 push 与否；逐个列出 commit。
【2. 测试】命令 + 结果（通过/失败/SKIP 的包数）；SKIP 和失败逐条写原因，并判断是否与本任务无关。
【3. 变异】M1…Mn：改了什么 → 哪些用例变红。
【4. 与派活设想的出入】实际行为和派活时的假设不一致的地方 + 证据 + 我怎么处理的。
【5. 偏离规则】没按规则做的地方，以及理由。
【6. 需要主脑/用户决定】编号，写选项和建议。
【7. 遗留】发现但没做的，建议入队。
```
