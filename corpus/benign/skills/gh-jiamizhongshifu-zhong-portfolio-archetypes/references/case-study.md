# 案例详情页与 NDA 作品

原型决定首页长什么样；案例页决定招聘方 / 客户是否相信你。这部分是编辑判断，不来自抓取数据（抓取只覆盖了首页）。

## 案例页结构

所有原型通用，视觉语言跟随主原型：

```
1. 标题区     项目名 · 一句结果（"Time-to-insight -38%"）· 角色 · 时间 · 团队规模
2. 封面       一张最能代表结果的图 / 视频
3. 背景       问题是什么，为什么重要（3–5 句）
4. 约束       时间、技术、业务、合规限制
5. 过程       2–4 个关键决策：当时的选项 → 选了什么 → 为什么
6. 结果       数据 + 定性反馈；没有数据就写上线后的变化
7. 反思       如果重做会改什么
8. 下一个案例  ←  →
```

- 首屏 10 秒内要能读到：**你的角色、问题、结果**。
- 长度控制在 4–8 屏；图文交替，不要连续 3 张以上大图没有文字。
- 各原型的变化：`poster-type` / `editorial-serif` 用大标题与满宽图分章节；`minimal-text` 用纯文字 + 少量内联图；`bento-cards` 可把背景 / 约束 / 结果做成卡片摘要。

## NDA 作品怎么呈现

按可公开程度从高到低选：

| 方式 | 做法 | 适合 |
|---|---|---|
| 脱敏重绘 | 用假数据、换品牌色、重绘关键界面 | 获得许可、只是不能露客户名 |
| 过程不露结果 | 展示草图、流程图、决策树，不放最终界面 | 界面敏感、过程可谈 |
| 文字案例 | 只写问题 / 决策 / 结果，配抽象示意图 | 界面完全不能露 |
| 列表 + 面试走查 | 列出项目名（可打码）、领域、角色、年份，标注“面试中可走查” | 什么都不能露 |

- 首页可以把公开案例做成大卡片，NDA 项目做成一张简洁列表，表明经验深度（测试样例中用打码条 + 领域 + 角色的列表，效果不错）。
- 永远不要把 NDA 截图打个马赛克就放上去——既违约又难看。
- 需要密码保护的案例页：给出明确的“申请访问”入口，而不是一个裸密码框。
