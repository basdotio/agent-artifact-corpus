# 标题改写规则（L1）

标题在元数据检索层权重最高——BM25 和向量检索都重仓标题。arXiv API 的
`ti:` 字段、Semantic Scholar、OpenAlex、Crossref 全部只索引 title/abstract。

## 结构模板

优先考虑这几个变体，各生成一版让作者挑：

| 模板 | 形态 | 适用 |
|---|---|---|
| 冒号副标题 | `核心方法：证据/范围` | 默认首选，副标题是免费的多召回入口 |
| 结论前置 | `方法 带来 N points 提升：跨 N 个 benchmark` | 有硬数字时 |
| 现象→方法 | `某类问题为何发生：我们的机制` | 内部术语和外部问题差距大时 |
| 对比定位 | `不同于假设 X 的做法：我们发现 Y` | 有反直觉结论时 |

## 前三个词

不要用这些开场：`Towards` / `A Novel` / `On the` / `A Comprehensive Study of` /
`A Study of` / `An Investigation into`。

它们是零信息量词，白占黄金位置，同时也是"水文"的统计特征，会拉低整句向量质量。
`Towards` 尤其可惜——在 NLP 领域它已经是"这篇贡献不足"的信号，读标题的
审稿人会先减一分。

## 冒号后面放什么

副标题是塞**同义词、领域名词、benchmark 名**的地方，规则：

- 只放你正文里真实出现过的东西（benchmark 名必须是真跑过的）
- 社区对同一件事有两种叫法就都放（`retrieval-augmented generation (RAG)`）
- 别在这里塞热词，热词走第三层的闸门，见 `layer3-terms.md`

## 数字

**先看数据再决定带不带**（实证见 `title-numbers.md`，五个顶会 16,677 篇录用标题）：
定量数字在录用标题里只占 **1.8–2.8%**，百分比几乎绝迹（五大会合计 4 例，
两位小数 0 例）。所以：

- **默认不带**。97% 的录用标题不带定量数字，带是差异化动作，不是装饰
- **要带就带人读的数**：整数大数（`1 million FPS`）、整数倍（`15x`）、
  拼写数词（`One-Shot`）、标志性整数百分比（`64% Better`）
- **禁止小数精度展示**：`48.6% less memory` → `half the memory`；
  `1.443×` → `1.4×` 或 `40% faster`；精确值留给摘要第 4–5 句
- 数字必须能在正文找到对应表格。找不到 → 标 `[待补]`
- 量级换算时朝证据保守侧舍入（48.6% lower memory → "half" 成立的唯一理由
  是"占用降为 51.4%"这个视角；若换算显得更强，宁可不带）
- 唯一允许小数的情况：小数本身是论点（量化到 `1.99 bits`）
- 数字常放冒号后（副标题是免费数字位）；数字不构成加长标题的理由
  （带数字标题中位 10–11 词，与不带相同）

## 撞名检查（改标题前必做）

方法缩写和方法名是最容易出事的地方，而且**后果和措辞完全不在一个量级**。

作者自创的缩写看着独特，实际经常撞车：撞名会让 AI 在检索匹配时把两篇论文
混淆，甚至把别人的实验结果当成你的。审稿人遇到同领域同名方法也会直接怀疑
你的工作。所以缩写不是"起个好听的名字"，它是一个**检索锚点**，撞了就失效。

```bash
node scripts/arxiv-trend.mjs --json "your acronym here" 2>/dev/null | head -20
```

或者用 arXiv API 直接查同名词条，重点看：

- 是否已有同领域论文用同一缩写（不同领域可以放过，同领域不行）
- 那个缩写是否已被更早的知名工作固化成了别的意思
- 方法名和缩写是否一致（正文叫 X，摘要写 Y，是一类隐蔽的归因错误）

撞了怎么办，按优先级：

1. **换缩写** — 首选，成本最低
2. **在摘要里把缩写和全称绑定出现**，让 AI 更倾向把"你的工作"和"你的全称"绑在一起
3. **把新缩写放进标题** — 降低被误配的概率（代价是放弃一个能带出领域词的位置）

作者自造缩写时，第一件事是在 `all:"<缩写>"` 上查一遍并把结果给他看。

## 长度

12-20 词。

这条是经验判断，不是被验证的定律：每多一个名词都在稀释标题向量对任何单个
query 的精度。超过 22 词时优先砍背景铺垫从句，保留方法名 + 结果 + 范围。

## 可检索性自检

写完把标题整句粘进 ChatGPT / Perplexity，问"你会用哪些论文回答这个问题"。
如果返回的论文语料和你的领域八竿子打不着，说明标题缺了那批人用的词。

## 反面清单

- 标题承诺了正文没有的强度 → 改写后 AI 引用它，然后被评论区打脸
- 堆方法名缩写当开头 → 只有已经知道你方法存在的人能搜到（这正是要避免的）
- 三个以上冒号层级 → 检索器看不懂主谓宾，读者也看不懂
- 副标题写成 abstract 的压缩版 → 长度失控且不可读

## 一个正反例

❌
> Towards Robust Retrieval-Augmented Generation: A Comprehensive Study of Adaptive Decomposition Techniques

问题：首位浪费；"Comprehensive" 零信息；无数字；无 benchmark；读者读完不知道你做了什么。

✅
> Adaptive Query Decomposition for Multi-Hop RAG: +23 Accuracy Points Across 6 Benchmarks and 3 LLM Families

信息量相当，但方法名、任务名、量级、评测广度全在，且能整句粘进任何提问框。
