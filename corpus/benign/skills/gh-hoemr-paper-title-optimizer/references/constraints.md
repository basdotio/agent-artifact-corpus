# 硬约束与反模式

这五条是 skill 的不可协商部分。它们不是风格偏好，违反任意一条都会造成
实质损害（学术诚信事故 / 论文被 AI 误引 / 工具失去可信度）。

---

## 约束 1：不新增事实

输出里的每个数字、名称、benchmark、引用，必须能在输入的论文全文里指到出处。

**为什么**：这是本工具最高风险的失效模式。检索优化天然带来"再具体一点、
再加个数字"的诱惑，而论文里根本没那个数字。补一个看起来合理的数字，
等于给一篇论文埋一个几个月后被翻出来打脸的雷。

**缺证据时的唯一正确行为**：

```
[待补: 需要 <baseline> 上的绝对准确率，正文 Table 3 未给出该数值]
```

禁止估算、禁止"根据经验典型值"、禁止从相邻表格外推。

---

## 约束 2：不抬高 claim 强度

只允许把 claim 做得**更具体**，不允许做得**更强**。

| 允许 | 禁止 |
|---|---|
| `显著提升了检索准确率` → `准确率提升 19.3 分（6 个 benchmark 均值）` | `准确率提升 19.3 分` → `大幅超越 SOTA` |
| `实验表明有效` → `在 X 上从 61.2 提升到 80.5` | 加上正文没有的 `显著` / `novel` / `first` |
| 明确写出代价 | 隐去负面结果 |

**为什么**：可验证性 > 流畅度。目标如果必须靠抬高 claim 才能达成，正确动作是
告诉作者"这篇需要补实验"，不是换个说法让它听起来更强。优化改变表达，
不改变论文说了什么。

---

## 约束 3：不挂无关热词

见 `layer3-terms.md` 资格闸门。相关但不适用的词，宁可不挂。

**为什么**：审稿人能识别出为检索而写的痕迹，而且这正是 KDD 论文实测有害的
那个操作。一个被审稿人识破的标题，比一个保守但可信的标题代价大得多。

---

## 约束 4：正文只给定位建议，不重写

对论文正文的输出是**位置 + 建议 + 理由**，不是改写后的段落。

例：
> `§3.2` 第 2 段建议加入术语映射句——这里首次出现 "polysemanticity"，
> 但没有说明它对应可解释性社区的 "feature superposition"。相邻社区的读者
> 搜不到你。

**为什么**：全文重写会引入新的 claim 风险（约束 1/2），且作者对正文的掌控
需求远高于对摘要。把正文改到需要通读校对才能接受，工具就没人用了。

---

## 约束 5：无法验证就标出来，不猜

包括：数字、引用关系、claim 强度、以及**测量的结果**。

脚本没测到的后端输出 `skipped` 并写明原因，**绝不输出假的 0**。
报告里未测量的项一律标 `null` + 原因。

**为什么**："没测"被读成"测了没有"是这个领域最常见的误读。混淆一次，
作者就会基于假结论做决策。

---

## 反模式速查

| 反模式 | 为什么坏 | 正确做法 |
|---|---|---|
| 摘要里塞 8 个热词 | 关键词堆砌，KDD 实测有害 | 最多 3 个词汇空间，1 个 `rising` |
| 把 `background` 词当钩子用 | 带不去新流量池，只在老池里更显眼 | 作背景词用即可 |
| 为了够字数稀释数字句 | 数字句是引用锚点，最不该砍 | 砍背景铺垫 |
| 把方法名缩写放开头当标题 | 只有知道你方法的人能搜到 | 现象层前置 |
| 改写后不回填原文位置 | 作者无法向合作者/导师解释 | 每条改写附证据指针 |
| 只给新标题不给理由 | 采纳率归零 | 每处改动写清为什么 |
| 用"提升可见性 X%"承诺效果 | 效果要 3-9 个月才观测 | 给代理指标，不承诺 |
| 在旧 arXiv 上改标题不改版本号 | 索引不更新 | 提 v2，abstract 可改 |
