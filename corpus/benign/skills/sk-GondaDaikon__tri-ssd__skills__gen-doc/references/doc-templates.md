# L2 サブ文書テンプレート集

gen-doc が生成する L2 サブ文書の正規テンプレート。生成前に該当節を読み、記入基準に従うこと。
YAMLフロントマターは共通で `layer: L2` / `updated: YYYY-MM-DD`（`depends:` は任意）。

## 機能契約（features/<機能名>.md）

機能単位の**責務の契約**。「何をやるか」だけでなく「**何をやらないか**」を明文化し、実装（特に AI エージェント）が余計な処理を混ぜたときにレビューで契約違反として検出できるようにする。

**適用基準**: 機能10個超のプロダクト、またはリソース・常駐系（ファイルハンドル・監視・常駐プロセス・外部 API 呼び出し等）に触れ「やらないこと」の逸脱が事故になる機能のみ。該当しなければ作らない。

### テンプレート（7セクション固定）

```markdown
# [機能名]

## 目的

ユーザーに何を提供するか（1-3文）

## やること

- [実装上必要な処理]

## やらないこと

- [禁止・スコープ外。「別機能の責務」「性能/安全上やらない」を明示]

## 性能予算

- [体感目標を数値で。例: 一覧表示は 100ms 以内]

## 副作用

- [DB / ファイル / 外部送信などの永続化・外部作用]

## 依存

- [依存する / される機能・テーブル・API]

## 既知の判断（任意）

- [意識的に採用した方針・トレードオフ]
```

### 記入基準

| セクション | 何を書く | 書かない |
|---|---|---|
| やらないこと | **事故防止の本丸**。「別機能の責務」「性能・安全上禁止」を具体的に | 自明なこと（「バグを入れない」等） |
| 性能予算 | 体感目標の数値（超えたら契約違反と判定できる形） | 実装方式 |
| 副作用 | 永続化・外部送信・リソース確保のすべて | 一時変数などプロセス内で閉じるもの |
| 全体 | 機能契約のみ。コード詳細（関数名・行番号）は書かない — コードが真実 | |

初回作成時は `features/README.md` に一覧表（機能名・1行概要・リンク）を作る。以後1行ずつ追加。

## 教訓（lessons.md）

L1 の要求でも L2 の設計でもない**学び**の蓄積場所（プロセスの学び・UX の気づき・機能の廃止判断など）。
**追記のみ**（過去の教訓は書き換えない・消さない。教訓が覆ったら新しい行で上書きの旨を書く）。

### 形式

```markdown
# 教訓（Lessons）

- YYYY-MM-DD [PH-xxxx]: [教訓1行。何をして何を学んだか]
- YYYY-MM-DD [PH-xxxx]: [例: Clock widget は4回改修しても体感が改善せず廃止。表示系は最初に体感目標を数値化してから作る]
```

L1/L2 に昇格すべき内容（要求の変化・設計前提の変化）が混ざっていたら、lessons への追記と同時に該当レイヤーの更新を提案する。

## 検証実証ログ（`validation/<topic>.md`）

事実確認（スパイク・API 検証）の**詳細根拠**。foundation「確認済みの前提」を膨らませないための分離。

### 形式

```markdown
# [トピック] 実証ログ

> foundation.md「確認済みの前提」の詳細根拠。結論サマリは foundation 側を参照。

## 方法

- 実施日: YYYY-MM-DD
- 方法: [ツール・頻度・遵守事項（ToS・レート制限）]

## 結果

- [実クエリ・レスポンス例・件数・確認したフィールド]

## 結論

- [判明した事実（foundation「確認済みの前提」に転記した内容と一致させる）]
```

foundation 側の「確認済みの前提」には結論1行＋`（詳細: validation/<topic>.md）` を書く。

## 用語集（glossary.md）

foundation §7 が肥大したときのみ分離（layer-rules トリガー⑤）。形式は §7 と同じ `| 用語 | 定義 |` の表。分離時は §7 をポインタ化する。
