# 变量 / 约束 / 档位 书写规范

> 这是 cognitive-anchor 的"翻译层"语法手册。agent 把用户的话翻译成下面三种元素时，照此书写。

## 1. 变量声明（--declare）

格式：`变量名:中文含义`，逗号分隔。变量名用小写字母（可带数字），含义用中文。

```
x:可行性,y:预算充足,z:时间允许,w:风险可控
```

规则：
- 变量只取 0 或 1（脚本自动加域约束 `0<=v<=1`）
- 含义要写成"肯定句"：`y:预算充足`（=1 表示预算充足），而不是 `y:预算不足`
- 数量建议 3~8 个；超过 8 个说明问题拆得不够，先合并同类项

## 2. 硬约束（--constraints）

分号 `;` 分隔多个 z3 表达式。可用运算符与函数：

| 写法 | 含义 | 示例 |
|---|---|---|
| `v==1` / `v==0` | 变量取值 | `x==1` |
| `v1+v2+...>=n` | 至少 n 个成立 | `x+y+z+w>=3` |
| `Implies(A,B)` | 若 A 则 B | `Implies(y==0,w==1)`（预算不足→风险可控） |
| `And(A,B)` / `Or(A,B)` | 且 / 或 | `And(x==1,w==1)` |
| `Not(A)` | 非 | `Not(x==1)` |
| `If(条件,真值,假值)` | 条件选择 | `If(x==1,1,0)` |

写约束的常见模式：
- 组合条件：`x+y+z>=2`（至少两个成立才算可行）
- 条件依赖：`Implies(z==0,And(x==1,w==1))`（时间不允许→必须可行且风险可控）
- 互斥：`Or(x==0,y==0)`（两者不能同时成立）
- 排除组合：`Not(And(x==1,y==1,z==1))`

注意：
- 变量是整数，比较写 `==`（不是 `=`）
- 不要写 `Not(y)` 这种对整数取反的写法，改写成 `y==0`
- 约束要能表达"人话里的必须/不能/除非"，写不出来就拆成多条

## 3. 决策档位（--decisions）

分号 `;` 分隔多个 `档名:谓词`。谓词对每个满足解求值，命中则记一票。

```
做:x+y+z+w>=4; 观望:x+y+z+w==3; 不做:x+y+z+w<3
```

规则：
- **档位必须互斥**（区间划分），不要写 `不做:True` 这种永远命中的兜底——它会抢走所有票
- 档名用中文短词：做 / 观望 / 不做、买 / 等 / 不买、A方案 / B方案……
- 谓词用上面第 2 节的表达式语法
- 推荐 = 票数最多的档；并列时用分支表第一条的档位裁决

## 4. 多轮对齐（--rounds）

`|` 分隔每轮追加的约束，第一段留空表示第一轮不加约束：

```
--rounds "|y==0"
```

含义：第一轮=原始约束；第二轮=原始约束 + `y==0`（预算紧张）。

追加规则：
- 每轮只写"新增"约束，脚本会自动累积
- 用户新说的条件、修正、澄清，都翻译成新约束追加
- 对比首末两轮推荐：不同=漂移（提示标准未稳）；相同=收敛（可钉结论）

## 5. 完整示例

人话：*"我想做一个小项目，可行性和时间最重要，至少两个条件成立才敢动手；预算不足时风险必须可控；时间不允许的话可行性必须成立。你看我做、观望还是不做？哦对了，预算其实很紧张。"*

翻译：
```
--declare "x:可行性,y:预算充足,z:时间允许,w:风险可控"
--constraints "x+y+z>=2; Implies(y==0,w==1); Implies(z==0,x==1)"
--decisions "做:x+y+z+w>=4; 观望:x+y+z+w==3; 不做:x+y+z+w<3"
--rounds "|y==0"
```

## 6. 翻译层边界（诚实声明）

- 本规范只覆盖"自然语言 → 符号"的书写规则；翻译动作由 agent（豆包）完成，不调用外部 LLM API
- 多模态输入（图片/图表/视频）：先用视觉/文档技能提取结构化事实，再按本规范翻译；若提取结果不确定，宁可不设该变量并在输出里注明"未建模因素"
- 遇到用户没明说但影响结论的条件，主动追问 1 次；追问不动就按"未建模"处理并提示
