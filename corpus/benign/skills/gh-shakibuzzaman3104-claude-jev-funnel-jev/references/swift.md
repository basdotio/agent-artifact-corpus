## Architecture: the app never holds a key

```
iOS app ──(App Attest / Firebase App Check token)──▶ your backend ──(OPENROUTER_API_KEY)──▶ openrouter.ai/api/alpha/decisions
```

- Same rule as Kotlin (`references/kotlin.md`): a key inside an app binary can be extracted,
  obfuscated or not. It stays server-side, with a credit limit set on the key.
- The backend must know a request came from your real app, not a replayed API shape. Verify
  the device with **Apple App Attest** (native) or **Firebase App Check** (App Attest under
  the hood on iOS, plus a managed server-side verifier) before spending a Jev call on it.
- Expose **use-case endpoints** (`POST /decisions/ticket-triage`), not a generic "forward any
  question" endpoint — a leaked device token still can't turn your key into a free API.
- The backend can be anything that holds a secret and makes an HTTP call. If yours is
  Kotlin/JVM, use `references/kotlin.md`'s Retrofit client instead of the sketch below —
  same architecture, same endpoint shape, different language.

## Preferred for bundled content: tag at build time, no runtime call

If what you need is content selection (tone, "fits a push notification", reading depth)
over a fixed set of bundled items — tips, articles, prompts, onboarding copy — don't call
Jev at runtime. Run `jev.py batch` once, before you ship, and bake the answers into the
JSON you already bundle. No backend, no attestation, no key on the device.

Example for a bundled file shaped `{"items": [{"id": ..., "text": ...}, ...]}` (adjust the
paths and keys to yours). `<skill-dir>` is this skill's base directory (see "Running the
script" in `SKILL.md`). Extract the items first, and keep the output outside `Resources/`
so it is never bundled into the app:

```bash
python3 -c 'import json; d = json.load(open("App/Resources/content.json", encoding="utf-8")); print("\n".join(json.dumps({"id": it["id"], "text": it["text"]}, ensure_ascii=False) for it in d["items"]))' > /tmp/content-items.jsonl
python3 "<skill-dir>/scripts/jev.py" batch \
  --items /tmp/content-items.jsonl \
  --template tag-content-template.json \
  --out tools/content-tags.jsonl
```

`tag-content-template.json` — one batched request per chunk, keyed ids handled by `batch`:

```json
{
  "questions": {
    "tone": {
      "type": "choice",
      "instructions": "What tone does `item.text` have?",
      "criteria": {
        "calm": "Relaxed, reassuring, unhurried",
        "upbeat": "Energetic, encouraging, motivating",
        "serious": "Warnings, hard trade-offs, sensitive topics",
        "none": "No listed tone fits"
      }
    },
    "notification_fit": {
      "type": "noul",
      "instructions": "Would `item.text` work well as a short push notification?",
      "criteria": {"true": "Understandable on its own and readable at a glance",
                   "false": "Needs surrounding context, or too long to read at a glance"}
    },
    "depth": {
      "type": "score",
      "instructions": "How much attention does `item.text` ask of the reader?",
      "criteria": ["Quick tip, reads in a glance", "Takes a minute of focused reading", "In-depth, needs time and context to follow"]
    }
  }
}
```

Merge the tags into the bundled JSON (run once, before you archive the build):

```python
import json

path = "App/Resources/content.json"
with open(path, encoding="utf-8") as f:
    data = json.load(f)
tags = {}
with open("tools/content-tags.jsonl", encoding="utf-8") as f:
    for line in f:
        row = json.loads(line)
        if "answers" in row:
            tags[row["id"]] = row["answers"]

for item in data["items"]:
    answers = tags.get(item["id"])
    if not answers:
        continue  # untagged; the app treats this as "no preference"
    item["tone"] = answers["tone"]["choice"]
    item["notificationFit"] = answers["notification_fit"]["noul"] >= 0.8
    item["depth"] = int(answers["depth"]["score"] + 0.5)

with open(path, "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, separators=(",", ":"))
```

If the bundled JSON is generated by a tool, merge the tags into the generator's input
instead so they survive regeneration.

On device, the `ContentItem` model just gains the extra `Codable` fields and the app
filters on them locally. Re-run with the same `--out` (already-tagged ids are skipped) as
the content grows; only build a runtime path once a feature needs a live judgment on
user-entered text.

## A backend proxy sketch (TypeScript)

A compact use-case endpoint — not a passthrough — as a Firebase Cloud Function (2nd gen).
The same shape works as a Cloudflare Worker; the Firebase-specific part is
`getAppCheck().verifyToken()`, which is what buys you not hand-rolling App Attest
verification yourself. On Cloudflare, verify the App Check token against Firebase's
published keys, or use a different attestation mechanism — the Admin SDK doesn't run there.

```typescript
import { onRequest } from "firebase-functions/v2/https";
import { defineSecret } from "firebase-functions/params";
import { initializeApp } from "firebase-admin/app";
import { getAppCheck } from "firebase-admin/app-check";

initializeApp();
const openRouterKey = defineSecret("OPENROUTER_API_KEY");
const RETRYABLE = new Set([429, 500, 502, 503, 504, 529]);

async function requestJevDecisions(body: unknown, apiKey: string): Promise<any> {
  const delaysMs = [0, 500, 1500, 4000]; // fixed backoff; add jitter for real traffic
  let lastError = new Error("unreachable");
  for (const delay of delaysMs) {
    if (delay) await new Promise((resolve) => setTimeout(resolve, delay));
    const response = await fetch("https://openrouter.ai/api/alpha/decisions", {
      method: "POST",
      headers: { "Content-Type": "application/json", Authorization: `Bearer ${apiKey}` },
      body: JSON.stringify(body),
      signal: AbortSignal.timeout(15_000),
    });
    if (response.ok) return response.json();
    if (!RETRYABLE.has(response.status)) throw new Error(`Jev ${response.status}: ${await response.text()}`);
    lastError = new Error(`Jev ${response.status}, retrying`);
  }
  throw lastError;
}

interface TicketTriageDecision {
  department: string;
  departmentPMax: number;   // top probability — the band to gate on, not `confidence`
  urgencyProbability: number;
  frustrationScore: number;
  needsHumanReview: boolean;
  modelVersion: string;
}

// Deployed behind a Hosting rewrite to /decisions/ticket-triage — same URL the Kotlin
// backend client in references/kotlin.md calls, if both apps share one backend.
export const ticketTriage = onRequest({ cors: false, secrets: [openRouterKey] }, async (req, res) => {
  if (req.method !== "POST") { res.status(405).json({ error: "Method Not Allowed" }); return; }

  const appCheckToken = req.header("X-Firebase-AppCheck");
  if (!appCheckToken) { res.status(401).json({ error: "Missing App Check token" }); return; }
  try {
    await getAppCheck().verifyToken(appCheckToken);
  } catch {
    res.status(401).json({ error: "Invalid App Check token" });
    return;
  }

  const message = String(req.body?.message ?? "").slice(0, 4000);
  if (!message) { res.status(422).json({ error: "message is required" }); return; }

  try {
    const jev = await requestJevDecisions({
      model: "typesafe/jev-1.13",
      state: { message },
      questions: {
        department: {
          type: "choice",
          instructions: "Which team should handle `message`?",
          criteria: { payments: "Charges, refunds, wallet, payouts", trip_issue: "Problems during a ride or delivery",
                      account: "Login, verification, profile", safety: "Harassment, accidents, threats",
                      none: "No listed team fits" },
        },
        is_urgent: { type: "noul", instructions: "Does `message` need action within the hour?" },
        frustration: { type: "score", instructions: "How frustrated is the writer of `message`?",
                       criteria: ["Calm, stating facts", "Annoyed but polite", "Angry, strong language or threats"] },
      },
    }, openRouterKey.value());

    const department = jev.answers.department;
    const departmentPMax: number = Math.max(...Object.values(department.probabilities as Record<string, number>));
    const decision: TicketTriageDecision = {
      department: department.choice,
      departmentPMax,
      urgencyProbability: jev.answers.is_urgent.noul,
      frustrationScore: jev.answers.frustration.score,
      needsHumanReview: departmentPMax < 0.5 || ["safety", "none"].includes(department.choice),
      modelVersion: jev.model,
    };
    res.status(200).json(decision);
  } catch (error: any) {
    res.status(502).json({ error: error.message ?? "Jev request failed" });
  }
});
```

Keep the model slug in config and log `jev.model`; treat a 402 (no OpenRouter credit) as a
page-someone failure, not a retry target.

## Swift client for your backend

The app calls its own backend's use-case endpoint, not OpenRouter directly, so most of the
client is an ordinary `URLSession` + `Codable` call.

Model the three Jev answer shapes once, generically, so any endpoint that forwards raw
answers decodes the same way — `.unknown` covers a type the client doesn't know about yet:

```swift
enum JevAnswer: Decodable, Sendable {
    case noul(p: Double)
    case choice(choice: String, probabilities: [String: Double])
    case score(score: Double, confidence: Double)
    case unknown(type: String)

    private enum CodingKeys: String, CodingKey { case type, noul, choice, probabilities, score, confidence }

    init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        switch try c.decode(String.self, forKey: .type) {
        case "noul":
            self = .noul(p: try c.decode(Double.self, forKey: .noul))
        case "choice":
            self = .choice(choice: try c.decode(String.self, forKey: .choice),
                            probabilities: try c.decode([String: Double].self, forKey: .probabilities))
        case "score":
            self = .score(score: try c.decode(Double.self, forKey: .score),
                           confidence: try c.decode(Double.self, forKey: .confidence))
        case let other:
            self = .unknown(type: other)
        }
    }
}
```

Decode a specific choice into your own enum, with `none` (Jev's own no-match answer) and
`unknown` (anything new or unrecognised) as distinct, always-available cases:

```swift
enum SupportDepartment: String, Decodable, Sendable {
    case payments, tripIssue = "trip_issue", account, safety, none, unknown

    init(from decoder: Decoder) throws {
        let raw = try decoder.singleValueContainer().decode(String.self)
        self = SupportDepartment(rawValue: raw) ?? .unknown
    }
}
```

A small policy type for act / confirm / escalate, with a stricter policy for riskier
actions. Which number feeds it differs by type: a noul's `p`, a choice's `p_max`
(`probabilities.values.max()` — not `confidence`, which means something different at 3
options than at 15), a score's `confidence`. Cutoffs live here, next to the action, not
in the prompt:

```swift
enum JevAction: Sendable { case act, confirm, escalate }

struct JevActionPolicy: Sendable {
    var actAtOrAbove: Double
    var escalateBelow: Double

    static let routine = JevActionPolicy(actAtOrAbove: 0.8, escalateBelow: 0.5)  // suggested category, pre-filled field
    static let risky = JevActionPolicy(actAtOrAbove: 0.95, escalateBelow: 0.5)   // notifying a person, closing a ticket

    func decide(_ value: Double) -> JevAction {
        value < escalateBelow ? .escalate : (value >= actAtOrAbove ? .act : .confirm)
    }
}
```

The use-case response, request body, and a repository that never throws into the UI:

```swift
struct TicketTriageDecision: Decodable, Sendable {
    let department: SupportDepartment
    let departmentPMax: Double   // top probability — the band to gate on, not `confidence`
    let urgencyProbability: Double
    let frustrationScore: Double
    let needsHumanReview: Bool
    let modelVersion: String
}

enum TicketTriageResult: Sendable {
    case decided(TicketTriageDecision)
    case unavailable(reason: String)
}

struct SupportDecisionService: Sendable {
    let baseURL: URL
    let session: URLSession = .shared

    func fetchTicketTriageDecision(message: String) async -> TicketTriageResult {
        var request = URLRequest(url: baseURL.appendingPathComponent("decisions/ticket-triage"))
        request.httpMethod = "POST"
        request.timeoutInterval = 8   // never block the UI on Jev
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try? JSONEncoder().encode(["message": message])

        do {
            let (data, response) = try await session.data(for: request)
            guard let http = response as? HTTPURLResponse, (200..<300).contains(http.statusCode) else {
                return .unavailable(reason: "HTTP error")
            }
            return .decided(try JSONDecoder().decode(TicketTriageDecision.self, from: data))
        } catch {
            return .unavailable(reason: "Network error")
        }
    }
}
```

In the UI, `.unavailable` and a low-confidence `.escalate` both fall back to the same
manual path — a category picker, not a spinner that never resolves.

## Swift 6 / SwiftUI idioms

`JevAnswer`, `TicketTriageDecision` and `SupportDecisionService` are already `Sendable`, so
they cross actor boundaries without extra ceremony. An `@Observable` view model keeps the
async call and the fallback decision together:

```swift
@MainActor
@Observable
final class TicketTriageViewModel {
    private(set) var decision: TicketTriageDecision?
    private(set) var needsManualPicker = false

    private let service: SupportDecisionService

    init(service: SupportDecisionService) { self.service = service }

    func triage(message: String) async {
        switch await service.fetchTicketTriageDecision(message: message) {
        case .decided(let decision):
            self.decision = decision
            needsManualPicker = JevActionPolicy.risky.decide(decision.departmentPMax) != .act
        case .unavailable:
            decision = nil
            needsManualPicker = true
        }
    }
}
```

The view reads `needsManualPicker`/`decision` and switches between a suggested-department
chip and the ordinary picker — the same fallback rule as Kotlin's `isVisible` toggle,
expressed declaratively.

## The community Swift bridge (jev-foundation-models)

[`peterfriese/jev-foundation-models`](https://github.com/peterfriese/jev-foundation-models)
is an unofficial, third-party Swift 6 package (verified from its README and source, not a
TypeSafe project). It maps Apple Foundation Models `@Generable` types onto Jev's primitives
— `Bool` → `noul`, an `enum` → `choice`, `@Guide(.range(...))` → `score` — so a
`LanguageModelSession` can run against `JevLanguageModel` instead of Apple's on-device
model. Its own `RoutingPolicy` (`escalateBelow` / `autoAtOrAbove`) produces an
`.auto`/`.confirm`/`.escalate` `Decision` via `response.decision(for:policy:)` — the same
three-way split as the policy type above, and part of what inspired it.

It **targets TypeSafe direct** (`JevLanguageModel.Configuration.endpoint` defaults to
`https://api.typesafe.ai/v1/systemone`) and, like the Kotlin community SDKs, warns never to
embed `TYPESAFE_API_KEY` in a mobile binary — it ships a complete reference,
`Integrations/FirebaseAppCheckProxy`, for exactly the architecture at the top of this file:
an App-Attest-backed transport on the client, a Firebase Cloud Function that verifies the
App Check token and injects the real key from Secret Manager.

`endpoint` is a plain configurable `URL`, and TypeSafe-direct and OpenRouter document the
same request/response body (`references/api.md`), so pointing it at
`https://openrouter.ai/api/v1/systemone` with an OpenRouter key is plausible — but
**untested**: the package has no OpenRouter code path or mention of one. Verify it against
a real call before relying on it; the plain `URLSession` client above, calling your own
backend, doesn't need this package at all.

## Language and input

Jev reads English best; other languages work but check confidence more carefully before
trusting a threshold. Input is text only — a string, JSON object, or array of text, never
images or other binary data (`references/api.md`). Describe non-text content in words
before putting it in `state`.
