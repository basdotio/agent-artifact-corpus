# Friction: Android bookmarks client (self-hosted server), skill 3072ea4

- **TOOL** · `net.sh reach` — reported that the app could not reach the test server ("No address associated with hostname") and blamed the app's network rules. On an Android 17 emulator, nothing resolves from the `run-as` context at all (a public host fails the same way, though the app uid has the inet group), while the shell resolves fine. The app itself reached the server (its own traffic in the log and new rows in its database after a cold start). Suggestion: check a control host from `run-as` too, and answer NOT PROVEN when it also fails instead of blaming the app.
- **TOOL** · `redcheck.py` — classified Mockito's `NeverWantedButInvoked` / `WantedButNotInvoked` as "ended before their check — a crash". Those are the test's own `verify` failing (`MockitoAssertionError` extends `AssertionError`). In a later run the same kind of failure was reported as RED, so the classification seems to depend on something other than the exception type. Worth treating any `AssertionError` subclass as the verdict. (It correctly refused an NPE from an unstubbed call as a red, which is exactly what it should do.)
