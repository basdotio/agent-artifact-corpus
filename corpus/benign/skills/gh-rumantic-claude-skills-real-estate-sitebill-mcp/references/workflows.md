# Сценарии работы агента

Готовые последовательности вызовов для типовых задач риелтора. Перед каждой записью сверяйтесь с пользователем.

## 1. Подборка для клиента

Запрос: «Подбери клиентке Ивановой двушку до 9 млн в центре и сделай ссылку».

1. `list_contacts` (`search`: Иванова) → `get_contact`: уточнить, что клиентка ищет, нет ли уже сделки.
2. `get_search_options` → `resolve_location` («центр» → `district_id`).
3. `search_properties` (`deal_type`: sale, `rooms`: [2], `price_max`: 9000000, район). Если результатов слишком много или мало,
   предложить ослабить или уточнить критерии.
4. Показать лучшие варианты кратко (цена, площадь, адрес, id).
5. `create_selection` с теми же фильтрами и `title` → отдать ссылку.
6. По согласию: `add_contact_note` (критерии подборки) и/или `move_deal` на стадию «Показ».

## 2. Новый клиент и сделка

Запрос: «Заведи контакт: Пётр, +7…, ищет студию в аренду, и создай сделку».

1. `list_contacts` (`search` по телефону): убедиться, что клиента нет. `create_contact` сам откажет при дубле.
2. `create_contact` (`name`, `channels`, `notes`).
3. `list_deals`: взять воронку и стадии. Первая стадия подойдёт по умолчанию.
4. `create_deal` (`contact_id`, `direction`: demand, `operation`: rent_long, `amount`: бюджет, `notes`: требования).
5. При необходимости найти объекты и передать их в `property_ids`.

## 3. Разбор воронки

Запрос: «Что висит в сделках на стадии "Показ"? С кем давно не общались?»

1. `list_deals` (`status`: open): найти id стадии «Показ» в ответе, затем `list_deals` с `stage_id`.
2. `list_contacts` с `last_activity_before` (дата месяц назад): кого пора «разбудить».
3. Выдать список: клиент, сумма, ожидаемая дата, давность последней активности, предложение следующего шага.
4. По решению пользователя: `add_deal_comment` или `move_deal`.

## 4. Объявление из описания

Запрос: «Создай черновик объекта по этому описанию».

1. `get_search_options`: допустимые `type`, `deal_type`, кастомные поля. `resolve_location`: `city_id`, `district_id`.
2. Собрать обязательные поля (`title`, `type`, `deal_type`, `price`, `area_total`, `city_id`). Чего не хватает, спросить,
   не додумывать.
3. Показать пользователю, что будет создано, и вызвать `create_property`. Объект станет черновиком.
4. Сказать, что публикует его пользователь (или `update_property` с `publish: true`, если у него есть право).

## 5. Массовая правка цены

Запрос: «Подними цену на 3% у моих объектов в Советском районе».

1. `search_properties` (`scope`: mine, район) постранично: собрать список объектов с текущими ценами.
2. Показать таблицу «было → станет» и дождаться подтверждения.
3. `update_property` по каждому объекту с новой `price`. Сообщить, сколько обновлено и какие вызовы не прошли.
