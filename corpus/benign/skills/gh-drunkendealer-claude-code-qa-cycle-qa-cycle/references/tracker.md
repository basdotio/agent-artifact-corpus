# The durable record

Long loops outlive the context window and the scratchpad. Keep two things durable:

1. **Tracker artifact** — a published page (private by default) the user reads and that survives compaction. Republish after every batch of status changes; it's the source of truth when resuming.
2. **Tooling folder** outside the scratchpad, e.g. `~/.claude/projects/<project>/qa-fix/`:
   `tracker.html` (local copy of the artifact), `qa.config.json`, the scripts below (copied from this skill's `scripts/`), generated `FIXRULES.md` / `VERIFYRULES.md`, `agents.txt`, `plans/`.
   Sandboxes (`<scratch>/<sandboxDir>/<ID>`) and worktree symlinks live under `scratch` in `qa.config.json`: point it at a **durable** path (e.g. the tooling folder; it is gitignored there and not synced) — not the session scratchpad, which a restart can wipe. Only scripts agents write for themselves belong in the scratchpad. Add `.claude/worktrees/` to the repo's `.gitignore` (fixer worktrees live there; an untracked one otherwise shows in `git status`).

Also save a short project memory pointing at both, updated at each cycle boundary.

## Tracker data

Embed the data as one JSON literal in the page (`const D={...};`) so small scripts can edit it:

```json
{ "workstreams": { "W1": { "name": "Server integrity", "scope": "server/projects.js, …" } },
  "items": [ { "id": "N150", "sev": "B|M|m", "bucket": "now|later", "ws": "W6", "unit": 12,
               "title": "…", "where": "file / function", "note": "repro + decisions",
               "status": "open|fixing|fixed|verified|failed|deferred",
               "commit": "", "verify": "verifier evidence, appended with ' | '",
               "by": "agentId of the verifier that verified it (set by st.mjs verified --by)",
               "triage": "known|next (later items only)",
               "residuals": [ { "text": "…", "state": "open|accepted|fix", "at": "date", "resolvedAt": "date" } ] } ],
  "units": { "U1": { "name": "Editor", "files": ["src/editor", "server/projects.js"] } },
  "passes": [ { "cycle": "2", "sha": "abc1234", "at": "…", "units": ["U1"], "platforms": ["android", "ios"], "found": { "B": 0, "M": 1, "m": 3 } } ],
  "gate": { "sha": "abc1234", "at": "…" },
  "done": { "verdict": "ANOTHER CYCLE", "why": "…", "cycle": "2", "sha": "…", "at": "…", "criteria": [ { "n": 1, "name": "…", "ok": true, "evidence": "…" } ] } }
```

`units` is the unit plan, `passes` the test passes (`st.mjs pass`), `gate` the sha the last successful `merge.sh` gated, `done` the last `done.mjs` result.

The page shows: a **QA CYCLE STATUS** banner rendered from `D.done` (verdict, the reason, and the seven criteria as ✅/❌ with their evidence; "not checked yet" when `D.done` is missing), a summary strip (counts by severity, fix-now vs later, `verified/total`), the execution plan, workstreams, and a filterable register (bucket, severity, workstream, status). The strip is static HTML; the scripts recompute its six `<b>` values from `D` on every write. Better: let the page compute them itself — give each `<b>` an id and set them from `D.items` in the page script right after the data literal, so the data is the only thing that ever changes.

## Status lifecycle

`open → fixing → fixed (merged) → verified`, or `fixed → failed → fixing → …`. `deferred` = later bucket, waiting on a decision.
Enums the scripts enforce: status `open|fixing|fixed|verified|failed|deferred`; severity `B|M|m`; bucket `now|later`; workstream = a key of `workstreams` or one already used by an item (`--force` creates a new one). `verified` requires non-empty `commit` and `verify`, a `--by` verifier (an `agents.txt` row with role `verifier` that lists the item among its items and is not a fixer listed for it), shas that are ancestors of main, and no `open` residual (the item stays `fixed` until the user's answer is recorded). Every `--commit` sha must exist and be an ancestor of main whatever the status. On an item that already has shas `commit` only grows (`--commit` adds, never replaces; `merge.sh` also adds); `--force` replaces. Every stored sha is `git rev-parse --short` of the resolved commit (`--commit HEAD~1` stores the sha, never the expression; existing values stay as they were). Severity decides the bucket of a NEW item: `B`/`M` → `now`, `m` → `later` (`add.mjs` default; `--now` overrides); `later` reaches `now` only at the user's gate. The page shows `by` and the residuals in the item row.

## Tooling scripts

There is ONE copy of the scripts: this skill's `scripts/`. Install by symlinking every script into the tooling folder next to `tracker.html` (`for f in <skill>/scripts/*.mjs <skill>/scripts/*.sh; do ln -sf "$(realpath $f)" <tooling>/$(basename $f); done`; not `qa.config.example.json`) and write `qa.config.json` from `scripts/qa.config.example.json` there; `tracker.html`, `agents.txt`, `qa.config.json` and `plans/` stay real files. A script finds its config next to the path it was invoked by (the symlink), then in the cwd — never next to its own realpath — and `$QA_CONFIG` overrides. All of them read that file ( `$QA_SCRATCH` overrides its `scratch`). Run with `node <script>.mjs` or the `.sh` wrappers (bash). The tracker and repo locks are directory locks holding the owner's pid and a random token (created fully formed by an atomic rename). A lock whose owner is dead or whose mtime is older than its limit is taken over under a short takeover mutex by renaming it aside (never `rm` on a lock someone else may have just re-made); `release` deletes a lock only while its token is still ours; released on exit, SIGINT and SIGTERM. The repo lock's limit is `3 × gateTimeoutMs + 10 min` and its holder renews the mtime every 30 s, so a merge that is slow but alive is never taken over.

| Script | Does |
|---|---|
| `st.mjs <status\|-> [--verify t\|+t] [--item-note t\|+t] [--commit sha] [--bucket b] [--ws W] [--by agentId] [--residual text] [--resolve-residual n accept\|fix] [--force] ID…` | Set status and fields. `--verify` is the verifier-evidence field; `--item-note` is the item's own note (`--note` is an error — it used to silently mean `--verify`). A leading `+` appends with ` \| `. Validates enums and status moves (`open → verified`, `deferred → verified` … need `--force`); unknown IDs or flags write nothing; `verified` needs commit + verify, every sha an ancestor of main, `--by <verifier agentId>` (not a fixer of the item) and no unresolved residual, unless `--force`; on a verified item `--commit` only adds. `--residual "text"` records a residual (one item); `--resolve-residual <n> accept\|fix` records the user's answer (the orchestrator runs it after the gate). |
| `st.mjs legacy` | Marks every `verified` item with no commit `legacy: true` (verified before shas were recorded) instead of backfilling; backs the page up to `tracker.html.pre-legacy.<time>`, under the tracker lock; idempotent. |
| `st.mjs pass <cycle> <units\|all> <B/M/m> [--platforms a,b] [--sha s]` | Record a test pass: units run (`all` = every unit in `D.units` now), platforms, the sha of main tested (default: main now; must be on main) and the count of new findings per severity. Unknown units write nothing. |
| `st.mjs - --triage known\|next ID…` | Sort a `later` item: ship as a known issue, or move to the next release (refused on `now` items). |
| `done.mjs [--json]` | The definition of done (SKILL.md): checks the seven criteria, prints the QA CYCLE STATUS block as markdown (or JSON), stores it as `D.done` for the page banner. Never runs a gate: criterion 5 trusts `D.gate`. Config: `platforms` (criterion 4 needs a pass on each), `maxCycles` (default 3), `cycle`. |
| `boundary.mjs` | Cycle-boundary check: lists the item ids in the project's `.claude/rules/*.md` (`rules` in config, default `<repo>/.claude/rules`) and the handoff memory file(s) (`handoffMemory`, array of paths) with tracker status; flags merged, verified and unknown ones. Read-only. |
| `st.mjs show ID…` | Read-only: `id \| status \| commit [\| by X] [\| residuals: n open / m]` per item. |
| `add.mjs ID sev "title" "where" "note" [later] [--now] [--ws W] [--unit N]` | Add an item (refuses duplicates; `ws` defaults to `defaultWs`, else the last item's). Bucket from severity: B/M → `now`; `m` → `later` (status `deferred`) unless `--now`; the 6th argument `later` parks any severity. |
| `merge.sh <branch> <IDs…> [--partial] [--force]` | Land a fixer branch on main and gate it. **Run in the background.** Refuses while `agents.txt` shows a `running` verifier or tester (`--force` overrides). Checks the gate commands exist, takes the repo lock, writes `merge.journal.json` (a dead run's journal makes the next run stop and print the recovery command; `merge.sh --clear-journal` after you restored main), asserts the repo is on `main` with a clean tracked tree (untracked files ignored); fast-forwards, else cherry-picks `merge-base..branch`; runs `commands.test`, `lint`, `build`, each under `gateTimeoutMs` (default 20 min). **Fails closed:** any failure, conflict, timeout, interrupt or unexpected error → `git reset --keep <pre-merge sha>`, nothing marked, exit 1; if `--keep` refuses it exits 2 and leaves the repo for a human (never forced). Success → items become `fixed` with the merged short shas ADDED to `commit`, and `D.gate` records the gated sha; the gate runs in its own process group, killed by a watchdog if merge.sh is SIGKILLed; `--partial` keeps them at `fixing` (a PARTIAL fix is not fixed). The gate is a full-suite run: medium load, not while a verifier runs a browser suite. No skip flag. |
| `mkbox.sh <ID> <port> [--force]` | Verifier/tester sandbox at `<scratch>/<sandboxDir>/<ID>`. Takes the repo lock first, then refuses to rebuild a sandbox ANY process has its cwd in (unless `--force`), then: `git archive <resolved main sha>` (the commit, never the working tree) + `sandboxCopy` caches + `sandboxLinks` symlinks (default `node_modules`) + test-only env file (`sandboxEnvFile`, default `.env`) from `sandboxEnv` + `commands.build` run inside; writes `SANDBOX_SHA` last. Order: merge → build → sandbox. |
| `reap.sh <ID\|branch\|agentId>` | Remove a finished item's worktree (and its scratch symlinks) and delete its branches. Refuses anything not fully merged into main (cherry-picked commits count as merged), locked, dirty or in use (a process has its cwd there). |
| `reap.sh --all-merged [--yes] [--skip a,b]` | Bulk form over every worktree and branch whose commits are all on main by patch-id. Dry run by default (`SAFE`/`SKIP <reason>` per entry); `--yes` reaps the SAFE ones. Skips locked, in-use, tracked-change and untracked-file worktrees, anything belonging to a `running` `agents.txt` row (agent id, its items' lowercased branches, names in its note), `--skip` names, a bare branch sitting exactly on main, **a branch with no commit of its own beyond main (a fresh agent worktree; `--include-empty` reaps it)** and **anything touched in the last 30 minutes (`--include-recent`, with `--yes` in bulk mode)**. The main checkout is excluded by realpath. Gitignored leftovers (and the `sandboxLinks` symlinks) go with the worktree. |
| `agents.mjs add\|set\|queue\|ls` | Maintain `agents.txt` (below); `add` validates role (`planner\|fixer\|verifier\|tester\|mapper\|reviewer\|other`) and model (`opus\|sonnet\|haiku\|fable\|?`). A `\|` or newline in any field is rejected (nothing written), not rewritten. |
| `stale.mjs <plan.md> [--rev N] [--allow-partial]` | The fixer's stale-plan check. Parses the plan's `BASE main <sha> [+ assumes <ITEM> merged]` (the last REVISION block must carry its own BASE, which may continue over indented or `+` lines; `--rev N` picks one), parses every id after `assumes` (split on `and`, commas, `+`), requires each to be `fixed`/`verified` with tracker shas that are ancestors of main (a `fixing` partial only with `--allow-partial`), and prints the diff stat from the earliest assumed sha's parent (or BASE) to main, limited to the files the plan's APPROACH names, plus what landed on top of each assumed item. Exit 2 with `PLAN GAP — stale: …` when an assumption fails or can't be read (no BASE line in the last block, an `assumes` that parses to nothing, a tracker id on the BASE line that isn't an assumed item). |
| `sweep.mjs` | Read-only resource sweep: TCP listeners in `sweepPorts` with pid, cwd and whether a `running` agent owns them. Stops nothing. |
| `mkrules.mjs` | Generate `FIXRULES.md` / `VERIFYRULES.md` from the templates and `qa.config.json`; keeps a differing old file once as `.bak`. Run it from the skill dir after editing the config or a template. |

Config keys beyond the example's basics: `sweepPorts` (port ranges `sweep.mjs` lists), `sandboxLinks` / `sandboxEnvFile` (what `mkbox` links and where it writes the env; `reap` ignores and removes the same links), `gateSummary` (regex of the gate-output lines `merge.sh` echoes after a pass; e.g. `^ℹ (pass|fail)` for node:test), `gateTimeoutMs`. `prod.rule` is free text for the generated rules: say where the production default can come from (the global environment, a shell outside the agent session) and what overrides it for the session, and always require an explicit `--server`/URL on the command line.

### `agents.txt`

One row per agent, `#` lines are comments: `id | role | model | items | state | started | ended | note`, `state` = `running|done|failed|stopped`. `agents.mjs add <agentId> <role> <model> <items> [--note t]` upserts a row as `running` (resuming an agent = add again; `started` is kept; an existing row's role can't change — use a new id; adding a `fixer` moves its `open`/`failed` items to `fixing`). Every write holds `agents.txt.lock`. `agents.mjs restart [--note t]` marks every `running` row `stopped` (the resume step: subagents never survive a session restart); `agents.mjs stale [hours]` only lists old `running` rows; `agents.mjs set <agentId> done|failed|stopped [--note +text]` stamps `ended`; `agents.mjs queue "text"` rewrites the single `# QUEUE:` line; `agents.mjs ls [state]`. Put sandbox, port and device IDs in `note` — the resource sweep keeps only what a `running` row owns.

Shell note (zsh): a command stored in a variable isn't word-split — use a function, not `A="node add.mjs"`.
