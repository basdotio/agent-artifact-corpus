# 表格与渲染完整性核验

普通论文和扫描书默认 `--table-format auto`：CLI 支持时采用 HTML 表格，保留 `rowspan/colspan`。`--table-format markdown` 显式使用原网格渲染；`html` 在 CLI 不支持时明确失败。旧 CLI 的 auto 回退会留下警告。其他 CLI 参数与旧报告字段保留。

## 区分三个阶段

- `table_processing_evidence.json`：同次转换中表格处理器前后的 HTML/文字。新字段为附加证据，不改变引擎数据；处理前未获得 HTML 时，不能据此判断识别阶段是否正确。
- `layout_evidence.json`：处理完成后的块文字、位置；表格增加可用的 `html` 字段。旧的纯文字证据仍可进行数值计数核对。
- `raw/`：Marker 实际渲染结果。原样保存，不把后续修订当作原始输出。

`quality_report.json` 分别记录表格结构、处理阶段数值减少、识别/处理证据与渲染输出差异，以及 wrapper 整理前后正文完整性。数字按出现次数比较，优先逐表核对；另一段正文或另一个表格里的同值不用于抵消遗漏。合并单元格范围、Markdown 列数、可用 HTML 与输出网格位置也参与检查。wrapper 添加图片路径和页标若改变正文，保留 raw 并拒绝发布最终 MD。

这些检查不能证明 OCR 识别正确。数值齐全、列数相同的表仍可能整体错列；跨页续表缺表头时尤其需要回查前页和原图。不要按模型编号、相邻行或统计常识自动移动数值、补值或修正公式下标。HTML 保留预测结构，不能修复错误预测。

脚注比较归一化自动链接、内联链接、HTML 标签、实体与常见 Markdown 转义，并比较完整注释而非前几个字符。真正缺文仍提示原图核验；跨页注释、图注中的特殊排版也可能需要人工判断。

## 核验状态与失败

`review_status` 绑定输入 SHA-256 与本次输出 SHA-256，文字、公式、表格和结构初始均为 `unreviewed`。印刷页码的 `verified` 只来自独立映射。存在 `reviewed_changes.json`、命令成功或检测器无报警，均不会自动把这些状态升为通过。

人工复核应另记源哈希、输出哈希、PDF 页、核验范围、修改前后及原图依据；重新转换或正文改变后重新核对相应记录。标题层级与重复列表编号目前只提示，不静默改写正文或参考文献。

`run_status.json` 与实时日志区分引擎初始化、缓存锁等待、识别/文档处理、表格处理、渲染和结果校验。锁超时、权限不足、引擎缺失有不同错误分类。等待持锁任务结束后可重试；锁文件存在不证明陈旧。此技能不删除其他任务的锁，也不终止其进程。运行阶段来自当前 CLI 的观测，多个阶段在轮询间很快结束时，完整顺序以 stderr 为准。
