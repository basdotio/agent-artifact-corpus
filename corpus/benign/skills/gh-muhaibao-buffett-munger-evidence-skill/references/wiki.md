# 可追溯主题 Wiki

Wiki 存在 `<资料库>/wiki/`，与原文库并列；使用普通 Markdown，不依赖特定笔记软件。它保存已完成的资料归纳、决策框架、思想变化及待解决分歧，不是原文，也不通过反复引用获得更高证据等级。

## 什么时候写

用户要求整理、更新知识库或反复研究的主题已经有足够证据时写入；普通一次性问答不自动把未验证的推演固化为人物思想。资料不足时记录待核问题，不补造结论。本次试点页数量与主题可查看 `index.md`，不代表完整覆盖两人的思想。

建立或更新主题页：先检索并打开相关原文和相邻上下文，再写中文归纳；证据不足以证明思想变化时保留不同语境，不能编造演化线。分别记录两个人物，跨人物比较引用各自证据。原文与旧归纳冲突时修订归纳，记录理由；新的表述不自动使旧材料失效。

## 页面类型

frontmatter 的 `page_type` 决定页面结构。缺省为 `concept`，最早的 6 个试点页没有这个字段，仍然有效。

| page_type | 用途 | 正文结构 |
|---|---|---|
| `concept` | 一个思想或原则 | 原文支持的判断 → 判断步骤（编辑整理）→ 条件 / 反例 / 未知 |
| `case` | 一个真实决策 | 情境 → 当时面对的问题 → 决定 → 当时给的理由 → 结果 → 事后评价 → 可迁移的判断与不可迁移之处 |
| `mistake` | 本人公开承认的错误 | 做了什么 → 错在哪里（按本人的说法）→ 他们从中得出的规则 → 这条规则的边界 |
| `declined` | 他们拒绝回答、说“不知道”或扔进“太难”的问题类型 | 典型问法 → 他们怎么回应 / 改写 → 改写后回答了什么 |
| `filter` | 他们明确陈述的筛选标准 | 标准原文的中文归纳 → 出现的年份与变化 → 如何按顺序使用 |
| `pattern` | 跨案例的规律 | 明确标为编辑归纳，逐项链接到 case / mistake 页的证据 |

案例页的“结果”和“事后评价”必须来自本人后来的材料或可核实的公司事实，不用后见之明替他们评价。可迁移部分写成条件句（“当……时，他们会先看……”），不能写成固定算法。

## 页面内容

每页应有：主题与人物、原文支持的判断、可复用的判断步骤、条件／反例／未知、原文出处与可读定位、相关主题、复核日期。判断步骤属于编辑整理，明确标记，不装成本人给出的固定算法。只录必要短引，主要用自己的中文说明原意。

证据条目不要手抄哈希。先打开并读过要引用的段落，再用 `wiki.py evidence` 生成条目，删掉 `_readable` 辅助字段后粘贴进 frontmatter：

```sh
"$PY" "$SKILL/scripts/wiki.py" --library "$LIB" evidence '<chunk_id_1>' '<chunk_id_2>'
```

正文每项重要判断跟随 `[E1]` 这样的证据标签；标签绑定到页头的原始证据。文末提供人物、材料名、年份、章节和链接。页头的内部定位字段服务核验，最终回答仍遵循可读引用规则，不把这些编号堆给读者。

JSON frontmatter（JSON 也是合法 YAML）可由标准库解析，无需额外 Markdown 依赖：

```text
---
{
  "kind": "synthesis",
  "page_type": "case",
  "title": "真实主题",
  "subjects": ["Warren Buffett"],
  "reviewed_on": "YYYY-MM-DD",
  "summary": "本页覆盖的主题与条件，供检索导航",
  "keywords": ["中文主题词", "English retrieval terms"],
  "evidence": [{
    "label": "E1",
    "chunk_id": "从实际检索取得",
    "raw_sha256": "从实际记录取得",
    "text_sha256": "对该chunk的完整text原始UTF-8文本计算SHA256",
    "metadata_sha256": "对该文档数据库metadata原始UTF-8文本计算SHA256",
    "speaker": "使用该chunk的真实speaker；未分配用null"
  }]
}
---
```

不要照抄占位符生成页面。读到引用才能写下判断，来源链接完整不等于支持关系已验证。页头引用不得使用 Wiki 页面、旧生成答案或模型记忆冒充原始证据。

## 更新和复核

- 兼容说明：本库 Wiki 只由本技能维护。`kind` 保持 `synthesis`、`page_type` 作为附加字段，是为了和旧版校验格式兼容，便于将来比对或迁移。
- `wiki.py check` 检查引用是否存在、原件／提取正文／元数据是否改变、发言人是否一致，以及正文标签是否绑定。OCR 文本修订即使不改变原件，也需复核归纳。这是机械校验，不能判断语义是否忠实。
- 校验失败页面标为待复核；重新打开新旧资料比较并修订，不能只更新SHA消除告警。
- 有实质修改时更新 `reviewed_on`，在 `log.md` 记录新增证据和改动理由；`index.md` 保持导航准确。
- 模型使用 Wiki 时仍回读当前问题需要的原文，并定向查反例；多页引用同一原文不增加独立证据数量。
- 外部当代事实与人物生前观点分开。新情境推演可另存研究笔记，不加入已证实人物主张。

Wiki 搜索返回的是主题导航，不是最终证据排序。相似度无校准，不把最相似页面理解为一定相关。
