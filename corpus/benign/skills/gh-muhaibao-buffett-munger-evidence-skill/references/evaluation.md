# 检索与回答评估

不要以资料数、向量数、相似度或风格分数宣称人物还原准确率。分别评估检索、证据归属、答案推演和表达。

## 用真实年会问答做盲测（衡量“像不像”的主方法）

1994–2024 年的年会文字稿里，有上千个“有人提问 → 两人当场回答”的真实记录。从中留出一部分问题，让系统在**看不到那场会议、也看不到之后任何材料**的条件下作答，再和当年的真实回答比较。这是目前唯一有真实基准的“思考方式”评估。

```sh
"$PY" "$SKILL/scripts/qa.py" --library "$LIB" status
"$PY" "$SKILL/scripts/evaluate.py" sample --library "$LIB" --out "$LIB/eval/<批次名>" --n 24 --seed <新种子> \
  --exclude-batch "$LIB/eval/pilot-2026-10-09/questions.jsonl"
# 只读 questions.jsonl，逐题按 skill 作答，检索时套用该题的 exclusions：
#   retrieve.py / qa.py 加 --exclude-document <document_id> --year-to <year-1>
# 作答写入 answers.jsonl：{"id", "buffett", "munger", "basket": "yes|no|too-hard|not-applicable"}
"$PY" "$SKILL/scripts/evaluate.py" score --holdout "$LIB/eval/<批次名>/holdout.jsonl" \
  --answers "$LIB/eval/<批次名>/answers.jsonl" --out "$LIB/eval/<批次名>/report"
# 读 report/judging-sheet.md，逐题判分写入 judgments.jsonl，然后：
"$PY" "$SKILL/scripts/evaluate.py" summarize --judgments "$LIB/eval/<批次名>/judgments.jsonl"
```

- **抽样**：固定种子，按年代分层；约四成选芒格有实质发言（≥40 词）的题；每场会议最多两题；排除程序性环节和过短的问题。`questions.jsonl` 不含 CNBC 小节标题，因为标题常常直接概括了答案。
- **隔离**：作答时排除该场会议文档，并只用该年之前的材料（`--year-to` 为会议年份减一）。作答者在写完 `answers.jsonl` 之前不能打开 `holdout.jsonl`。
- **机械指标**（`score` 自动计算）：两人是否都发言、与真实情况是否一致；篇幅比（中文按约 1.6 字折 1 个英文词）；芒格在真实回答中简短时，系统是否也简短；是否出现拒答或“太难”标记。
- **判分维度**（由人或独立模型按表判，写入 `judgments.jsonl`）：
  - `direction`：结论方向，取 agree / partial / disagree / not-comparable；
  - `core_reason`：核心理由，取 same / partial / different；
  - `decline_behaviour`：是否同样拒答、改写或说“太难”，取 match / mismatch / n/a；
  - `fabrication`：有没有编造的事实、引文或经历，取 none / minor / major。
- **已知偏差，报告时要写明**：底层模型在预训练中可能读过著名问答，造成“记忆泄漏”；同一模型既作答又判分会偏宽。可以换一个模型判分，或者人工抽查判分结果。题数少时只报告计数，不报告百分比的小数位。
- **对比**：评估改动时，用同一批题比较新旧协议，不能换题。

### 试点结果（2026-10-09，`<LIB>/eval/pilot-2026-10-09/`）

抽样 24 题，按固定规则作答其中的偶数号 12 题（不挑题）。作答和判分都由同一个模型（Claude Opus 5.5）完成，不是独立评审；该模型可能在预训练中见过部分原答。结果只作方向参考：

| 指标 | 结果 |
|---|---|
| 两人是否发言与真实一致 | 11 / 12 |
| 结论方向 | 一致 4、部分一致 7、相反 1 |
| 核心理由 | 相同 2、部分 7、不同 3 |
| 拒答 / 改写行为 | 一致 1、不一致 3、不适用 8 |
| 编造 | 无 9、轻微 3 |
| 篇幅（系统 / 真实，中位数） | 巴菲特 0.24，芒格 0.43 |

暴露的问题及已做的修订（见 [cognition.md](cognition.md)）：

- 巴菲特回答太短、缺少具体故事 → 默认篇幅改为 400–900 字，并要求必须有一个取自材料的故事。
- 对高估值默认看空，漏掉“利率如引力”这一原则 → 估值类问题必须先做经济分析。
- 拒绝评价熟悉的经理人（真实回答是明确称赞），却直接回答了巴菲特刻意回避的热点问题 → 第一步表格增加这两类。
- 芒格的短回答写成了摘要，而真实回答常是自嘲或玩笑；两人在 2001 年护城河问题上的真实分歧被抹平 → 已补充表达规则。
- 资料缺口：巴菲特关于政治献金的《纽约时报》评论文章未入库，导致竞选经费题只能降级推演。

这一批题已经用于开发，不能再当留出集。下一轮用新种子抽样，并在 `sample` 之后排除这 24 个问答单元。

## 可复跑的小样本

保持相同资料快照、问题、人物／时期过滤和最终候选数，对比：现有关键词检索、改进关键词检索、混合检索、混合＋重排。Wiki 单独评估导航作用，不能把 Wiki 中存好的结论当成原文召回成功。

问题覆盖：英文原话、中文同义问法、专名和年份、跨人物混淆、未分配发言人、前提错误、思想例外、跨年代比较、证据缺失、新情境推演。不要只选含已知术语的简单题。

每道检索题先保存相关原文的位置、理由及必要上下文。相关证据可以有多份；新发现的有效命中可以经复核补入答案集，但不能静默改动基准来美化分数。分开用于调参与保留测试的问题；少量开发题通过不代表独立泛化验证。

记录：目标证据是否进入前K、首次相关命中位置、人物与时间过滤是否正确、上下文能否还原、耗时和实际模式。答案集不完备时称“指定证据命中率”，不要称全库召回率。

## 生成答案评估

同一底层模型、相同资料权限和合理工具预算，比较原版与新版。按主张检查：

- 引用是否支持相邻论点，而非只有相同关键词。
- 是否把提问者、继任管理层或编者观点归给本人。
- 是否保留适用条件、例外与思想时期。
- 是否标清原话、归纳、推演，以及证据不足。
- 是否分别回答两人并解释证据，避免模板化分歧或伪造金句。

如使用其他评审者，不给其预期胜者；保留原始问题、回答、证据及判分理由。口吻相似度单列，不能冲抵事实和归属错误。正常优化无需追求固定题数或任意通过率；发现实际失败后先修复原因，再复跑受影响项目。
