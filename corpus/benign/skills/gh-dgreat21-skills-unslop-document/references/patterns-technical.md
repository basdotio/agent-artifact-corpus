## 1. Транслитерированный жаргон и призраки из кода

Слово из английского, записанное кириллицей (промоушен ← promote, слаг ← slug, дефолт ← default, инстанс ← instance, деплой, мёрж), выглядит как нормальный технический термин и поэтому проскакивает. Проверяй его как любой ярлык: есть ли определение и один ли у него смысл во всём тексте или репозитории.

| Где встретилось | Что не так | Что сделали |
|---|---|---|
| инструкция: «проверка, что **промоушен** не откатывается» | Слово нигде не определено. В README описана только команда: «`promote` переносит изменения в основную ветку» | Ушли от слова к описанию: «что **изменения, перенесённые командой `promote`**, не откатываются» |
| README: `data/<**слаг**>/config.yaml` | Не определено, а в соседнем файле «слаг» означает имя пользователя | Привели к одному смыслу и дали определение при первом упоминании: «**Слаг — имя папки проекта в `data/`, например `shop-eu`**» |
| комментарии: «дефолт» | Общепринятый жаргон, одинаково во всех файлах | Не трогали: менять во всех файлах сразу или нигде |

Где искать определение и разнобой: по всему тексту, а для diff — по всему репозиторию (`grep` по слову и корню).

## 2. Кальки разработчиков

| Было | Стало |
|---|---|
| конфиг **живёт в** `config/local/` | конфиг **лежит в** `config/local/` |
| пока ветка **жива** | пока ветка **существует** |
| правка **уедет** в коммит | правка **попадёт** в коммит |
| переменная окружения **побеждает** значение из файла | см. раздел 6: здесь правило, а не слово |
| сервис **пишет** имя в заголовок | сервис **сохраняет** имя в заголовке |
| библиотека **адресует** проблему утечек | библиотека **решает** проблему утечек |

Признак: глагол движения или жизни про данные и файлы (живёт, уехало, прилетело, подтянулось) или прямой перевод (wins → побеждает, lives → живёт, address → адресует).

«Упал», «падает» про тест или сборку — устоявшийся жаргон, допустим.

## 3. Фразы-обрывки

| Было | Стало |
|---|---|
| **Для локальной разработки и ручных тестов.** Окружение задаёт… | **Стенд нужен для локальной разработки и ручных тестов.** Окружение задаёт… |
| **Способов запуска два, и это разные вещи:** | **Есть два разных способа запуска:** |

В таблицах, списках и комментариях к строкам кода обрывок нормален: «# один раз: свои URL и токен».

## 5. Что не трогаем

- Блоки кода, команды, вывод программ. Если вывод написан коряво, это находка для «Попутно»: править надо код.
- Идентификаторы в обратных кавычках: файлы, флаги, переменные, функции, ветки, номера задач.
- Названия разделов, на которые ссылаются другие файлы. Меняешь заголовок — проверь ссылки. Битая ссылка — находка для «Попутно».
- Устоявшийся жаргон команды, если он одинаков во всех файлах (дефолт, стенд, инстанс, упал). Меняй везде или нигде.

## 6. Метка «проверить» на правиле, а не на слове

Если фраза описывает правило (приоритет, условие, порядок, откуда берётся значение), метка называет само правило так, как оно работает сейчас. Иначе автор подтверждает слово, а не смысл.

| Было | Плохая метка | Хорошая метка |
|---|---|---|
| переменная окружения побеждает файл, а файл побеждает значения по умолчанию | «проверить: „побеждает“ — устоявшийся термин?» | «проверить: сейчас порядок такой — окружение → файл → значения по умолчанию» |

Итоговое «стало»: «Если значение задано в нескольких местах, берётся первое по порядку: переменная окружения, затем файл, затем значение по умолчанию».

То же, когда автор сам предлагает термин: проверь, не занято ли слово в тексте другим смыслом, и скажи об этом до замены.
