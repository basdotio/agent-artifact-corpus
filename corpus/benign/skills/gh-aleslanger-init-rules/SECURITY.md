# Security policy

## Supported version

Security fixes, when made, target the current `main` branch. Older tags and commits, including `v1.0.0`, are not maintained separately.

## Reporting a vulnerability

Use [GitHub's private vulnerability report form](https://github.com/aleslanger/init-rules/security/advisories/new) to report a suspected vulnerability. Please do not open a public issue or pull request containing exploit details, secrets, or private repository data.

Include a clear description, the affected behavior, steps to reproduce with non-sensitive data, and the possible impact. For this skill, issues such as unsafe commands, unintended writes, disclosure of repository secrets, or instructions that can be manipulated by untrusted repository content are especially relevant.

The maintainer will review reports through GitHub's advisory workflow. Fixes and disclosure will be coordinated there when appropriate; no fixed response or resolution time is promised.
