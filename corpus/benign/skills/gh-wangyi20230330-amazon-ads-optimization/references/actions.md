# 动作库与安全边界

## 一、动作分级

| 级别 | 动作 | 执行方式 |
|---|---|---|
| **只读** | 查活动/关键词/搜索词/广告位报表、算指标、生成诊断 | 直接执行，无需确认 |
| **低风险写** | 加否定词、暂停单个明确亏损词 | 说明依据后执行（用户可免确认授权） |
| **中风险写** | 改出价（±30% 内）、改广告位加价一档、加预算 ≤ 30% | **必须逐条确认** |
| **高风险写** | 建/删活动、改匹配方式、批量改 > 20% 对象、关整个活动、改预算 > 30% | **必须逐条确认 + 说明影响预估与回滚方案** |

**默认行为：只出方案不落盘。** 用户明确说「直接改」才进入写流程。

## 二、标准动作库

### 出价类
| 动作 | 触发 | 幅度 |
|---|---|---|
| 降价 | ACoS > 盈亏线，点击 ≥ 20 | -20%~-30% |
| 微调降价 | ACoS 在目标与盈亏线之间 | -10%~-15% |
| 提价 | ACoS ≤ 目标 × 0.8 且曝光受限 | +10%~+20% |
| 抢位置提价 | TOS 转化显著更优 | +25% 一档 |

### 否定类
| 动作 | 触发 |
|---|---|
| 否定精确 | 单个无关词，或需要做流量隔离（词已在别处出单） |
| 否定词组 | 一类无关词根（如竞品品牌、错误品类） |
| 不否定 | 强相关但 0 单 —— 是转化问题，不是匹配问题 |

### 结构类
| 动作 | 触发 |
|---|---|
| 建 Exact 活动/组 | 搜索词订单 ≥ 2 且 ACoS ≤ 目标 |
| **迁移出价起手** | 新建 Exact 的初始出价按**当前自动活动出价的 80%** 起步（独立实现给出的实操值，见 [verification.md](verification.md) V5；再用 `metrics.md` 的可接受 CPC 复核上限） |
| 原位置否定精确 | 完成迁移后必做 |
| 拆广告组 | 单组关键词 > 50 或主题混杂 |
| 收敛重复词 | 同一词出现在 3+ 活动 |

### 预算类
| 动作 | 触发 |
|---|---|
| 加预算 +20%~30% | 预算烧穿 + ACoS 达标 |
| 不加预算 | 预算烧穿 + ACoS 超标 → 先降价加否词 |
| 降预算 | 活动效率差且短期无法修复 |

### 状态类
| 动作 | 说明 |
|---|---|
| 暂停 | 用于止血；数据保留，可恢复 |
| 归档/删除 | 仅在确认无历史价值时；删除不可逆，需明确确认 |
| 不要频繁启停 | 反复开关会打断学习期 |

## 三、限速规则（防止把账号玩坏）

1. **单次批量变更 ≤ 该对象总量的 20%**（如 100 个词一次最多改 20 个）
2. **学习期内（新建或大改后 < 7 天）不做出价或结构变更**
3. **同一对象的两次出价调整间隔 ≥ 3 天**（等数据回稳）；**实操观察期为 3~5 天**（独立中文来源给出的调价观察窗口，与本条一致）
4. **广告位加价一次只动一档**，观察一个完整周期再动下一档
5. **大促前 14 天 / 大促当天不做结构性调整**
6. **库存 < 30 天销量时暂停加投类动作**

## 四、变更留痕与回滚

每次写操作前记录：

```
时间 / 对象（活动名+ID）/ 字段 / 改前值 / 改后值 / 依据 / 预期影响 / 回滚条件
```

回滚触发条件示例：
- 3 天后 ACoS 未改善且订单量下降 > 20% → 回滚出价
- 提预算后 3 天 CVR 未变 → 回滚预算
- 否定后曝光下降 > 40% → 检查是否误否

**没有改前值，就不要执行写操作。** 拿不到改前值的批量工具不要用。

## 五、执行前检查清单

- [ ] 目标明确（利润 / 排名 / 清库 / 冲量）
- [ ] 盈亏平衡 ACoS 与目标 ACoS 已算出
- [ ] **份额短板已定位**（有 SQP 时先跑第 0 层；若短板在转化环节，本轮不应调广告）
- [ ] 数据时间窗与币种已标注
- [ ] 不在学习期 / 不在大促 / 库存充足
- [ ] 变更清单已给用户看过，含改前值
- [ ] 批量变更比例 ≤ 20%
- [ ] 回滚条件已写明

## 六、数据接入（怎么拿到数）

见 [data-integration.md](data-integration.md)。要点：

- 优先用**本机已有的 Ads API 代理能力**（本机已装亚马逊广告 API 数据技能），不要抓卖家后台页面
- 只有汇总数时，明确告知只能做粗诊断，不产出精确出价数字
- 缺搜索词报告 → 无法做第 4 层诊断，直接说明
- 不要向用户回显内部 ID、代理地址、密钥

## 七、建议出价 vs 可承受 CPC 的缺口决策（吸收自上游 nexscope PPC 框架）

创建/调整活动时，亚马逊会给出**建议出价区间**。把它和本 Skill 算出的**可接受 CPC** 对比：

| 情况 | 处理 |
|---|---|
| 建议出价 **≤ 可接受 CPC** | 正常出价，按建议区间中低位起步 |
| 建议出价 **> 可接受 CPC，但差距 ≤ 30%** | 可小幅接受，用广告位/否定词优化 CVR 来补；一个周期后复核 |
| 建议出价 **> 可接受 CPC，差距 > 30%** | **必须做三选一，不能硬投**：<br>① 接受阶段性亏损（仅限新品冲排名，且要有预算上限与止损日期）<br>② 提价或降成本，把可接受 CPC 抬上来<br>③ 跳过该词，先投更便宜的长尾 |

**输出要求**：给出这个判断时必须同时说清「选哪个、为什么、止损条件是什么」。只报「建议出价高于你的上限」不算完成诊断。

## 八、通用浪费修饰词（否定词种子表）

建活动前预先否定这批低意图修饰词，可省掉大量前期浪费（吸收自上游，按本 Skill 口径整理）：

| 类型 | 词例 | 否定方式 |
|---|---|---|
| 免费/低价 | free, cheap, cheapest, budget, under $X | 否定词组 |
| 二手/维修 | used, refurbished, repair, replacement parts, broken | 否定词组 |
| 教程/资讯 | how to, tutorial, DIY, review, vs, reddit, youtube, wiki | 否定词组 |
| 错误品类 | 与本品共享词根但不同类（如 cutting board → cutting board oil / stand） | 否定词组 |
| 错误材质/规格 | 明确不匹配的材质、尺寸、型号 | 否定精确或词组 |
| 竞品品牌 | 竞品品牌词 | **谨慎**：是否否定取决于是否有意做竞品词截流 |

**注意**：否定词不是越多越好。误否会切断有效流量，尤其是「教程/资讯」类词在部分类目（如工具、配件）反而是高转化意图。**先小批量否定，观察曝光变化再决定是否扩大。**

## 九、扩词能力（免登录，已内置）

```bash
node scripts/ads_opt.mjs keywords --seed "portable blender" --site us
```

走亚马逊官方自动补全端点（`completion.amazon.com`），**免 Key、免登录**，支持 us/uk/de/fr/it/es/jp/ca/au/in/mx/br 十二个站点。

- 用途：扩词、验证词根、发现真实搜索表达方式
- **局限**：补全反映的是**搜索热度**，不是转化率；不能只凭补全词决定出价
- 含品牌词的补全都单独标出来，投竞品品牌词前先确认合规与预算容忍度

**实测情况（2026-09-21，本机网络）**：us / uk / de / ca 均正常返回 10 条；**jp（completion.amazon.co.jp）当前网络不可达**，脚本会给出明确提示而不是静默返回 0。
端点必须用**站点自己的域名**（如 completion.amazon.co.uk），用 completion.amazon.com 配其他站点 MID 会返回 0 条 —— 脚本已按站点域名+MID 配对，不要手动改成 .com。

## 十、诊断前的「数据够不够」与「看哪四类数据」（补自雨果网实战文）

### 数据量前置检查（不足就不要下结论）

- 「一天十几个点击、没有订单，**只能说明暂时没出单，还不足以下结论**」
- 复盘**至少拉 7 天**；遇**大促、断货、售价调整、优惠券到期、配送时效变化** → **拉长到 14 天**
- 阈值按**自己 ASIN 的历史转化率**推导，不照搬别人的数字；高客单/决策慢的产品周期更长

### 日常诊断固定看四类数据

| # | 数据 | 看什么 |
|---|---|---|
| 1 | **广告搜索词报告** | 实际匹配到哪些搜索词，及其点击、花费、订单、销售额 |
| 2 | **广告表现数据** | **分自动 / 广泛 / 词组 / 精准 / 商品投放分别看** —— 不要把所有流量混在一起看 |
| 3 | **业务报告** | **Sessions** 与 **Unit Session Percentage** —— 判断 ASIN 整体访问与转化变化（用于区分流量问题 vs Listing 问题） |
| 4 | **商品经营信息** | 售价、优惠券、评分、评论数、库存、配送日期、购物车展示位、变体情况 |

> 第 3 类是把"广告问题"和"Listing 问题"分开的关键 —— 只看广告报表永远分不清。
