# legal-bidding · 法律服务投标全流程

> **A nine-step workflow + two read-only scripts for Chinese law firms bidding on legal service tenders.**
> Covers 资格条件 / 评分办法 / 废标条款 / 报价 / 装订密封 / 述标 / 投后复盘.
>
> 一套给中国律师用的**法律服务招投标工作流**：拿到招标文件到投后复盘，九步走完。
> 配套两个只读脚本，一份招标文件进去，四份导航材料出来。

## 它解决什么问题

法律服务招投标的失败，绝大多数不是败在方案写得不好，而是**败在流程漏项**：

- 没细看资格条件，投完才发现 ★ 条款不满足
- 投标函里的投标有效期是上个项目的模板值，没改
- 报价表有一项忘了填，而招标文件明文写着"漏填即无效响应"
- 密封方式没按要求分册，形式评审直接不过

这些错误的共同点：**不是能力问题，是没人逐项打勾。**

这个仓库做的就是那张清单——把"该看的都看了、该打的勾都打了"变成一件有据可依的事。

**它不替你写标书。** 投标文件签的是律所的名字，任何一份对外提交的材料，最终都必须有人逐字看过。
脚本能替你找、替你算、替你想起来，**但不能替你签字**。


### 三条设计原则

**1. 不做静默失败。** 每一项都明确报「找到 / 未成章节（散见 N 行）/ 全文无此字眼」——
**报"没找到"不等于文件里没有，只等于脚本没认出它。** 给你一份假装成功的输出，比报错更坏。

**2. 抽到交叉引用不算数。** 抽到"详见投标人须知前附表"时不当答案用——那是路标，不是答案，
留着比空着更误导。

**3. 会自己认错文件。** 把一份**投标文件**（我方应答）当招标文件喂进去时，脚本会识别出来并告诉你：

```
> 文件性质判断：投标文件（我方编写的应答）（招标类标记 1 个／自称 20 处）
> ⚠️ 这看起来是投标文件，不是招标文件。
> 投标文件里不会有资格条件、评标办法、报价上限——那些在招标方发的文件里。
> 下面的「未抽到」是正常的，不是脚本坏了。
```

> ⚠️ **脚本的输出只作导航，不作依据。** 资格条件、评标办法、报价上限三项，必须回原文逐字核对。

## 九步流程

框架出处：毕宝胜、陈正刚、白静《法律服务投标"三篇九步法"》（北京德恒律师事务所），威科先行 2022-06-14 发布。
本仓库引用其九步结构，**框架归属德恒所**，内容按实务重写。

| 篇 | 步 | 做什么 | 产出物 |
|---|---|---|---|
| **知彼** | 1 熟悉文件、定位需求 | 读资质条件、废标条款、招标范围；估准备时间 | 《项目基本信息清单》＋投/不投的判断 |
| | 2 对照标准、锚定得分 | 把评分标准当靶心；模拟打分，标出基础分／差距分／胜负分 | 《评分标准梳理表》 |
| | 3 及时沟通、避免偏差 | 有歧义按程序要澄清；内部有分歧集体讨论 | 澄清函（必要时） |
| **解己** | 4 分工协作、重点突出 | 按模块拆解分派；资深把关法律意见，合伙人核定 | 《分工计划表》 |
| | 5 读者友好、换位思考 | 评委在短时间阅多份上百页文件——做成"读者友好型" | 《评分导读表》随文件附上 |
| | 6 逐项检查、交叉复核 | 清单式管理 ＋ 同事交叉复核 | 《投标文件自检表》完成 |
| **制胜** | 7 装订密封、准时响应 | 胶装不活页；签字盖章骑缝；报价函单独放；按开标时间倒推 | 密封完成的投标文件 |
| | 8 模拟演练、精准述标 | 准备 5 分钟与 15 分钟两版；顺手记同行报价 | 述标稿 |
| | 9 投后复盘、成长提升 | 不论中没中都复盘 | 《投标复盘表》 |

**三步里最容易省、也最不该省的：第 3、8、9 步。** 这三步不产生交付物，所以最常被跳过——
而它们恰恰是"下一次投得更好"的唯一来源。

### `references/01` —— 把 70% 变成取件

投标材料按"要不要重做"分两类：**常备件约 70%**（执业许可证、律师名册、完税证明、社保、业绩合同、
制度文件），**本次专有件约 30%**（服务方案、团队配置、报价、针对性承诺函）。

现在的做法是每次从零找一遍那 70%——翻上个项目的文件夹复制，日期没改、版本是旧的。
**这不是"投标能力"问题，是"文件管理"问题，而文件管理可以一次性做掉。**
该文件按更新频率把常备件分成五档（按次／按月／按季按年／事件驱动／制度类），
配目录结构、业绩索引台账字段、更新日历。

## 自动化的边界

本仓库的脚本**只读不写**：读招标文件、读你自己的存货，都不生成也不改写任何投标材料。

| 能做（脚本） | 不能做（必须人做） |
|---|---|
| 读招标文件，抽出资格条件、评分表、时间节点、废标条款 | **判断"我们够不够格"**——这要对人、对证件、对未来排期，脚本看不见 |
| 扫描常备件目录，报"哪件过期了 / 哪件快到期了" | **填写任何一份材料的内容**——措辞一个字错就是废标 |
| 按招标文件要求生成"本次要交哪些材料"的取件清单 | **决定报价**——那是商业判断，得由能担责的人定 |
| 核对命名规范、编号连续性 | **签字盖章**，以及判断盖章位置对不对 |
| 把已填好的文件归档、生成台账 | **读评标办法之外的东西**：招标文件里没写进评分表的要求，往往才是真要求 |

**这条界线不是技术限制，是责任限制。**
