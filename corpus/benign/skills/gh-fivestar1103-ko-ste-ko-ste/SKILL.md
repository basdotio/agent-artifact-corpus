# ko-ste

목표는 하나다. 한국어 독자가 글을 한 번 읽고 쓴 사람의 뜻대로 이해하게 한다. 짧게 만드는 것이 목표가 아니다. 특정 사람의 말투를 흉내 내는 것도 목표가 아니다.

이 스킬은 공개 자료를 바탕으로 만든 한국어 글쓰기 지침이다. 공인된 한국어 STE 표준이 아니다. ASD-STE100 규격을 번역한 것도 아니다. 근거와 한계는 references/에 있다.

## 언제 쓰고 언제 쓰지 않나

쓴다:
- 기존 한국어 글을 다듬을 때
- 한국어 기술 글, 답변, 문서를 직접 쓸 때
- 영어 기술 문서를 한국어로 옮길 때

자동으로 쓰지 않는다:
- 창작, 홍보 문구, 감정과 말투가 내용인 글
- 에이전트가 읽는 영어 프롬프트

코드, 로그, 명령어, 직접 인용, 표의 데이터, 법령 원문은 보존한다. 사용자가 오류 메시지 문구 자체를 다듬으라고 하면 그 문구는 편집 대상이다. 인용된 실제 오류 로그는 보존한다.

## 두 모드

모드를 사용자가 정하지 않으면 글의 성격으로 고른다. 한 문서 안에서도 성격이 다른 부분은 그 부분에 맞는 모드를 쓴다. 예를 들어 README의 설명 단락은 80% 모드, 설치 절차는 엄격 모드로 다듬는다.

- 엄격 모드: 절차, 지시, 오류 메시지, 안내문, 설정 설명. 잘못 읽으면 독자가 잘못 행동하는 글이다.
- 80% 모드: 대화 답변, 설명, 보고, 일감, README, PR 설명.

80% 모드는 규칙을 무작위로 20% 버린다는 뜻이 아니다. 의미 보존(MP)과 모호성(AM) 규칙은 두 모드에서 똑같이 지킨다. 80% 모드는 뜻이 통하는 자연스러운 설명을 과하게 고치지 않는다.

| 항목 | 엄격 | 80% |
|---|---|---|
| 지시문 | 한 문장에 동작 하나. 14어절을 넘으면 살핀다 | 동작 둘까지 |
| 설명문 길이 | 17어절을 넘으면 절 경계를 살핀다 | 17어절 초과와 다른 신호가 겹치거나 25어절을 넘으면 절 경계를 살핀다 |
| 연결어미로 이은 절 | 둘까지 | 셋까지 |
| 한 명사구의 '의' | 하나 | 둘 |
| 띄어 쓴 명사 연속 | 셋 (고정 용어는 하나로 센다) | 넷 |
| 같은 대상의 이름 | 고정 | 고정 |
| 같은 동작의 동사 | 고정 | 지시문만 고정 |
| 목록 B 표현 | 고친다. 01-rules.md의 '그대로 둘 때'에 해당하는 정상 쓰임은 둔다 | 고치지 않는다 |

다른 신호는 절 넷 이상, 문장 안의 주어 변경, 겹친 관형절, 기준을 넘은 '의'나 명사 연속이다.

이 수치는 공인 표준값이 아니라 검토를 시작할 작업 기준이다. 영어 STE의 단어 수를 어절 수로 옮긴 값도 아니다. 문서 분포는 독자의 이해도를 증명하지 않는다. 길이만으로 수정하지 않고, 나눌 때 뜻이 더 잘 읽히는지 확인한다. 보정 결과와 한계는 references/03-calibration.md에 있다.

## 의미 보존: 무엇보다 먼저

아래 규칙은 어느 모드에서나 지킨다. 다른 규칙과 부딪히면 이 규칙을 따른다.

- MP-1: 원문에 없는 사실, 원인, 빈도, 수치, 주어, 목적어, 다음 행동을 더하지 않는다.
- MP-2: 조건, 예외, '만', '까지', '일부', '등', '이상/이하' 같은 범위 표지를 빼지 않는다. 새 독자에게 필요 없어 보이는 사실('이번 PR에서는' 같은 출처·시점)도 본문에서 빼지 않는다. 빼는 편이 낫다고 보면 남겨 둔 채 '확인 필요'로 묻는다.
- MP-3: 확신 정도를 바꾸지 않는다. '실패했을 수 있다'를 '실패했다'로 올리지 않는다. 단정을 추측으로 낮추지도 않는다.
- MP-4: '해야 한다', '해도 된다', '할 수 있다', '하는 것이 좋다'를 서로 바꾸지 않는다.
- MP-5: 코드, 식별자, 경로, URL, 버전, 고유명사, 직접 인용, 수치와 단위는 글자 그대로 둔다.
- MP-6: 원문의 높임 수준과 문체를 유지한다.
- MP-7: 원문이 두 가지로 읽히면 하나를 고르지 않는다. 모호한 부분의 표현과 수식·접속 범위를 그대로 두고 '확인 필요'에 적는다. 덧붙임에서 알렸어도 본문에서 해석을 고르면 안 된다. 문장을 나누거나 합치는 것, 연결어미(-며, -고)를 바꾸는 것, 어순을 바꾸는 것도 범위를 바꾼다. 모호한 범위가 걸린 문장은 이런 변경을 하지 않는다. 그 범위에 영향을 주지 않는 다른 부분은 고칠 수 있다.
  - 예(설명용): '캐시는 메모리를, 큐는 디스크를 쓰며, 재시작하면 비워진다.' '비워진다'가 둘 다인지 큐만인지 정해지지 않는다. '…쓴다. 재시작하면 비워진다.'로 나누면 '둘 다'를 고른 것이 된다. 문장을 그대로 두고 확인 필요에 적는다.
- MP-8: 이미 잘 쓴 문장은 손대지 않는다. 바꾼 문장마다 규칙 ID를 댈 수 있어야 한다.
- MP-9: 내용이 부족한 글을 그럴듯한 말로 채우지 않는다.

문장을 줄이면 뜻이 달라질 때는 길이 규칙보다 의미 보존을 따른다.

## 핵심 규칙

규칙마다 근거, 예외, 검사 방법은 references/01-rules.md에 있다. 아래는 고칠 때 떠올릴 요약이다.

글의 구성(ST):
- ST-1 요지를 먼저 쓴다.
- ST-2 한 문단에는 한 주제만 둔다.
- ST-3 절차는 순서대로 번호를 붙인다. 조건과 경고는 동작 앞에 둔다.
- ST-4 원인과 결과, 시간의 순서를 지킨다.
- ST-5 조건이나 항목이 셋 이상이면 목록으로 푼다.

문장(SE):
- SE-1 한 문장에 한 내용을 담는다.
- SE-2 모드 기준 길이를 넘으면 절 경계에서 나눈다. 조건이 뒤의 여러 절에 걸리면 나눈 문장마다 조건을 이어받게 쓴다. 그럴 수 없으면 나누지 않는다. 조건이 뒤 절까지 걸리는지 확실하지 않으면 나누지 않고 MP-7을 따른다.
  - 예(설명용): '용량을 초과하면 업로드가 취소되며 임시 파일은 1시간 뒤 삭제됩니다.'를 '…취소됩니다. 임시 파일은 1시간 뒤 삭제됩니다.'로 나누면 삭제가 조건 없이 일어나는 일로 읽힌다. 나누려면 '용량을 초과하면 임시 파일은 1시간 뒤 삭제됩니다.'처럼 원래 조건을 그대로 이어받는다. '업로드가 취소되면'으로 바꿔 이으면 다른 이유로 취소된 경우까지 넓어진다.
- SE-3 문장 중간에 주어가 바뀌면 바뀐 주어를 밝힌다. 원문에 없는 주어는 만들지 않는다. 바뀌지 않는 주어의 생략은 그대로 둔다.
- SE-4 성분끼리 호응시킨다.
- SE-5 꾸밈말은 꾸밈받는 말 가까이 둔다.
- SE-6 대등하게 이을 때는 같은 문법 단위끼리 잇는다.
- SE-7 조사와 어미를 정확하게 쓴다.
- SE-8 문맥상 하나로만 읽히는 빠진 성분만 채운다.

꾸밈말(MO):
- MO-1 관형절을 겹쳐 쌓지 않는다.
- MO-2 '의'를 잇달아 쓰지 않는다.
- MO-3 명사를 이어 붙여 쌓지 않는다. 고정 용어와 영문·코드 이름은 세지 않는다.

모호성(AM):
- AM-1 부정이 미치는 범위를 분명히 한다. '모든 테스트가 통과하지 않았다'는 두 가지로 읽힌다.
- AM-2 '할 수 있다'가 능력, 허용, 가능성 중 무엇인지 확인한다. 문맥이 정하지 않으면 묻는다.
- AM-3 대상이 둘 이상이거나 멀리 있으면 지시어를 실제 명사로 바꾼다.
- AM-4 수식과 접속의 범위가 두 가지로 읽히는지 확인한다.

어휘(LX):
- LX-1 같은 대상은 같은 이름으로 부른다.
- LX-2 같은 동작은 같은 동사로 부른다(엄격 모드, 그리고 지시문).
- LX-3 동작을 명사로 굳히지 않는다('배포 수행이 필요합니다' → '배포가 필요합니다'). 의무의 강도는 그대로 둔다. 실제 진행 상태의 '진행', 실제로 건네는 '제공'은 그대로 둔다.
- LX-4 '~에 대한', '~를 통해', '~로 인해', '~할 경우'는 금지어가 아니다. 문맥에서 하는 역할을 본다. 범위나 경로를 나타내면 그대로 둔다.
- LX-5 어려운 한자어와 낯선 외래어는 같은 뜻의 쉬운 말로 바꾼다. 독자가 쓰는 기술 용어는 그대로 둔다.
- LX-6 약어는 처음 나올 때 푼다. 원문에 풀이가 없으면 지어내지 않는다.
- LX-7 뜻과 규범에 맞는 단어를 쓴다(일체/일절, 이중 피동).
- LX-8 영어 동사를 직역한 조합('결정을 만들다')은 문맥에서 같은 뜻의 자연스러운 짝('결정을 내리다')으로 바꾼다. 사전 용례는 참고 자료다. 검색 건수나 용례 부재만으로 번역투를 판정하지 않는다.

불필요한 표현(RD):
- RD-1 근거 없는 평가어를 더하지 않는다. 남의 글의 평가어는 저자의 주장이므로 함부로 지우지 않는다.
- RD-2 군말과 중복을 뺀다. 강도를 나타내는 '반드시'는 군말이 아니다.
- RD-3 정보가 없는 메타 담화를 줄인다. 다른 절을 가리키는 참조는 정보다.
- RD-4 상투적인 대비, 요약, 맺음말을 붙이지 않는다.

문체와 부호(FM):
- FM-1 한 글 안에서 높임 수준과 어미를 맞춘다.
- FM-2~FM-5는 이 스킬의 문체 선택이다. STE 규칙이 아니다. 직접 쓸 때만 적용하고, 남의 글에서는 바꾸지 않는다.
  - FM-2 굵게는 놓치면 안 되는 것에만 쓴다.
  - FM-3 연결어미 뒤 쉼표를 줄인다.
  - FM-4 줄표로 문장을 잇지 않는다.
  - FM-5 마크다운에서 범위 물결표가 취소선으로 바뀌는지 확인한다.

표현 목록:
- 목록 A(두 모드에서 고침): 뜻을 흐리거나 규범에 어긋나는 표현이다.
- 목록 B(엄격 모드에서만 고침): 뜻은 통하지만 길거나 딱딱한 표현이다.
- 두 목록은 references/01-rules.md 9절에 있다.

## 기존 글을 고칠 때

다음 순서로 처리한다.

1. 보존 목록을 만든다. 원문에서 지켜야 할 것을 먼저 뽑는다.
   - 사실, 조건과 예외, 숫자와 단위, 범위 표지
   - 확신 정도, 의무·허용의 강도
   - 코드와 식별자, 높임 수준
   - 두 가지로 읽히는 곳
   - 이 목록은 머릿속으로만 만들고 출력하지 않는다.
2. 글의 요지와 문단 순서를 본다. 요지가 뒤에 묻혔거나 한 문단에 주제가 둘이면 구성을 고친다. 인과나 시간 순서를 뒤집지 않는다.
3. 모드를 정한다. 성격이 다른 부분은 부분마다 모드를 정한다.
4. 규칙을 어긴 부분만 고친다. 위반이 없는 문장은 그대로 둔다.
5. 같은 유형의 사람이 고친 전후 쌍을 참고한다. references/04-native-pairs.md에서 관련 규칙 ID로 찾는다. 사용자 수정 쌍(U-)이 있으면 그것을 먼저 따른다. 제외 쌍(X-)은 본보기로 쓰지 않는다. 이 파일의 국립국어원 인용문은 출력에 옮겨 쓰지 않는다.
6. 원문과 대조한다. 1단계의 보존 목록이 결과에 모두 있는지, 원문에 없는 것이 생겼는지 확인한다. 특히 다음 두 가지를 본다.
   - 문장을 나눴다면, 원문에서 조건 아래 있던 절이 나눈 뒤에도 조건 아래 있는가.
   - '확인 필요'로 보낸 부분의 문장 경계, 연결어미, 어순, 꾸밈 범위가 원문과 같은가.
   셸을 쓸 수 있으면 `scripts/check.py --compare 원문 결과`를 돌린다. 이 도구의 결과는 참고용이다. 차이가 없다고 의미가 보존됐다는 뜻은 아니다.
7. 처음 읽는 독자가 되어 다시 읽는다. 주어, 호응, 지시어가 한 번에 읽히는지 확인한다.

원문이 이미 괜찮으면 원문을 그대로 돌려준다. 바꿀 것이 없다는 말을 덧붙이는 것은 괜찮다.

## 직접 쓸 때

사용자가 제공한 사실과 확인한 자료로 쓴다. 서비스 이름, 포트, 경로, 수치 등 필요한 정보가 없으면 지어내지 않는다. 일반적인 설명은 할 수 있지만 특정 환경에서 확인된 사실처럼 쓰지 않는다. 예시 값은 예시임을 밝힌다. 내보내기 전에 사실·조건·수치·강도와 독자가 할 행동을 점검한다. 비교할 원문이 없으므로 `--compare`는 쓰지 않는다.

이번 보정에서 Claude 출력은 공개 문서와 다르게 치우쳤다(references/03-calibration.md 5절). 작성 과정과 장르가 다르므로 이 결과를 모든 모델의 지침으로 일반화하지 않는다.

- 많았던 것: 굵은 글씨, 표, 목록, 맺음 제안('궁금한 점이 있으면'), 문장이 아닌 개조식 조각.
- 적었던 것: 번역투('~에 대한')와 평가어. 사람 글보다 적었다.
- 문장 길이: 사람 글보다 오히려 짧았다(중앙값 8어절, 사람 글 11어절).

직접 쓸 때 참고할 원칙은 다음과 같다.

- 문장을 더 짧게 자르지 않는다. 한 문장에 한 내용이 들어 있으면 충분하다.
- 산문으로 충분한 내용은 산문으로 쓴다. 목록과 표는 항목이 실제로 나란할 때만 쓴다.
- 굵은 글씨는 경고와 꼭 지킬 값에만 쓴다.
- 마지막 사실이나 다음 행동에서 끝낸다. 맺음 제안을 붙이지 않는다.

## 영어 원문을 한국어로 옮길 때

문장마다 직역한 뒤 다듬지 않는다.

1. 원문에서 사실, 조건, 숫자, 확신 정도, 의무의 강도를 먼저 뽑는다. 조동사는 문맥에서 뜻을 정한다. 'may'는 가능성이나 허용, 'can'은 능력·허용·가능성, 'should'는 권고나 예상일 수 있다. 뜻을 단어 하나로 확정하지 않는다.
2. 한국어 어순으로 새로 쓴다. 조건을 앞에, 서술어를 끝에 둔다.
3. have, make, pay, take 같은 동사의 직역을 피한다(LX-8).
4. 코드, 명령어, 식별자, 제품명은 번역하지 않는다.
5. 1단계 목록과 결과를 대조한다.

## 출력

기본으로 고친 글만 낸다. 다음은 붙이지 않는다.
- 모드 안내, 인사, 위반 개수, 변경 요약
- 도구를 쓰지 못했다는 보고

`check.py`를 못 돌렸으면 손으로 대조하고, 그 사실을 따로 알리지 않는다.

고칠 곳이 없으면 원문을 그대로 낸다. 필요하면 '고칠 곳이 없습니다.' 한 줄만 붙인다.

필요할 때만 고친 글 뒤에 다음을 덧붙인다.

```
그대로 둠: <줄이거나 바꾸면 의미가 달라지는 부분>. <이유>
확인 필요: <원문만으로 뜻을 정할 수 없는 부분>. <가능한 해석들>
```

'확인 필요'는 해석에 따라 독자의 행동이나 판단이 달라지는 곳에만 쓴다. 다음 순서로 고른다.
1. 의무와 허용
2. 범위와 대상
3. 수치의 기준

항목은 많아야 셋이다. 항목 하나는 두세 문장으로 끝낸다.

모든 문장을 의심하지 않는다. 문맥상 한 해석이 자연스럽고 다른 해석은 억지스러우면 묻지 않는다.

해당하는 것이 없으면 두 줄 모두 쓰지 않는다.

사용자가 전후 비교나 이유를 요청하면("뭘 고쳤어?", "이유도", "비교표") 다음 표를 낸다. 이유를 요청했다면 규칙 ID만 적지 말고 왜 바꿨는지 짧게 설명한다. 표 아래에 모드를 한 줄로 적는다.

```
| 규칙 | 원문 | 고친 글 | 이유 |
|---|---|---|---|
| LX-3 | 배포 수행이 필요합니다. | 배포가 필요합니다. | 불필요한 '수행'만 뺀다. 필요의 강도는 유지한다. |
```

## 사용자 수정 쌍 기록

사용자가 결과를 직접 고쳐 주면, 그 수정을 references/04-native-pairs.md의 U- 항목으로 기록할지 묻는다. 기록 조건은 다음과 같다.

- 사용자가 직접 쓴 문장만 기록한다. LLM이 다시 고친 문장은 기록하지 않는다.
- 회사 정보와 개인 정보는 기록하지 않는다.
