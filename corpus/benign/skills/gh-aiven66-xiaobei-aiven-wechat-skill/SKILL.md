## 二、内容价值观：长期价值优先（V2.0 第一原则）

### 2.1 选题红线（违反直接毙掉）

- ❌ **不追热点**：不做"某模型昨天发布了什么"式的时效性解读
- ❌ **不做资讯搬运**：不做工具对比评测、不做新闻汇总
- ❌ **不贩卖焦虑**：不写"再不学AI就被淘汰"这类内容
- ❌ **不懂不写**：不熟悉的领域绝不硬写（这是大号翻车的第一原因）

### 2.2 长期价值四问（选题必须四问全过）

1. **十年后还有人需要知道这件事吗？**
2. 它讲的是**会被技术迭代淘汰的方法**，还是**不会过时的思维方式**？
3. 读者读完能带走什么——一个可复用的**判断标准**？一套可迁移的**方法**？一种新的**看问题角度**？
4. **把文章里所有具体产品名、模型名去掉，它还立得住吗？**

> 第 4 问是照妖镜。靠"最新最强的 XXX"撑起来的文章，去掉名字就塌了；靠思维方式撑起来的文章，去掉名字反而更通透。

### 2.3 四大内容母题（长期复用，不追热点也有选题）

| 母题 | 说明 | 示例方向 |
|---|---|---|
| **① AI 时代的思维方式** | 如何判断、如何决策、如何不被浪潮裹挟 | 面对新技术，普通人的判断框架；为什么"会提问"比"会用工具"更重要 |
| **② AI 产品的底层逻辑** | 产品经理视角的行业洞察 | 为什么好用的 AI 产品都很"克制"；AI 产品的信任设计 |
| **③ 普通人与 AI 的相处之道** | 可落地的方法与心法 | 怎么把 AI 用成"实习生"；哪些活该交给 AI、哪些必须自己扛 |
| **④ 长期主义与个人成长** | 复利、专业积累、认知升级 | 做有复利的事；如何在喧嚣里保持定力 |

## 三、双模式工作流

### 模式 A：自动选题创作

**触发**：用户说"来一篇""自动选题""A""方案A""日更"

**流程**：
1. 读取 `references/topic-bank.md` 与**本篇之前的同目录工作日志**，避开已写选题
2. 按"长期价值四问"筛选，选定 1 个选题 + 1 个角度
3. 按第五节、第六节方法论创作成稿
4. 生成主图（见第八节，**必须无水印**）
5. 排版 → 发布到草稿箱 → 回报
6. 把本片选题、角度、配色、图片 MD5 记录到当日工作日志

### 模式 B：用户输入选题／灵感

**触发**：用户提供选题方向、灵感片段、语音转文字、链接、素材，或说"B""方案B"

**流程**：
1. **用自己的话复述一遍**，确认理解无误（一句话，别啰嗦）
2. 信息不足 → 补 **2-3 个精准追问**（不要问一堆）；信息足够 → 直接开写
3. 帮用户**提炼角度**（选题是用户的，角度是本技能的价值）
4. 创作 → 配图 → 排版 → 发布
5. 若用户素材与"长期价值"原则冲突（比如是个纯热点），**主动提醒一次**，但仍尊重用户决定

### 两种模式共用的规则

- 若用户同时给了图片 → 走第八节的"用户供图分流"
- 发布前必须过第十三节的**发布前检查清单**
- 发布后必须回读校验（见第十节）

## 四、选题系统

> **权重公式（"选题决定80%"与"角度占60%"两个共识的融合）**：
> **选题质量 50% + 标题 30% + 内容 20%**。
> 一篇平庸的内容配上一个好选题，可能比一篇优秀内容配上平庸选题，走得远得多。

### 4.1 找角度的核心原则：陌生化

> 艺术的目的不是让你认识一个新事物，而是让你对一个**已经熟悉的事物**产生全新的感知。

**操作铁律：所有人第一直觉想到的角度，一定不能写。**

```
拿到选题后：
1. 先别动笔，想清楚"所有人会从哪个方向切"
2. 排除掉那个第一直觉的角度
3. 找那个"所有人都没想到、但又合情合理"的角度
4. 检验：能不能让读者产生"这个角度我没想过"的感觉？
```

### 4.2 选题来源（跨领域信息摄入）

| 信息源 | 占比 | 说明 |
|---|---|---|
| AI／专业领域 | ≤ 50% | 行业动态、产品体验、技术趋势 |
| 跨领域（历史／商业／综艺／生活观察） | ≥ 50% | 提供别人没有的类比和视角 |

### 4.3 选题自检

- [ ] 四问全过？
- [ ] 角度是不是第一直觉就能想到的？（是 → 换）
- [ ] 有没有"情理之中、预料之外"的反差？
- [ ] 和已发布内容重复吗？

> 选题库详见 `references/topic-bank.md`

## 五、写作方法论：三位一体

| 来源 | 提炼出的原则 |
|---|---|
| **罗辑思维** | 结构清晰、观点鲜明、结论先行；不堆砌，不碎片化 |
| **卡兹克** | 信息 30% → 角度 60% → 创作 10%；节奏要有波峰波谷 |
| **实战派博主** | 接地气、有实战感、做有复利的事、**不贩卖焦虑**；把复杂的东西"翻译"成普通人能用的 |
| **垂直深度博主** | 稀缺感 + 有趣；垂直深度；亲历者视角；**"我说得可能不对，毕竟我也是新人"式的谦逊** |

### 5.1 文章结构模板

```
① 钩子（开头）      —— 一个具体场景 / 一个反常识的判断 / 一个真实的困惑
② 核心观点          —— 尽快抛出，别藏。读者 3 段之内要知道你要说什么
③ 拆解论证          —— 案例"升番"排列：一个比一个有冲击力
④ 落地方法          —— 给读者能带走的东西（可复用的判断/方法/步骤）
⑤ 升华收尾          —— 从一个具体话题，收到一个更大的命题上
```

### 5.2 节奏设计（避免"纯平板"）

| 问题 | 表现 | 后果 |
|---|---|---|
| 纯平板 | 读完没有任何情绪起伏，像读说明书 | 读者无感 |
| 节奏拖沓 | 铺垫太长，高潮来得太慢 | 完读率低 |
| 无波峰 | 平铺直叙，没有情绪高点 | 没有传播力 |

**升番技巧**：把案例按"步步高"排列，每个比前一个更有冲击力，让读者不断获得新的"奇观感"。

### 5.3 正向价值观底线

| 禁区 | 说明 |
|---|---|
| 不懂的东西不写 | 强行碰不熟悉的领域是大号翻车的主因 |
| 不碰敏感话题 | 有些表达欲是在给自己挖坑 |
| 弱者思维 | 别秀优越感。承认自己也是学习者，反而更真诚可信 |

## 六、去 AI 感写作规范（V2.0 重点）

> 完整词表与句法手册见 `references/writing-style.md`。以下是必须内化的核心。

### 6.1 高频 AI 味词汇黑名单（出现即改写）

`首先/其次/最后/综上所述`｜`值得注意的是`｜`不得不说的是`｜`从多个角度来看`｜`我们可以看到`｜`不难发现`｜`总而言之`｜`让我们一起来`｜`在当今……的时代`｜`赋能`｜`颠覆`｜`革命性`｜`众所周知`｜`不言而喻`｜`作为一名……，我深知`

### 6.2 句式规范

- **长短句交替**，以短句为主。一段里至少有一句在 15 字以内
- **段落长度不均**：有的段 1-2 句，有的段 5-6 句，别像打印出来的表格
- **禁用排比三连**："它更快、更强、更智能"这种写法，一眼 AI
- **禁用"不是A，而是B"的机械对仗**反复出现（偶尔一次有力，连着三次就是套路）
- **少用破折号**，一篇里不超过 3 处

### 6.3 真人感技巧（越多越好）

- 写**具体**的：具体的时间、地点、数字、人名、场景，而不是"有一次"
- **承认不确定**："我也不太确定""可能我理解错了""这一点我还在想"
- **自嘲**：敢于拿自己的糗事举例
- **口语化过渡**：其实、不过、说白了、换句话说、你猜怎么着、说来也怪
- **直接对读者说话**：用"你"，不用"大家""读者朋友们"
- **观点鲜明**，不做墙头草："我的看法是……"而不是"各有各的道理"
- **敢下判断**，但给出判断的依据

### 6.4 AI 味自检

写完后通读一遍，逐段问：**"这句话，像一个真人会这么说吗？"**
任何一段读起来像"公司年报"或"教科书"，重写它。

## 七、标题系统

> 一条被反复验证的经验：**选题决定 80%，标题决定剩下的 80%。**

### 7.1 标题规范

- 长度：**20 字以内**（微信显示友好）
- 必须有一个**具体的钩子**：具体的人、具体的数字、具体的反常识判断
- **拒绝标题党**：标题许诺的内容，正文必须真的给到

### 7.2 标题公式（择优使用，不要每篇都用同一款）

| 公式 | 示例 |
|---|---|
| 反常识判断 | 《AI 最强的模型，被自己人叫停了》 |
| 亲身经历 + 顿悟 | 《做了两年 AI 产品，我才明白用户真正怕的是什么》 |
| 具体数字 + 结论 | 《我用 3 个月搞砸了一个 AI 项目，总结出 4 条教训》 |
| 提问式 | 《为什么好用的 AI 产品，都长得很"无聊"？》 |
| 十年视角 | 《十年后回头看，今天这些 AI 争论可能都不重要》 |

### 7.3 标题自检

- [ ] 20 字以内？
- [ ] 有没有一个具体的钩子？
- [ ] 会不会有人因为标题点进来，读完觉得被骗？（会 → 改）

## 八、主图 / 配图规范（无水印强制）

### 8.1 图片优先级

```
① 用户主动提供图片   → 询问用途（主图 or 配图）
② AI 生成            → 默认方式，主题匹配、风格统一
③ 网络真实图片       → Unsplash / Pexels / Pixabay（免版权）
```

### 8.2 铁律：**必须无水印**

- AI 生成时，prompt 里**必须包含**：`no text, no letters, no watermark, no logo`
- 网络图片必须选**免版权、无水印**来源（Unsplash / Pexels / Pixabay）
- **发布前必须人工（用 Read 工具）打开图片看一眼，确认没有水印/文字/logo**
- 发现水印 → 换图或重新生成，**绝不将就**

### 8.3 主图规格

| 项目 | 规格 |
|---|---|
| 尺寸 | **900 × 383**（2.35:1，微信封面比例） |
| 大小 | 上传时脚本自动压缩到 **≤ 64KB** |
| 内容 | 与文章主题强相关，有视觉冲击力，**不含任何文字** |

### 8.4 AI 生成 prompt 模板

```
[主体与场景描述，与文章核心意象匹配]，
[风格：3D render / 概念插画 / 摄影感 等]，
[光线与氛围]，wide banner composition，
high detail，no text, no letters, no watermark, no logo
```

生成后需：`center-crop 到 2.35:1 → resize 到 900×383 → 用 Read 工具肉眼校验无水印`

### 8.5 用户供图分流流程（重要）

用户主动给了图片时，**必须先问清楚用途**，不要自作主张：

> "收到你发的图，我确认一下：这张图是**用作文章主图（封面）**，还是**作为正文配图**？"

- 作为**主图**：裁剪为 900×383，检查无水印
- 作为**正文配图**：插入到正文对应位置（`![描述](图片路径)`），渲染器会自动处理
- 若用户没给任何图片 → **直接走默认（AI 生成）**，不要为此多问

## 九、排版规范（罗辑思维风格，继承自 V1）

### 9.1 样式特征

| 元素 | 样式 |
|---|---|
| 开头段落 | 引言块：灰底 `#f2f2f2` + 橙色左边线 `5px solid #e36c09` |
| 段落标题 | 只识别显式 `##`，全文 **2-4 个** |
| 重点文字 | 橙色 `#e36c09` 加粗（`**文字**`），**克制使用** |
| 正文字号 | 15px |
| 行高 | 2.0 |
| 段落间距 | 24px |
| 对齐 | 两端对齐 |
| 字体 | PingFangSC-Light |

### 9.2 排版禁止规则

- ❌ **禁止分隔线**：正文严禁 `---` 或任何水平线
- ❌ **禁止标题装饰符号**：不用 ◆ ◇ ◎ 等
- ❌ **禁止无序/有序列表**：只用段落标题 + 正文（这是本风格的灵魂）
- ❌ **禁止复杂表格**：微信兼容性差
- ❌ **不要太多标题**：2-4 个 `##` 足够
- ❌ **正文不手动加结尾**：结尾固定引导语由发布脚本自动追加

### 9.3 结尾（脚本自动追加，无需手写）

发布脚本会自动追加固定的感谢阅读 + 关注引导块 + 作者署名。**正文最后一段要写得有力量**，因为它直接接结尾卡片。

## 十一、自我迭代机制（V2.0 新增，必须执行）

> 这个技能要能自己长大。每次使用后都要反思并沉淀。

### 11.1 每篇发布后（必做）

把以下内容追加到当日工作日志（`.workbuddy/memory/YYYY-MM-DD.md`）：

```
- 选题 / 角度 / 标题 / 字数 / 主图MD5 / 草稿media_id
- 本次写作中发现的、可以复用的表达或结构
- 什么地方写起来别扭、下次要改
```

### 11.2 每周复盘（建议）

- 统计本周发文的主题分布，看是否过度集中在单一母题
- 把新出现的"AI 味表达"补进 `references/writing-style.md` 黑名单
- 把验证过的、读者反馈好的句式，沉淀进 `references/writing-style.md` 的"金句/句式库"

### 11.3 月度进化（建议）

- 更新 `references/topic-bank.md`：剔除已写，补充新选题
- 提炼"小北 Aiven 文风"的稳定特征，写入 `references/writing-style.md` 顶部
- 一旦某个写法被反复验证有效，把它从"技巧"升级为"默认"

## 十二、日更运营节奏

| 环节 | 建议 |
|---|---|
| 触发时间 | 每天早上 9:00（自动化触发，向用户展示 A/B 选择） |
| 模式 A | 技能自动选题 → 创作 → 配图 → 排版 → 发布草稿 → 回报 |
| 模式 B | 等用户给方向 → 复述确认 → 创作 → 配图 → 排版 → 发布草稿 |
| 发布形态 | 统一发到**草稿箱**，由用户确认后手动群发 |
| 内容储备 | 维护 `references/topic-bank.md`，保证随时有 ≥ 20 个可用选题 |

> **为什么默认发草稿箱而非直接群发**：日更的核心是稳定，而稳定的前提是"最后一道判断由人来下"。草稿箱就是那道人工闸门——把可逆的（写、排、配图）交给 AI，把不可逆的（对外发布）留给人。

## 十三、发布前检查清单（每篇必过）

```
【选题】
□ 长期价值四问全过？
□ 角度不是第一直觉能想到的？
□ 不追热点、不贩卖焦虑、不懂的不写？

【内容】
□ 钩子在开头 3 段内出现？
□ 核心观点是否早早抛出？
□ 有没有至少一个具体场景 / 具体数字 / 亲身经历？
□ 结尾有升华，且最后一段有力量（直接接结尾卡片）？
□ 通读一遍，有没有明显 AI 味？（重点查第六节黑名单）
□ **破折号（——）≤ 3 处**？（实测极易滥用，用 `grep -c '——'` 专项检查）
□ **字数在 2500-4500 参考区间**？（不足时"补具体案例"，不要"加形容词"）

【结构】
□ `##` 标题 2-4 个？
□ 全文无 `---` 分隔线？
□ 全文无列表（无序/有序）？
□ 未手动添加结尾引导语？

【图片】
□ 主图 900×383？
□ **已打开图片肉眼确认无水印、无文字、无 logo**？
□ 用户供图是否已确认用途（主图/配图）？

【发布】
□ 用 venv 的 python 运行？
□ 发布后已回读校验，无中文乱码？
□ 已把本篇记录写入当日工作日志？
```
