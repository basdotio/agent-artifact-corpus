# 【小北Aiven】公众号创作技能 V2.0

> 把「选题 → 创作 → 配图 → 排版 → 发布 → 自我迭代」串成一条流水线的微信公众号创作系统。
> 它不只是一个排版工具，而是一套**完整的内容创作方法论 + 可执行的发布脚本**。

作者：[小北Aiven](https://github.com/Aiven66) · 一个懂点技术喜欢分享的 AI 产品经理
个人站点：https://aiven.coze.site/

---

## 一、这是什么

大多数"公众号排版工具"只解决了最后一步。这个技能解决的是从 0 到 1 的全过程，并且内置了一套**长期主义的内容价值观**：

- **不追热点**。写的是十年后还有人愿意翻出来读的东西。
- **去 AI 感**。内置 AI 味词汇/句式黑名单，写作时有意识地避开"公司年报腔"。
- **双模式**。既可以由 AI 自动选题，也可以由你给灵感、AI 来创作。
- **可自我迭代**。文风库、选题库、黑名单都是可迭代资产，越用越厚。

它是给 AI Agent（WorkBuddy / Claude Code 等）使用的 Skill；也可以直接当作一套**人类可读的内容创作 SOP** 来参考。

## 三、快速开始

### 第 1 步：安装技能

把它放进你的 Agent 技能目录。以 WorkBuddy 为例（默认用户级目录为 `~/.workbuddy/skills/`）：

```bash
git clone https://github.com/Aiven66/xiaobei-aiven-wechat-skill.git \
  ~/.workbuddy/skills/xiaobei-aiven-wechat-v2
```

> 其他 Agent（如 Claude Code）请放到它对应的 skills 目录下。技能目录名建议保持 `xiaobei-aiven-wechat-v2`，与 `SKILL.md` 里的 slug 一致。

### 第 2 步：配置微信凭证

发布脚本**不硬编码任何密钥**，按以下优先级读取：

```bash
# 方式一：环境变量（临时）
export WX_APPID="你的AppID"
export WX_SECRET="你的AppSecret"

# 方式二：配置文件（推荐，一次配置长期有效）
mkdir -p ~/.workbuddy
cat > ~/.workbuddy/.wx_config <<'EOF'
{"AppID": "你的AppID", "AppSecret": "你的AppSecret"}
EOF
```

> 前提：你的公众号需要是**服务号或已认证订阅号**，并已开通草稿箱接口权限。

### 第 3 步：安装依赖

发布脚本依赖 **Pillow**（用于封面裁剪压缩）。建议用独立虚拟环境：

```bash
python3 -m venv ~/.venv/wechat
~/.venv/wechat/bin/pip install Pillow
```

装好后，后面所有脚本都用 `~/.venv/wechat/bin/python` 运行。

## 四、怎么用：方案 A 与方案 B

这是本技能最核心的用法。**每次创作前，先选一种方案**——要么让 AI 自动选题，要么由你给方向。

### 方案 A：AI 自动选题创作

**适合场景**：你只想说一句"今天来一篇"，其余交给 AI。

**怎么触发**：对 Agent 说 `A`、`方案A`、`自动选题`、`来一篇`、`日更`。

**Agent 会做什么**：

1. 读取 `references/topic-bank.md`，避开已经写过的选题；
2. 按「长期价值四问」筛选，选出 1 个选题 + 1 个角度（角度必须避开第一直觉）；
3. 按写作规范创作成稿；
4. 生成主图（AI 生成，强制无水印）；
5. 排版 → 发布到公众号草稿箱 → 回读校验；
6. 把本篇记录写入当日工作日志与选题库。

### 方案 B：你给灵感，AI 来创作

**适合场景**：你脑子里已经有一个想写的东西，或者只有一句模糊的灵感。

**怎么触发**：直接说 `B`、`方案B`，然后跟一句你的想法。例如：

```
B 选题灵感：一篇文章讲清楚到底怎样转型做 AI 产品经理？
```

**Agent 会做什么**：

1. **先用一句话复述你的理解**，确认没跑偏；
2. 信息不够就补 2–3 个精准追问，够就直接开写；
3. 帮你**提炼角度**（选题是你的，角度是技能的价值）；
4. 创作 → 配图 → 排版 → 发布到草稿箱。

### 两种方案对比

| | 方案 A | 方案 B |
|---|---|---|
| 选题来源 | AI 从选题库自动选 | 你提供方向或灵感 |
| 需要你做什么 | 说一个"A" | 说"B" + 一句灵感 |
| 输出 | 完整文章 + 主图 + 草稿 | 完整文章 + 主图 + 草稿 |
| 适合 | 日更、省心 | 有明确想写的话题 |

### 关于配图

- 主图**默认由 AI 生成**，并在 prompt 中强制 `no text, no watermark, no logo`；发布前 Agent 会打开图片**肉眼校验无水印**。
- 如果你**主动发图片**给它，它会先问你："这张图是用作**主图（封面）**，还是**正文配图**？"
- 如果你**没给图**，就直接走默认，不会为此多问。

## 五、手动发布一篇文章

如果你想跳过 Agent、直接自己写 Markdown 再发布。先准备一个 Markdown 文件（用 `##` 做小标题，**不要用列表和分隔线**），然后：

```bash
~/.venv/wechat/bin/python scripts/publish.py \
  article.md \
  "文章标题（20字以内）" \
  "小北Aiven" \
  "/path/to/cover.png"      # 可省略，省略则用默认封面
```

脚本会自动完成：

```
渲染排版 → 追加结尾引导块 → 裁剪封面到 900×383 并压缩到 ≤64KB
→ 上传封面 → 创建草稿 → 回读校验（确认无中文乱码）
```

## 六、使用前需要改的地方（重要）

本技能是**个人化**的，仓库里有几处属于作者的配置，你需要按自己的情况替换：

| 位置 | 内容 | 说明 |
|---|---|---|
| `scripts/publish.py` → `DEFAULT_THUMB_MEDIA_ID` | 默认封面素材 ID | 这是作者账号的永久素材 ID，**请换成你自己的**（用微信素材接口上传一张图即可获取） |
| `scripts/publish.py` → `ENDING_HTML` | 结尾引导块 | 里面的公众号名、邮箱、话术，改成你自己的 |
| `scripts/publish.py` → `AUTHOR` | 作者署名 | 改成你的笔名 |
| `SKILL.md` → 第一节「账号与人设档案」 | 账号信息、作者经历 | 改成你自己的 |
| `references/publish-guide.md` | Python 路径示例 | 改成你本机的路径 |

> 如果你只想把本技能当**方法论**用（不用脚本发布），那 `references/` 下的写作手册和选题库可以直接读，无需任何配置。

## 七、核心设计

### 1. 长期价值四问（选题红线）

每个选题必须四问全过，否则直接毙掉：

1. 十年后还有人需要知道这件事吗？
2. 它讲的是会过时的**方法**，还是不会过时的**思维方式**？
3. 读者读完能带走什么：一个判断标准 / 一套方法 / 一种新角度？
4. **把文章里所有产品名、模型名去掉，它还立得住吗？**（照妖镜）

### 2. 四大内容母题（不追热点也有选题）

| 母题 | 说明 |
|---|---|
| ① AI 时代的思维方式 | 如何判断、如何决策、如何不被浪潮裹挟 |
| ② AI 产品的底层逻辑 | 产品经理视角的行业洞察 |
| ③ 普通人与 AI 的相处之道 | 可落地的方法与心法 |
| ④ 长期主义与个人成长 | 复利、专业积累、认知升级 |

### 3. 找角度的铁律：陌生化

> **所有人第一直觉想到的角度，一定不能写。**

拿到选题后，先想清楚"大家会从哪个方向切"，排除它，再找那个"所有人都没想到、但又合情合理"的角度。

### 4. 标题：选题决定 80%，标题决定剩下的 80%

标题控制在 **20 字以内**，必须有一个具体的钩子（具体的人、具体的数字、或一个反常识的判断）。拒绝标题党——**标题许诺的内容，正文必须真的给到。**

### 5. 排版规范（无列表、无分隔线）

- 只识别显式 `##` 标题，全文 **2–4 个**；
- **禁止**分隔线、**禁止**无序/有序列表、**禁止**复杂表格；
- 首段自动渲染为引言块（灰底 + 橙色左边线）；
- 重点用橙色加粗，克制使用。

> 为什么禁止列表？这是这套风格的灵魂——**用连贯的段落讲一个完整的意思，而不是把观点切成碎片。** 列表让人"扫"，段落让人"读"。

## 八、两条「实战踩坑」规则

这两条是实际写作中撞出来的、再沉淀回技能的硬规则，分享给同样在写公众号的人：

1. **破折号上限 3 处/篇。** 初稿极易滥用（实测一篇初稿用了 10 处），重读时必须专项检查（`grep -c '——'`）。多数场合用冒号、逗号或直接断句替代，效果更好。
2. **扩写靠"补案例"，不靠"加形容词"。** 字数不足时，正确做法是补一个具体场景（谁、什么时候、发生了什么、结果如何），而不是把一句话拆成三句。这是"深度优先、不注水"落到操作层面的含义。
