# 检查协议 · 完整规格

SKILL.md 是紧凑运行核心，覆盖默认运行所需的全部语义；本文件是完整规格与定义源，**默认运行不需要读**。按需加载：展开完整报告 / 成绩估计 → 第 8、10 节；复杂复查边界 → 第 11 节；可追溯性与外部事实细则 → 第 7 节。所有状态值与 SKILL.md 同一套原词。

## 1. Requirement Ledger 字段

| 字段 | 内容 |
|---|---|
| `id` | `R1`、`R2`… 按老师材料里的出现顺序编号 |
| `source` | 来自哪份材料的哪一处（brief §3 / rubric row 2 / 邮件 / 题目） |
| `quote` | 老师原句 |
| `requirement` | 拆到一个动作、一个对象后的一句话 |
| `parent criterion` | 若拆自 rubric row，写 row 名 |
| `deliverable` | 关联的必交物（没有就留空） |
| `verification` | 验证状态 |
| `status` | 要求状态 |

## 2. 要求状态

| 状态 | 定义 |
|---|---|
| `MET` | 有充分证据证明要求已完成 |
| `PARTIAL` | 有相关内容，但缺少要求中的一部分 |
| `MISSING` | 已确认提交物读取完整，且没有对应内容 |
| `CONTRADICTED` | 作业内容与要求明确冲突 |
| `UNVERIFIED` | 无法可靠读取、定位或判断 |
| `NEEDS CLARIFICATION` | 老师材料本身含糊或互相冲突 |
| `NOT APPLICABLE` | 经确认不适用于本次提交 |

## 3. 验证状态

| 验证状态 | 含义 |
|---|---|
| `VERIFIED` | 有工具输出、重算结果、可复核文件证据或可追溯外部来源 |
| `REVIEWED ONLY` | 已读取并分析，但没有独立验证 |
| `NOT VERIFIED` | 当前没有完成验证 |

按**单条 requirement / finding** 标验证状态。同一个 requirement 的覆盖与正确性可以分别记录验证状态。

## 4. Finding 来源

| 来源 | 含义 |
|---|---|
| `TEACHER REQUIREMENT` | 直接来自老师材料 |
| `RUBRIC` | 影响某个评分 criterion |
| `TECHNICAL CORRECTNESS` | 可验证的事实、数学、代码、数据问题 |
| `SUBMISSION INTEGRITY` | 文件缺失、损坏、跑不起来、读不了 |
| `GENERAL ADVICE` | 老师没要求、可能改善质量的建议 |

`GENERAL ADVICE`：不计入要求完成率，不用于推导成绩，单独不足以把总体状态推到 `NEEDS REVISION`。

## 5. 严重度与最低证据

| 严重度 | 判定 |
|---|---|
| 严重 | 必交物缺失、核心要求未完成、承重结论错误、主要功能失败 |
| 重要 | 要求部分完成、关键解释不足、明显影响某个 criterion |
| 小问题 | 局部清晰度、格式、表达、低影响修正 |
| 未验证 | 可能重要，但证据或工具不足 |

标成"严重"或"重要"的问题必须同时给齐：位置、作业中的证据、判断理由、影响的 requirement 或 rubric criterion、验证状态、修改方向。凑不齐就降级到"小问题"或归入"未验证"，不许硬标。

## 6. 去重

一个根因 = 一个主 finding，另附它波及的全部 requirement。同一个"缺少比较"在要求表、rubric 判断和详情里各出现一次，仍然只算一个问题。

## 7. 验证证据与可追溯性

- 联网得到的 `VERIFIED` 结论必须让用户能复核：优先附稳定 URL / DOI；环境使用引用卡片时附对应引用。
- **可追溯性收紧**：任何通过联网获得、并用于支撑 finding 的外部事实，无论验证状态是 `VERIFIED` 还是 `REVIEWED ONLY`，同一条 finding / 说明里都必须附可追溯 URL、DOI 或环境引用。给不出来源的外部事实不得当作 finding 的依据，只能作为待确认项。
- **外部事实必须带验证状态**：报告里出现的外部事实（来源是否存在、元数据是否正确、判例或事件内容等）都必须可归到某个验证状态。不得用"均存在""元数据正确"这类确定语气写未核验的外部事实。
- "公开检索未找到"只能证明本次检索没有定位到来源，不能单独证明"来源不存在"。
- 文件内部可直接重算、计数或定位的结论，可以用工具输出或明确的可复现步骤作为 `VERIFIED` 证据。
- 外部核验遵循最小披露：优先搜索公开题名、DOI、作者或非敏感事实；不得把学生姓名、学号、私密数据或整段未发表文本作为查询内容发送给第三方。若验证必须暴露敏感内容，先征得用户同意，否则保持 `NOT VERIFIED`。

## 8. 不确定项四问

每个 `UNVERIFIED` 或 `NEEDS CLARIFICATION` 都要在**检查逻辑里**答齐（默认短报告只压成一句，用户要求展开或完整报告时逐项写全）：

1. 什么还没确认？
2. 为什么确认不了？
3. 已经检查了什么？
4. 需要什么才能确认？

## 9. 总体状态

判定顺序与 READY 语义见 SKILL.md「总体状态闸门」，两者一致。补充解释：

- 这里的"会改变结论"指**会改变该 requirement 的状态或该 rubric criterion 的 band**，不是只看"物理上能不能上传"。
- 只有待确认 / 未验证项在**所有合理解释下都不会改变对应 requirement 状态或 rubric band** 时，才允许继续判 `NEEDS REVISION` / `READY TO SUBMIT`；报告里要说明为什么它不影响状态。
- `READY TO SUBMIT` 只表示：基于当前可读材料与明确标准，没有发现需要修改的严重/重要问题，且所有正式要求与计分 criterion 都已足够确定。它不保证老师最终成绩。

## 10. 成绩区间

只有同时满足以下六条才输出估计区间：

1. rubric 明确给出分值、权重或 performance band；
2. 所有计分 criterion 都能读取；
3. 每个 criterion 都有证据或已确认缺失；
4. 未验证部分不足以让相邻 band 改变结论；
5. 区间能从 criterion 判断一路推到总分；
6. 明确标注为估计，不是老师最终成绩。

缺任何一条：只给 readiness、要求状态和修改优先级，不给数字。

## 11. 复查状态细则

状态集与 ID 规则见 SKILL.md「同会话复查」。补充边界：

| 状态 | 含义 |
|---|---|
| 已解决 | 上一轮的证据缺口已补上，或问题已消失 |
| 部分解决 | 改了一部分，仍不满足要求 |
| 未解决 | 位置或内容基本没动 |
| 不再适用 | 作业结构变化后该问题已不存在，且不是被改好 |
| 新增 | 改动引入的新问题 |
| 回归 | 改动让原本满足的地方不再满足 |

- 既不硬合并，也不因同一 requirement 仍有问题就把旧 finding 降成"部分解决"。
- 复查展示规则：上一轮问题逐条给出复查状态，已解决项也要出现。默认短报告用“短问题标题 → 已解决 / 部分解决 / 未解决”等自然语言，不显示内部 finding ID；完整报告才显示 ID。已解决项不占“最该先改”的 1–3 项位置。

## 12. 用户可见统计与展示词

| 内部值 | 默认展示 |
|---|---|
| `READY TO SUBMIT` | 可以提交 |
| `NEEDS REVISION` | 建议修改后再提交 |
| `CHECK INCOMPLETE` | 还不能确认是否可以提交 |
| `MET` | 已完成 |
| `PARTIAL` | 部分完成 |
| `MISSING` | 缺失 |
| `CONTRADICTED` | 有冲突 |
| `UNVERIFIED` / `NEEDS CLARIFICATION` | 暂时无法确认 |
| `VERIFIED` | 已核实 |
| `REVIEWED ONLY` | 已检查，未独立核实 |
| `NOT VERIFIED` | 未核实 |
| `MATCH UNCERTAIN` | 暂时无法确认是不是同一个问题 |

- Ledger 拆出的原子项对用户统一显示为“检查项”；需要时写“老师主要求 X 项，拆成 Y 个检查项”。
- 默认不展示 `R4` / `R4-I1` 等内部 ID；完整报告或用户明确要求技术细节时再显示。
- 无法确认 / 待确认计数按独立根因计。

## 13. 展开报告格式

单条 finding 展开形态：

```text
R4-I1 · 严重

位置：Section 3，第 2–4 段
问题：分别描述了 A 和 B，没有形成比较
证据：……
为什么成立：老师用的是 compare；两段各自介绍不构成比较动作
影响：R4 / Rubric「Critical comparison」
验证状态：REVIEWED ONLY
修改方向：选 2–3 个共同维度，逐项对照 A 与 B，并说明差异意味着什么
```

完整报告 = 学生友好的结论摘要 + 验证状态统计 + 完整要求检查表 + 全部详细问题 + 未验证事项（四问逐项）+ 有具体证据的优点 1–3 条 + 成绩依据（仅当满足第 10 节六条）。完整报告可显示内部 ID / 状态码，但要同时给自然语言含义；压缩形式与展开形式的结论必须一致。
