# 小白X（LittleWhiteBox）路线

适用于用户点名要"小白X"、或玩法需要小白X独有能力（剧情总结、小白板、四次元壁 OOC、世界书变量条件编辑器等）的场景。小白X 与酒馆助手可以共存，但**一张卡只走一条变量路线**（小白X 变量管理 2.0 与 MVU 二选一）。

- 仓库：`https://github.com/RT15548/LittleWhiteBox`
- 文档：`https://docs.littlewhitebox.qzz.io/`（本文件的信息以该文档为准；功能迭代较快，动手前建议核对在线文档）

## 1. 代码块渲染（小白X 的"前端美化"基础）

- 能力：把聊天消息中**包含 HTML 标签的代码块**渲染为**自适应高度的可交互 iframe**。
- 触发条件：代码块（``` 包裹）内容包含 `<html>`、`<!DOCTYPE>` 或单独的 `<script>` 标签。
  - 与酒馆助手的判定不同（酒馆助手看 `html>`/`<head>`/`<body`），所以**按目标渲染器写 HTML 头**：小白X 卡建议用 `<html>` 或 `<!DOCTYPE html>` 开头；两边都要兼容就写完整 `<html><head>…</head><body>…</body></html>`。
- 开启方法（玩家侧）：扩展设置 → 小白X扩展 → 小白X模板 → 勾选 `总开关` 与 `渲染`。
- iframe 内提供 `STscript()` 异步函数调用酒馆 Slash 命令：
  ```js
  await STscript('/echo Hello World');
  ```
  - 插件会自动解析管道输出（pipe 值），**不要**再 `JSON.parse`。
  - 默认只提供 `STscript()`；启用"封装函数"后会有更多桥接函数（细节见官方文档）。
- 官方也自评：初次写前端卡推荐"传统方式"（正则把占位符替换成代码块）而非"沉浸式模板"。

## 2. 变量管理 2.0（小白X 的变量体系）

AI 输出 `<state>` 块来更新变量，规则是"**你看到的就是状态面板，改哪里写哪里**"：

```text
<state>
角色.生命值: -20          # 数值负号 = 减少
角色.技能: +"火球术"      # + 前缀 = 数组追加（字段不存在自动建空数组）
角色.临时状态: null       # null = 删除/清空
</state>
```

对比 1.0（不要用于新卡）：需要写"录入/变更/追加/遗忘"指令词，结构松散。

要点：

- `$schema` 结构模板可限制 AI 只能改哪些字段（2.0 默认不守护，需要时开启）。
- 支持 `$range / $step / $enum / $ro` 等约束规则（写在变量定义/模板里）。
- 相关工具：**变量面板**（可视化查看/编辑）、**世界书变量条件编辑器**（根据变量控制世界书条目）、**小白板**（剧情地图/大纲推演，挂载后从消息【X】按钮唤出，并新增【剧情地图】预设条目）。
- 变量卡写法：世界书里定义变量列表 + 让 AI 输出 `<state>` 的指令（提示词模板做法与 MVU 卡类似，但输出格式换成 `<state>` 语法）。

## 3. 其他特性（写卡时可利用）

| 特性 | 用途 |
|---|---|
| 剧情总结 | 自动总结剧情、关键词云、时间线、人物关系（长线剧情卡） |
| 四次元壁 | OOC 元对话空间（与角色/作者对话的"第四面墙"玩法） |
| 流式模板渲染（沉浸式模板） | 多楼层流式渲染 UI：模板编辑器放 HTML，AI 按约定格式实时输出 `vars` 对象驱动界面（进阶） |
| 音频播放命令 / 流式 gen 命令 / 更多内置函数 | 消息内音效、前端内请求生成等（见官方"渲染交互"栏） |
| Log 记录 / Log 拦截 | 查看/拦截发给 AI 的实际内容（调试利器） |

## 4. 与"酒馆助手 + MVU"路线的对比与选择

| 维度 | 酒馆助手 + MVU zod | 小白X |
|---|---|---|
| 变量机制 | 楼层级 `stat_data` + JSONPatch 更新 + zod 结构 | 楼层/全局状态 + `<state>` 更新语法 + `$schema` 约束 |
| 前端渲染条件 | 代码块含 `html>`/`<head>`/`<body` | 代码块含 `<html>`/`<!DOCTYPE>`/`<script>` |
| 生态资料 | 教程/示例卡/写卡工作流最丰富（推荐默认） | 一体化功能多，但多为英文/自有文档 |
| 独家功能 | injectPrompts、完整的脚本 API 体系 | 剧情总结、小白板、四次元壁、变量条件编辑器 |
| 混用 | 两者可同时安装；**不要同一张卡混用两套变量机制** | 同上 |

**写卡建议**：用户没有明确偏好时默认走酒馆助手+MVU（资料多、兼容好）；用户已在用小白X或点名要小白板/剧情总结时，走小白X路线，输出格式改为 `<state>`，HTML 头改 `<html>` 风格。

## 5. 卡内数据与模块（xiaobaix-* 扩展键）

小白X 会把模块数据存进角色卡的 `data.extensions`：

- **`xiaobaix-tasks`**：任务模块数据（源码常量 `TASKS_MODULE_NAME`，通常是 `{"tasks": [...]}`）。
- **`xiaobaix-template`**：沉浸式模板（流式渲染）配置，含 `enabled` / `template` / `customRegex`（默认 `\[([^\]]+)\]([\s\S]*?)\[\/\1\]`）/ `limitToRecentMessages` / `recentMessageCount` 等字段——**AI 输出自定义标签、扩展提取变量驱动模板界面** 的配置就在这里。

要点：

- 这些键由扩展读写，**拆卡/重建时必须原样保留**（本技能工作流的 `extensions_extra` 会自动透传，`card-format.md` 有键清单）。
- 小白X 仓库还带 `bridges/`（iframe 桥接：STscript、生成调用、世界书桥）与 tauritavern 集成模块——写界面时可在 iframe 内用桥接函数与宿主编排（细节以仓库/文档为准）。
- 生态占比参考（291 张去重卡样本）：带 `xiaobaix-tasks` 16 张、`xiaobaix-template` 2 张、世界书含 `<state`（变量管理 2.0 语法）5 张——小白X 真实存在但仍是少数派；MVU（79 张）是当前绝对主流。

## 6. 小白X 卡的交付说明附加项

- 玩家需安装小白X（GitHub Releases 安装）并开启：扩展设置 → 小白X扩展 → 小白X模板 → 总开关 + 渲染。
- 若卡使用了剧情总结/小白板/OOC，需在说明里写明对应开关位置（数据互动菜单）。
- 卡内如果**同时**夹带酒馆助手脚本/正则（比如为了兼容性），说明中分别标注两套要求，避免玩家只装一半。
