# 提示词模板（ST-Prompt-Template / EJS）实战

提示词模板让世界书/角色卡里的文本变成**小脚本**：发送前先执行 JavaScript，再决定发什么、发多少。

安装：与酒馆助手同样方式装扩展，地址 `https://codeberg.org/zonde306/ST-Prompt-Template`（GitHub 镜像 `zonde306/ST-Prompt-Template`）。
官方中文文档：仓库内 `README_CN.md`（入门）与 `docs/reference_cn.md`（API 全参考）。

## 1. 核心语法

| 语法 | 作用 |
|---|---|
| `<%_ 代码 _%>` | 执行代码，不输出（`_` 吃掉前后空白，排版更干净） |
| `<%= 表达式 %>` | 输出表达式的值（类似宏，但能运算） |
| `<%- 表达式 %>` | 输出但不转义（一般 `<%=` 即可） |

### 条件分段（最常用：分阶段人设）

```ejs
<%_ if (getvar('stat_data.角色.络络.好感度') < 30) { _%>
【络络对你态度平淡，甚至有些冷漠】
<%_ } else if (getvar('stat_data.角色.络络.好感度') < 60) { _%>
【络络对你抱有好感，但仍保持着一些距离】
<%_ } else { _%>
【络络现在非常信任你，愿意和你分享她的小秘密】
<%_ } _%>
```

- 条件按顺序命中即止（if → else if → else）。
- 变量路径与 `{{format_message_variable::…}}` 一致，从 `stat_data` 起算。
- **变量可能不存在**（AI 中途新增的字段）：判断用 `getvar('…') !== undefined`，取值用 `getvar('…', { defaults: 0 })` 给默认值。
- 也可以整段用代码 + `print()` 输出（好写也好读）：

```ejs
<%_
if (getvar('stat_data.事件.天气') === '晴天') {
  print('【今天阳光明媚，适合出门散步】');
} else {
  print('【今天天气一般】');
}
_%>
```

## 2. 常用函数

| 函数 | 作用 |
|---|---|
| `getvar('stat_data.…')` | 读变量（提示词模板自己的变量系统；对 MVU 卡读的也是楼层里的变量） |
| `setvar('路径', 值)` | 写变量（写时注意 MVU 行为差异） |
| `getwi('条目标题')` | 取**其他世界书条目**的内容 → `print(await getwi('天气-晴天'))`，把长内容拆分到独立条目管理 |
| `matchChatMessages(['关键词'])` | 最近 2 楼（上次用户输入+AI回复）命中关键词/正则才发送；`{ start: -4 }` 扫最近 4 楼 |
| `print('文本')` | 代码块内输出文本 |
| `TavernHelper.…` | 酒馆助手 API 都可用，如 `TavernHelper.getLastMessageId() > 5` |

## 3. 进阶：让条目"激活前"就处理好（`@@preprocessing`）

默认顺序是"世界书先激活、模板后处理"，所以无法用 EJS 决定**绿灯条目要不要激活**。在条目内容首行写：

```
@@preprocessing
```

（ST 1.13.4+）模板会在世界书激活前处理此条目——处理结果再参与绿灯/黏性/冷却判定，于是可以用变量控制绿灯条目：各天气文案各一条目（绿灯，关键字 `天气-晴天` 等），逻辑条目写：

```ejs
<%_
if (getvar('stat_data.事件.天气') === '晴天') print('天气-晴天');
else if (getvar('stat_data.事件.天气') === '雨天') print('天气-雨天');
_%>
```

注意 `@@preprocessing` 行本身不会发给 AI。

## 4. 与 MVU 变量卡的配合要点

### 用 EJS 写"过滤版变量列表"（替代 $ 前缀的进阶做法）

实测卡做法：克隆 `stat_data`、删掉不想给 AI 看的内部字段、再输出 JSON——比逐字段加 `$` 前缀更灵活（可按阶段隐藏不同字段）：

```ejs
<%_
const raw = getvar('stat_data');
if (raw) {
  const s = JSON.parse(JSON.stringify(raw));
  if (s['系统']) { delete s['系统']['阈值']; delete s['系统']['状态标志']; }   // 脚本内部字段
  if (s['触手君']) { delete s['触手君']['成长度']; }
_%>
<status_current_variable>
<%= JSON.stringify(s, null, 2) %>
</status_current_variable>
<%_ } _%>
```

注意：遍历对象键时过滤 `$` 前缀键与 MVU 元数据键 `$__META_EXTENSIBLE__$`（可扩展对象会带这个内部键）。

- **`$`/`_` 前缀**：`$变量`（对 AI 不可见）适合做 EJS 的开关；`_变量`（AI 不能更新）适合脚本/界面专用状态。详见 `mvu.md` §2.4。
- **不同开局发不同世界观**：世界观条目全部设为绿灯+`@@preprocessing`，用 EJS 按 `getvar('stat_data.$开局')`（开局变量用 `$` 前缀/或用 `_` 防改）只输出匹配开局的关键字。
- **分阶段人设平滑过渡**：不要"一刀切"，把区间拆细（0~40/40~80/80~100 三段起），条件里引用当前值让 AI 知道"现在处于哪一段、下一步会怎样"。
- **调试**：`<%_ alert('触发了晴天分支'); _%>` 或 `toastr.info(...)` 会在处理时弹提示；`<%_ debugger; _%>` 可断点；发完后用**提示词查看器**核对实际发送内容。
- **提示词模板与"做卡时的查看方式"冲突**：自己写卡/让 AI 看提示词时，可用写卡助手的「启用/禁用提示词模板和酒馆助手宏」按钮临时关闭处理；玩家游玩时必须开启。
- EJS 里可以用 `_`（lodash）、`YAML` 等全局；示例——把变量按 YAML 格式输出：

```ejs
<%= YAML.stringify(getvar('stat_data'), { blockQuote: 'literal' }) %>
```

## 5. 常见坑

| 坑 | 说明 |
|---|---|
| 提示词里出现 `<%_` 原文 | 扩展没装/没启用；或该文本在非处理区域（楼层消息等） |
| 条件不生效 | 路径写错（少了 `stat_data.`）；变量是字符串 `'30'` 而比较用了数字——先 `Number(...)` 或让 schema `z.coerce` |
| 世界书里 EJS 处理顺序不对 | 需要"先处理后激活"的场景加 `@@preprocessing` |
| 大量条目重复内容 | 用 `getwi` 拆分段落，或删掉被 union 覆盖的分支 |
| 想删的空白删不掉 | 用 `<%_ _%>`（带下划线）而不是 `<% %>` |
