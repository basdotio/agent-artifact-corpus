# Evaluation Framework

Deep-read 所有维度的统一评价规范。在开始 A 组审视前加载此文件。

## 1. 评估边界声明

每个 deep-read 输出开头必须包含：

```markdown
## 评估边界声明

- **输入范围**: [PDF全文 / 仅摘要 / 用户提供片段 / DOI解析 / ...]
- **论文类型**: [发现/机制研究 / 方法/算法 / 资源/数据集 / 综述 / ...]
- **可评估**: [列出可评估的维度编号]
- **无法评估**: [列出因材料不足无法评估的维度编号 + 简短原因]
- **影响评估置信度的缺失材料**: [如 "Methods section partially illegible" / "Supplementary figures not provided"]
```

## 2. 适用性分诊

每个 A 组维度开头标记适用性：

| 标记 | 含义 | 使用条件 |
|------|------|---------|
| `[applicable]` | 该维度适用且可评估 | 论文提供了相关材料 |
| `[not applicable]` | 该维度不适用于本文 | 例如纯理论论文标记"资源新颖性"为不适用 |
| `[not assessable]` | 该维度重要但材料不足 | 例如 Methods 缺失时标记"统计严谨性"为不可评估 |

**规则**：
- 标记 `[not applicable]` 时必须附一句话解释为什么
- 标记 `[not assessable]` 时必须说明缺少什么材料
- 不要因为"不想评价"而标记为不可评估

## 3. 严重度标签

维度内的关键发现标注严重度：

| 标签 | 含义 | 阈值 |
|------|------|------|
| `[MAJOR]` | 影响核心结论、可复现性或有效性 | 如果不解决，结论的可信度会显著下降 |
| `[MINOR]` | 呈现问题、局部缺陷或边缘情况 | 不削弱核心主张 |

**规则**：
- 每个 MAJOR 必须有具体的证据锚定（引用原文位置）
- 不要把所有问题都标 MAJOR——区分"作者需要修正的"和"作者可以改进的"
- 一个维度可以有 0 个或多个 MAJOR/MINOR

## 4. 解决方案测试

每个 `[MAJOR]` 发现必须附带：

```markdown
**如何解决**: [需要什么具体证据、分析或澄清才能消除此顾虑]
```

解决方案测试必须：
- 具体可操作（不说"需要更多实验"，说"需要至少 n=3 的独立生物学重复 + 统计检验"）
- 与问题的严重度匹配

## 5. 置信度标记（继承原规则）

| 标记 | 含义 |
|------|------|
| `[HIGH]` | 原文明确可查的事实 |
| `[MEDIUM]` | 合理推断，有间接证据 |
| `[LOW]` | 领域知识推测，原文未涉及 |

`[LOW]` 置信度的判断必须明确说是"推测"，不用确定语气。

## 6. 证据锚定（继承原规则）

每条评价必须引用原文具体位置。禁止空泛判断。

```
❌ 禁用: "样本量偏小"
✅ 要求: "[MEDIUM] 关键酶活实验仅 n=2（Fig.3B，无 error bar），
   发酵罐重复 n=3 但未报告生物学重复来源（Methods p.7 段落2）。"
```

## 7. 异议空间（继承原规则）

关键判断后，当存在合理分歧时添加：

```
"另一视角：如果作者的目标是工业应用而非机制研究，n=2的酶活初筛是可以接受的——
关键在于后续放大实验（Fig.4）的 n=3 数据是否可靠。"
```

不强制每条维度都有——仅在存在合理分歧时出现。

## 8. 问题键去重

当同一个潜在问题跨维度出现时（例如样本量不足同时影响"方法严谨性"和"过度宣称"），在第二个维度引用第一个维度的分析，而不是重复：

```
"样本量问题已在 dim 3（方法严谨性）中详细分析，此处仅补充：
该小样本的结论在 Abstract 中被推广为'通用机制'，属于过度宣称。"
```
