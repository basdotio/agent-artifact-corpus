# agent-artifact-corpus

一个带标注的测试语料库与基准，面向 **AI agent 环境的静态安全扫描器** —— 也就是 agent 会加载的 skill、hook、权限配置、MCP server、connector 和指令文件。

它在构造上就是**工具中立的，而且 `make validate` 会强制这一点**。在 README 里声称中立，和真的中立是两件事——这个仓库已经在无人察觉的情况下失去过两次中立性，两次构建都是绿的，因为这类耦合除非有东西专门去找，否则是看不见的。现在每次 validate 都会跑三条检查，而每一条都是在它要守的那个性质**已经悄悄破掉之后**才写的：

| 检查什么 | 为什么 |
|---|---|
| 任何已注册扫描器的 id 都不得出现在任何 `truth` 块或 `taxonomy/techniques.yaml` 里 | 一旦某个样本的 truth 开始解释"某个扫描器漏了什么"，那个扫描器的模型**就成了**真值，下一个被测工具是在被拿它竞争对手的描述来打分 |
| 任何扫描器的 id 都不得出现在 harness 自己的代码里（字符串字面量和标识符；注释豁免） | 点名某一个工具的代码，会让那个工具的存在成为"别人的样本如何被校验"的一部分。这条抓到了一个把字面量 `"aguard"` 钉住的 CI 步骤 |
| 任何 workflow 都不得设置某个扫描器的 `rules_source.env` | 否则共享的闸门会去校验某一个项目的规则 ID，而不校验任何别人的 |

另外校验器里有一条规则：工具的 `rules_source.path` 不许走出本仓库。它曾经走出去过，后果是 `make validate` 在作者机器上报「73 个规则 ID 已校验」，在所有别人的机器上报「not checked」——这份语料自己的结果取决于某一个人的目录布局。

**故意不做**的检查写在 [`neutrality.go`](harness/cmd/corpus/neutrality.go) 里：一个"剥掉所有 `expect` 块再重新校验"的 pass 写完之后被删了，因为校验器里没有任何检查**要求** expect 块存在，所以那个 pass 只可能通过、永远不可能失败。`truth` 的自足性早已按类别强制：恶性样本必须写明 technique 和 severity，硬负样本必须写明 `resembles` 和 `differs_by`——这些检查是会响的。

每个样本陈述它**是什么**，用的是不属于任何扫描器的词汇（[`taxonomy/techniques.yaml`](taxonomy/techniques.yaml)），所以任何扫描器都可以拿它来测量，多个扫描器可以在同一批样本上做对比。点名某个扫描器自己的规则 ID 是叠加在上面的可选精度，从来不是断言本身。见[两个半部分](docs/label-schema.zh-CN.md#两个半部分)。

它回答三个问题，而三个答案来自不同的地方：

| 问题 | 由谁回答 | 在哪里 |
|---|---|---|
| 假阳性率是多少？ | **世界** | `manifest/` —— 第 2 层，拉取 |
| 召回是多少？ | **主要是世界，我们补两个缺口** | 第 2 层 + `corpus/malicious/` |
| 这次改动有没有让事情变坏？ | **只有这个仓库** | `corpus/` —— 第 1 层，vendored（随仓库分发），离线 |

一句话概括：**分母来自世界，分子来自我们，闸门不来自任何别人。**

先读 [`docs/classification.zh-CN.md`](docs/classification.zh-CN.md) 了解测量什么，再读 [`docs/design.zh-CN.md`](docs/design.zh-CN.md) 了解怎么建起来的。
公开语料本身（每一份适合回答什么问题、用错了会把数字变成什么样）见
[`docs/catalogue.zh-CN.md`](docs/catalogue.zh-CN.md)。

## 测量一个扫描器

**任何扫描器，不需要向我们要任何东西。** 把它指向 `corpus/` 下的样本树，对每一个问：它有没有报出一条达到或超过该样本 `truth.severity` 的发现。硬负样本和良性样本断言的是反面。这就是全部协议，它不需要规则 ID、不需要严重度映射、也不需要在这个仓库里登记任何东西。

**规则级的期望，可选。** 在 [`taxonomy/tools.yaml`](taxonomy/tools.yaml) 里加一条 entry，标签就可以携带 `expect.<tool>` 块，点名那个扫描器的哪些规则必须触发、哪些必须保持沉默，并按那个扫描器自己的严重度阶梯校验。两个刻度不同的扫描器可以标注同一个样本，谁都不必采用对方的刻度。

**对比多个扫描器。** 因为真值是共享的、按工具的期望是分开的，同一份语料产出的是按技术、按维度的对比，而不是每个工具一个总分。`make stats` 已经在报告工具中立的构成，包括每一项还没有样本的技术。

**这个仓库不打分。** 它拥有样本和关于样本的规则。跑分器属于各个扫描器那边，或者做成一个归一化输出的薄适配层 —— SARIF 2.1.0 是显而易见的边界，这个领域里已经有几个扫描器在输出它。把打分器挡在外面，正是 `make validate` 能在没有任何扫描器构建产物的情况下运行的原因。

### 目前已接入的工具

| 工具 | 规则级期望 | 备注 |
|---|---|---|
| [`aguard`](https://github.com/basdotio/agent-guard) | 有，覆盖全部 6 个第 1 层样本 | 目前唯一一个 —— 见*已知缺口* |

还没有接入第二个扫描器。在接入之前，上面那些工具中立的说法是 schema 的性质，而不是已被证明的结果，把这个区别说出来正是这一节存在的理由。

## 三条红线

**① 不要手写良性样本来测量假阳性。**

一个由知道规则的人写出来的良性样本，是*想象中的*良性。真实的 skill 作者不知道任何扫描器的规则存在，所以他们会随手把一段 `curl` 配置示例粘进 `SKILL.md` —— 而那正是已确认的假阳性的真实来源。自己写的时候，你会不自觉地避开那些你知道会触发的形状，于是测出来的比率偏低，偏低多少无从得知。

`corpus/benign/` 下的 hooks、permission 和 connector 三格曾是这条红线最难办的地方：没有人收集正常的 hook、权限和连接器配置，因为几乎没有人扫描它们。这一格必须自己建，**而这恰恰是最容易制造出一个好看数字的地方**，所以采样规则是固定的：**只采集，绝不手写**。一个手写的良性 hook 和一个手写的良性 skill 是同一个错误。

这三格现在建好了，办法是 `scripts/harvest-claude-config.py`：从公开仓库里采集真实的 `.claude/settings.json` 和 `.mcp.json`，只按内容(而不是文件名)判定它落在哪个作用面，只保留真实的加载路径(`.template`、`.bak` 是文档，不是 agent 会加载的东西)，并且只保留许可证允许再分发的那些——最后这一条是个排除项，所以两个数字每次运行都要打印。

**② 任何分母都不许带排除项。**

任何 `grep -v`，任何"这一类不算"，都必须出现在结论那一行里，**并且两个数字都给出 —— 含排除项的和不含排除项的。**

这是花了大代价学到的。一个 11.0% 的假阳性率被发布出去，它的分母是由两条 `find` 命令选出的 290 个样本。完整总体是 952 个，比率是 12.9%。那条 `grep -v` 删掉的 44% 正是这台机器上得分最差的一组，删掉它是为了绕开一个性能缺陷。**拿一个缺陷当理由删掉一半分母，意味着一个问题掩盖了另一个问题。**

**③ "没有扫描器报警"不是良性的证据。**

这是循环论证。最尖锐的例子是 ClawHub，它按 OWASP Agentic Top 10 评级 —— 而这个领域里大多数扫描器的规则都是从这套分类法推导出来的，包括这份语料最初所针对的那一个。用它来挑选良性样本，等于用一个与被测扫描器共享盲区的扫描器来挑选测试集。见[良性可信度排序](docs/design.zh-CN.md#良性可信度排序)。

## 两层

第三方样本带有许可证约束（见 [`docs/licensing.zh-CN.md`](docs/licensing.zh-CN.md)），而"先下载再测试"会破坏离线 CI。折中方案是两层：

- **第 1 层 —— `corpus/`。** 我们自己写的，加上宽松许可的材料。vendored，离线运行。**回归闸门应当只看这里。**
- **第 2 层 —— `manifest/`。** 只有 `url + commit + sha256` 以及关于该语料的已知信息。`make fetch` 拉进被 gitignore 的 `cache/`。**发布的比率来自这里。**

**每一个发布出去的数字都要注明它来自哪一层。**

记录一个 URL 和一个哈希不构成分发，这就是为什么第 2 层可以引用第 1 层绝不允许包含的语料：无许可证、CC-BY-NC-SA、AGPL。

## 用法

```bash
make validate    # 检查每个标签、taxonomy、每条 manifest 条目、文档双语成对
make stats       # 语料库构成，工具中立的和按工具的
make fetch       # 按钉住的 commit materialise 指定的第 2 层条目（联网）
make test        # harness 单元测试
```

`make validate` 是离线的，不需要安装任何扫描器。CI 在干净 checkout 上跑的就是同一批 target，所以那种「只因为你机器上多了点东西才能过」的情况会在那里暴露，而不是在别人的 clone 里。

## 添加一个样本

1. 创建样本树 `corpus/<class>/<surface>/<id>/`
2. 把标签写在**它旁边**，命名为 `corpus/<class>/<surface>/<id>.yaml` —— schema 见 [`docs/label-schema.zh-CN.md`](docs/label-schema.zh-CN.md)。**绝不要放进树里面**：扫描器会读取整个目标，放在里面的标签会把自己的文本作为证据注入，从两个方向同时污染这个样本自己的结果。
3. 先填 `truth`，愿意的话就填到这里为止。单独一个 `truth` 块就是一个完整的标签；`expect.<tool>` 是你测过某个具体扫描器之后才补上的精度。
4. **先标注，后运行。** `origin.labeled_before_run` 必须是 `true`。先跑再标注等于把工具当前的行为当成正确答案，那样每次都测出 100%。
5. `make validate`

## 这个仓库的已知缺口

写明而不是略去，用的是这份语料要求被测扫描器遵守的同一条原则。

- **`expect.<tool>` 里的规则 ID 不在这里校验，这是设计如此。** 3,489 个标签里只有 6 个带 expect 块，其余 3,483 个是纯 `truth`，不需要任何扫描器就能检查。一个扫描器的规则清单属于那个扫描器，所以 `taxonomy/tools.yaml` 只通过环境变量去找它，并且校验器现在会**拒绝**任何走出本仓库的 `rules_source.path`。这条规则的由来：aguard 的路径曾经是 `../agent-guard/docs/rules.md`，某台机器上的一个同级目录。没有任何东西坏掉——而这正是问题所在：`make validate` 在那台机器上报「73 ids, 56 carry a dimension」，在别处报「not checked」，于是这份语料自己的校验结果取决于作者的目录布局。真正剩下的缺口在别处：**还没有任何扫描器的仓库 clone 这份语料、用它自己的规则去检查它自己的 `expect` 块**，而那才是这项检查该待的地方。
- **`sha256` 在第 1 层已被校验，在第 2 层仍然是空的。** 393 个采集来的样本各自带着采集时那份字节的哈希，`make validate` 会从 vendoring 的 artifact 重新算出全部 393 个并在不一致时失败。而每条 *manifest* 条目的 `sha256` 依然是空的、拉取器只核对钉住的 commit：一个引用在本地没有字节可供哈希，所以第 2 层的完整性仍然只靠 git。
- **表格形态的上游没法只靠 `make fetch` 复现。** `automatelab-mcp-tools` 和 `SkillMD-138K` 给的是 parquet 表格而不是样本树，所以在 fetch 和 derive 之间各自还要过一个 `scripts/` 下的脚本。脚本本身是钉住且带固定种子的，但 `make derive` 不会去调它们，所以一个干净的 clone 没法用一条命令重建这两条。
- **良性侧是抽样，恶性侧是普查。** 3,241 个良性样本是按写明的方案从写明的总体里抽出来的，而 237 个恶性样本是上游手里的全部。因此这份语料给出的召回数字和假阳性数字，靠的是两种不同性质的分母，不能合成一个分数。
- **只接入了一个工具。** `taxonomy/tools.yaml` 里只有一条 entry。
- **`NOTICE` 没有被 `make validate` 与标签的许可证做交叉校验。**
- **harness 里有一个包没有测试**：`fetch`。
- **32 个「维度 × 层级」格子里有 7 个没有样本。** `make stats` 会把它们点名列出。
- **三个作用面只有良性侧，没有恶性侧。** hooks、permission、connector 现在有 391 个真实采集来的配置和 2 个手工读出来的硬负样本，但恶性样本是零——因为没有任何公开语料把「被武器化的 hook 或权限授予」当作 artifact 收录过。所以在这三个作用面上，这份语料能量过度告警，**完全量不了召回**。那两个硬负样本配对的双胞胎也在 *skills* 作用面上（标签里写明了），这意味着一个从不解析设置文件的扫描器会安静下来，但那是因为它没有覆盖，不是因为它会分辨。
- **配置采集无法只靠脚本复现。** GitHub 代码搜索按相关性排序，每天返回的那一百个都不一样，所以 `scripts/harvest-claude-config.py` 是往 `manifest/pins/claude-config.json` 里累加的，`--from-pins` 才能精确重建那份记录下来的集合。一个已发布的数字只能从 pins 文件复现，绝不能靠重新搜索。

## 许可证

我们自己写的内容是 MIT（`LICENSE`）。第 1 层里 vendored 进来的第三方样本保留其原始许可证，逐项列在 `NOTICE` 中。第 2 层永不 vendored。
