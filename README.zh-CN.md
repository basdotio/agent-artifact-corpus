# agent-artifact-corpus

一个带标注的测试语料库与基准，面向 **AI agent 环境的静态安全扫描器** —— 也就是 agent 会加载的 skill、hook、权限配置、MCP server、connector 和指令文件。

它在构造上就是**工具中立的**。每个样本陈述它**是什么**，用的是不属于任何扫描器的词汇（[`taxonomy/techniques.yaml`](taxonomy/techniques.yaml)），所以任何扫描器都可以拿它来测量，多个扫描器可以在同一批样本上做对比。点名某个扫描器自己的规则 ID 是叠加在上面的可选精度，从来不是断言本身。见[两个半部分](docs/label-schema.zh-CN.md#两个半部分)。

它回答三个问题，而三个答案来自不同的地方：

| 问题 | 由谁回答 | 在哪里 |
|---|---|---|
| 假阳性率是多少？ | **世界** | `manifest/` —— 第 2 层，拉取 |
| 召回是多少？ | **主要是世界，我们补两个缺口** | 第 2 层 + `corpus/malicious/` |
| 这次改动有没有让事情变坏？ | **只有这个仓库** | `corpus/` —— 第 1 层，vendored（随仓库分发），离线 |

一句话概括：**分母来自世界，分子来自我们，闸门不来自任何别人。**

先读 [`docs/classification.zh-CN.md`](docs/classification.zh-CN.md) 了解测量什么，再读 [`docs/design.zh-CN.md`](docs/design.zh-CN.md) 了解怎么建起来的。
公开语料本身（每一份适合回答什么问题、用错了会把数字变成什么样）见
[`docs/catalogue.zh-CN.md`](docs/catalogue.zh-CN.md)。

## 测量一个扫描器

**任何扫描器，不需要向我们要任何东西。** 把它指向 `corpus/` 下的样本树，对每一个问：它有没有报出一条达到或超过该样本 `truth.severity` 的发现。硬负样本和良性样本断言的是反面。这就是全部协议，它不需要规则 ID、不需要严重度映射、也不需要在这个仓库里登记任何东西。

**规则级的期望，可选。** 在 [`taxonomy/tools.yaml`](taxonomy/tools.yaml) 里加一条 entry，标签就可以携带 `expect.<tool>` 块，点名那个扫描器的哪些规则必须触发、哪些必须保持沉默，并按那个扫描器自己的严重度阶梯校验。两个刻度不同的扫描器可以标注同一个样本，谁都不必采用对方的刻度。

**对比多个扫描器。** 因为真值是共享的、按工具的期望是分开的，同一份语料产出的是按技术、按维度的对比，而不是每个工具一个总分。`make stats` 已经在报告工具中立的构成，包括每一项还没有样本的技术。

**这个仓库不打分。** 它拥有样本和关于样本的规则。跑分器属于各个扫描器那边，或者做成一个归一化输出的薄适配层 —— SARIF 2.1.0 是显而易见的边界，这个领域里已经有几个扫描器在输出它。把打分器挡在外面，正是 `make validate` 能在没有任何扫描器构建产物的情况下运行的原因。

## 三条红线

**① 不要手写良性样本来测量假阳性。**

一个由知道规则的人写出来的良性样本，是*想象中的*良性。真实的 skill 作者不知道任何扫描器的规则存在，所以他们会随手把一段 `curl` 配置示例粘进 `SKILL.md` —— 而那正是已确认的假阳性的真实来源。自己写的时候，你会不自觉地避开那些你知道会触发的形状，于是测出来的比率偏低，偏低多少无从得知。

唯一的例外是 `corpus/benign/hooks/` 和 `corpus/benign/permission/`：没有人收集正常的 hook 和权限配置，因为几乎没有人扫描它们。这一格必须自己建，**而这恰恰是最容易制造出一个好看数字的地方**，所以采样规则是固定的：**只从真实机器上采集**（我们自己的、同事的、公开的 dotfiles 仓库）。**绝不手写。** 一个手写的良性 hook 和一个手写的良性 skill 是同一个错误。

**② 任何分母都不许带排除项。**

任何 `grep -v`，任何"这一类不算"，都必须出现在结论那一行里，**并且两个数字都给出 —— 含排除项的和不含排除项的。**

这是花了大代价学到的。一个 11.0% 的假阳性率被发布出去，它的分母是由两条 `find` 命令选出的 290 个样本。完整总体是 952 个，比率是 12.9%。那条 `grep -v` 删掉的 44% 正是这台机器上得分最差的一组，删掉它是为了绕开一个性能缺陷。**拿一个缺陷当理由删掉一半分母，意味着一个问题掩盖了另一个问题。**

**③ "没有扫描器报警"不是良性的证据。**

这是循环论证。最尖锐的例子是 ClawHub，它按 OWASP Agentic Top 10 评级 —— 而这个领域里大多数扫描器的规则都是从这套分类法推导出来的，包括这份语料最初所针对的那一个。用它来挑选良性样本，等于用一个与被测扫描器共享盲区的扫描器来挑选测试集。见[良性可信度排序](docs/design.zh-CN.md#良性可信度排序)。

## 两层

第三方样本带有许可证约束（见 [`docs/licensing.zh-CN.md`](docs/licensing.zh-CN.md)），而"先下载再测试"会破坏离线 CI。折中方案是两层：

- **第 1 层 —— `corpus/`。** 我们自己写的，加上宽松许可的材料。vendored，离线运行。**回归闸门应当只看这里。**
- **第 2 层 —— `manifest/`。** 只有 `url + commit + sha256` 以及关于该语料的已知信息。`make fetch` 拉进被 gitignore 的 `cache/`。**发布的比率来自这里。**

**每一个发布出去的数字都要注明它来自哪一层。**

记录一个 URL 和一个哈希不构成分发，这就是为什么第 2 层可以引用第 1 层绝不允许包含的语料：无许可证、CC-BY-NC-SA、AGPL。

## 用法

```bash
make validate    # 检查每个标签、taxonomy、每条 manifest 条目、文档双语成对
make stats       # 语料库构成，工具中立的和按工具的
make fetch       # 按钉住的 commit materialise 指定的第 2 层条目（联网）
make test        # harness 单元测试
```

`make validate` 是离线的，不需要安装任何扫描器。

## 添加一个样本

1. 创建样本树 `corpus/<class>/<surface>/<id>/`
2. 把标签写在**它旁边**，命名为 `corpus/<class>/<surface>/<id>.yaml` —— schema 见 [`docs/label-schema.zh-CN.md`](docs/label-schema.zh-CN.md)。**绝不要放进树里面**：扫描器会读取整个目标，放在里面的标签会把自己的文本作为证据注入，从两个方向同时污染这个样本自己的结果。
3. 先填 `truth`，愿意的话就填到这里为止。单独一个 `truth` 块就是一个完整的标签；`expect.<tool>` 是你测过某个具体扫描器之后才补上的精度。
4. **先标注，后运行。** `origin.labeled_before_run` 必须是 `true`。先跑再标注等于把工具当前的行为当成正确答案，那样每次都测出 100%。
5. `make validate`

## 这个仓库的已知缺口

写明而不是略去，用的是这份语料要求被测扫描器遵守的同一条原则。

- **没有 CI。** 没有任何东西会自动跑 `make validate`，所以上面说的回归闸门是一个设计，不是一个机制。
- **`sha256` 从未被校验。** 每条 manifest 条目的 `sha256` 都是空的，拉取器只核对钉住的 commit。完整性靠的是 git，不是哈希。
- **表格形态的上游没法只靠 `make fetch` 复现。** `automatelab-mcp-tools` 和 `SkillMD-138K` 给的是 parquet 表格而不是样本树，所以在 fetch 和 derive 之间各自还要过一个 `scripts/` 下的脚本。脚本本身是钉住且带固定种子的，但 `make derive` 不会去调它们，所以一个干净的 clone 没法用一条命令重建这两条。
- **良性侧是抽样，恶性侧是普查。** 2,850 个良性样本是按写明的方案从写明的总体里抽出来的，而 237 个恶性样本是上游手里的全部。因此这份语料给出的召回数字和假阳性数字，靠的是两种不同性质的分母，不能合成一个分数。
- **只接入了一个工具。** `taxonomy/tools.yaml` 里只有一条 entry。
- **`NOTICE` 没有被 `make validate` 与标签的许可证做交叉校验。**
- **harness 里有一个包没有测试**：`fetch`。
- **32 个「维度 × 层级」格子里有 7 个没有样本**，另有三个作用面——hooks、permission、connector——完全没有样本，因为没有任何公开语料覆盖它们。`make stats` 会把它们点名列出。

## 许可证

我们自己写的内容是 MIT（`LICENSE`）。第 1 层里 vendored 进来的第三方样本保留其原始许可证，逐项列在 `NOTICE` 中。第 2 层永不 vendored。
